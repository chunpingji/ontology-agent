## 当前行为

- 报告模板源文档和抽取详情共用识别结果树，以源文档本体类型为根，按本体定义的属性、关系组织分支；关系下展示关联实体，再展开实体自身的属性与关系。同名不同实体保持独立。
- 节点显示中文类型、属性名称、原始值及原始单位。共享实体通过链接跳转，循环和深层关系不会造成无限展开。
- 取消独立的逐项审核列表、全局审核理由框和原始 JSON 展示。原文定位、按需展开的识别依据及“提出异议”位于树节点中。
- 2026-09-09：右侧关系图谱不展示“文档识别记录”及文档主体的自动通过状态，直接展示文档属性、关系和关联实体。指回文档主体的循环关系跳转到文档属性与关系入口。
- 通过服务端校验的文档抽取候选在持久化时自动确认，并记录系统审核来源及审核历史。未通过校验、已失效依赖和人工录入仍遵循对应校验规则。
- 用户可将已通过项改为拒绝，理由不能为空。前端提交预期审核状态和内容版本，后台检查并发修改。
- 拒绝实体或关系时递归失效依赖项，并在同一事务中更新最新事实快照；历史快照和已有报告保留原内容。重复持久化同一候选不会覆盖人工拒绝。
- “发布通过项”仅提交通过校验与审核、依赖有效且尚未发布的结果；自动审核不隐式发布事实。

## 源文档本体树修正

2026-09-07，根据用户反馈修正此前将独立实体平铺为顶层节点的组织方式。

- 证据读取接口增加 `graph_schema`，直接复用抽取使用的本体定义，包括继承后的属性、关系与目标类型标签。根类型优先取当前源作业的 `doc_class_iri`，没有配置时才使用类型唯一的文档根识别记录；不使用模板的输出类型或相似实体名称替代。
- 同一关系的多个识别记录集中在一个分支中；不同关系即使目标类型相同，也保持独立。属性值仍按主体候选 ID 归属，并保留原始单位。
- 本体定义的空属性、空关系分别显示“未识别到值”“未识别到关系”。未建模的已识别断言放在“其他已识别属性与关系”中。
- 缺少从源文档出发的关系路径的实体移到默认折叠的“尚未关联到文档”，再按类型分组；不因实体类型符合关系目标类型而生成关系。
- 文档根记录共用一个本体树视图，各候选和主体引用保持独立。按 2026-09-09 用户要求，不再在图谱中单独展示“文档识别记录”。共享实体、循环关系通过跳转访问；较深的关联实体仍保留在文档树内。
- 原文定位、自动审核、异议理由、拒绝与发布行为保持原有语义；有条件、否定等关系状态仍在关系依据入口显示。
