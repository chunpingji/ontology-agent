## 2. 当前问题与依据

2026-09-27 的只读浏览器检查发现：当前列表有 29 条 `doc_repo` 记录，其中 28 条是上传或内嵌导入记录；内置 Mock 有 5 个数据集，生产区域与设备已映射，但没有出现在连接器列表中。进入列表产生 29 个 `/runs` 请求。此次检查未提交表单、执行连接测试或触发同步。

| 问题 | 当前实现 | 改造决定 |
|---|---|---|
| 来源与导入批次混在一起 | 文档上传每批创建一个连接器；上传记录也显示“研发文档库”和“探活” | 系统连接与文档导入分开；上传记录按批次展示导入结果 |
| 状态含义不准确 | `connectorStatus()` 将同步成功转换成“已连接”；未知非空状态也显示连接成功 | 配置状态、连接测试和最近同步分别显示；无测试结果不推断可达性 |
| 操作缺少主次 | 每条记录同时出现探活、编辑和删除 | 卡片主操作为查看详情；测试进入详情；删除放入更多菜单 |
| 编辑改变来源身份 | `connector-form.tsx` 先创建连接，再删除原连接 | 编辑原位更新并保留 ID；这是正式实施前必须解决的接口问题 |
| 列表请求随记录数增长 | `LastSync` 为每个连接读取全部运行记录，只用于展示最近时间 | 列表使用摘要；打开详情中的导入记录时再请求运行明细 |
| 参数表单负担重 | 创建表单直接展示分页、游标和轮询等字段；初次打开即出现必填错误 | 先选类型，再填基础参数和认证；高级项折叠；失焦或提交时校验 |
| 映射、查询入口割裂 | 数据映射页以本体类为入口，缺少来源上下文 | 从来源详情进入映射，查询跳转实体管理并选中对应来源 |

## 3. 页面职责与交互

| 页面 | 职责 |
|---|---|
| 数据源接入 `/connector` | 了解有哪些来源，维护连接参数，手动测试连接，进入来源对应的映射 |
| 数据映射 / 本体映射编辑 | 配置目标类型、属性、身份标识与来源字段的对应关系 |
| 实体管理 `/entities` | 浏览已保存实体，以及通过已映射来源查询实体 |

### 来源概览

- 以来源为卡片单位，显示名称、类型、数据范围、状态摘要和“查看详情”。
- 内置 Mock 从已有来源目录生成，包含五个数据集，不创建虚拟连接器记录。页面上的数据集名称和映射数量均由目录和映射配置提供。
- 文档上传、内嵌导入按 `system_type` 与 `connection_config.access_mode` 分类，不按中文名称前缀判断。缺失或不认识的模式保留为待确认记录，不自动当作远程连接或删除。
- 文档导入标签下按批次查看名称、导入状态、时间及详情；不显示远程连接测试。现有导入记录不因展示分组而迁移或删除。
- 本地“已保存实体”继续归属实体管理，不作为需要填写连接参数的外部来源。
- 卡片与“查看详情”打开同一 Drawer；更多菜单点击不触发卡片打开。搜索与类型筛选只影响展示。

### 来源与连接详情

- Mock Drawer 先展示已映射数据集，再展示待映射数据集。生产区域示例显示 `code → 生产区域编号` 与目标类型，说明身份来自本体映射。
- “配置映射”带入来源和数据集上下文；“查询实体”进入实体管理的相应来源 Drawer。实体列表不在接入页另做一份。
- 外部连接 Drawer 分为连接配置、本体映射、导入记录。连接配置中分别显示本次测试和最近同步，不能互相代替。
- HTTP 文档库已有默认类型映射。连接摘要显示实际有效的类型映射数量，不能因没有 `OntologyClassMapping` 关联便显示为“未映射”。具体流程见第 6 节。
- 未点击测试时显示“本次未测试”；点击后显示测试中、通过或失败及本次返回信息。无需新增连接测试历史存储；修改参数后清除旧参数对应的本次测试结果。
- 同步成功只表示该次同步结果。失败、超时、未执行和未知状态分别表达，不兜底为连接正常。
- 删除保留确认步骤；编辑保持原 ID 与未修改配置，不以新建和删除替代更新。

### 添加与编辑

- 第一层提供 REST API、数据库、文档库和文件四种类型；根据类型切换必要字段。
- REST 示例包括来源名称、服务地址、接口路径和认证。环境变量名的说明放在凭据字段旁边。分页、游标和每页条数收进高级选项。
- 流程为“保存配置 → 在详情中测试连接 → 配置映射”。保存不自动同步，也不代表连接已通过测试。
- 现有测试接口依赖已保存的连接 ID，所以设计不提供保存前测试。
- 不把现有轮询间隔输入框包装成已生效的独立调度能力；调度行为不在本次 UI 改造中扩展。

## 4. 实施依赖与范围

1. **原位编辑接口。** 更新原连接，保留 ID、未修改的映射及载荷等配置；前端不再调用创建加删除。
2. **列表同步摘要。** 模型已有 `last_sync_at`，但 `ConnectorResponse` 没有返回。补充该字段，列表使用同步摘要，运行明细按需读取。
3. **按实际来源取得映射。** HTTP 文档库直接读取当前连接的有效文档类型规则，复用 `field_mapping.doc_type_to_class`，无需为这个入口先建立统一映射关联表。REST/DB 的类与字段映射是另一条路径：当前 API reader 按连接器名称找来源，DB reader 按环境变量名取 DSN，不能直接拿 `source_system` 当统一连接 ID。该路径需要服务端可验证的来源关联；无法确认时显示待确认，不伪造映射数量为零。若实施显式连接 ID，需同时调整相关读入器与校验。
4. **来源深链接。** 数据映射与实体管理接收可验证的来源/映射标识，定位正确数据集；未知标识给出可返回的提示，不自动选中另一个来源。

当前实体查询服务支持 `mock_dataset` 与 `builtin_mock`。外部 REST、数据库或文档库接入成功，不代表已经支持统一实体查询。UI 按实际能力展示查询入口；本次设计不默认扩建外部实体查询引擎。

不新增图数据库、来源副本、连接测试历史或调度平台。复用当前来源目录、映射配置和既有运行记录。

## 5. 验收口径

- 设计：各 Frame 的文字可读、卡片对齐、Drawer 内容和底部按钮完整可见；复用原导航、蓝色主操作和主题变量。
- 来源分类：上传批次不会显示远程“已连接”；Mock 的五个数据集在一个来源下呈现。
- 状态：同步成功、未知同步状态均不能使连接测试显示通过；打开页面和切换标签不触发测试、同步或模型任务。
- 编辑：修改配置后 ID 不变，既有关联仍指向原来源；失败不会额外留下新连接。
- 查询路径：从 Mock 生产区域进入实体管理，定位到生产区域映射并能查询 `611`；其他来源不显示未实现的查询能力。
- 请求：初次加载概览不对每个连接发起 `/runs`；只在查看运行明细时请求对应记录。
- 交互：保留角色门禁；表单标签、键盘操作、关闭后焦点返回和未保存修改提示完整；窄屏卡片单列、Drawer 占满可用宽度。
- 空态与异常：无来源、搜索无结果、列表加载失败、详情加载失败分别提供明确提示；失败不显示为零数据或成功。

## 6. 连接详情：关联本体映射

### 6.1 当前选中来源的实际契约

选中的是“研发文档事实源”，类型为 HTTP `doc_repo`。

- [connector_factory.py](../../backend/app/services/integration/connector_factory.py) 的 `doc_type_to_class_map()` 合并 7 条默认类型规则与当前连接的 `field_mapping.doc_type_to_class`；自定义同名键覆盖默认值。
- [doc_repo_connector.py](../../backend/app/services/integration/doc_repo_connector.py) 将来源 `doc_type` 归一化为 `entity_type`，将 `doc_id` 归一化为记录标识；[materializer.py](../../backend/app/services/integration/materializer.py) 根据有效类型规则选择本体类。
- 这不是 `mock_dataset` 查询配置，也不是 `doc_pattern` 文档识别规则。本次设计对这个连接展示文档类型关联，不提供尚未接通的通用属性映射编辑器。
- 默认映射已存在，先前仅依赖类映射关联而将该来源显示为“待关联映射”的设计不准确，现已修正。默认规则、本体标签与类 IRI 均从后端和本体读取；设计中的列表不作为前端硬编码清单。

### 6.2 完整操作路径

1. 在连接配置中点击“管理本体映射”，切换当前 Drawer 的“本体映射”标签，保留连接 ID。
2. 展示有效映射，区分默认与自定义规则，可按来源类型或目标本体类搜索。默认 7 条、自定义 0 条是当前例子的初始状态。
3. 点击“关联本体映射”，在同一 Drawer 内进入表单，不叠加第二个 Drawer。输入来源文档类型，按中文名称或完整 IRI 搜索可用本体类，预览对应关系。
4. 来源类型保留实际代码，不按标签、语义相似度或大小写猜测对应；目标以精确类 IRI 保存。同名类通过完整 IRI 区分。目标范围由来源能力及本体层级决定，不在前端写死类选项。
5. 保存只更新当前连接的类型规则，不新建连接、不修改本体类定义、不触发导入或查询。成功返回映射列表，刷新连接摘要并显示本次保存反馈；取消不写配置。
6. 已有关联可进入预填的编辑表单，或从更多菜单移除自定义关联。移除前说明将影响后续导入；不删除目标本体类和已保存实体。覆盖默认类型时，移除自定义覆盖会恢复默认值；新增自定义类型移除后回到未关联。

设计示例 `TECH_TRANSFER → 技术转移报告` 中，`TECH_TRANSFER` 是示意输入，未从外部系统读取，也未实际保存。它是一个新的来源类型键，因此示例保存后为 7 条默认加 1 条自定义，共 8 条有效映射。如果编辑现有默认类型，则是 6 条默认加 1 条自定义覆盖，共 7 条，不能重复计数。

本次配置保存不修改已有导入记录；后续导入（包括同一记录的新版本）按最新规则处理。`doc_id` 是现有来源记录标识，不因类型关联便成为本体 `identityKey`，也不在这里声称跨系统全局唯一。

### 6.3 校验与结果状态

| 情况 | 页面行为 |
|---|---|
| 新类型未关联 | 填写并选择目标后允许保存 |
| 来源类型已有规则 | 字段旁提示已有默认或自定义映射，提供“编辑现有映射”；新增保存不可用，不静默覆盖 |
| 缺少来源类型或目标类 | 字段级提示，阻止保存；初次打开不提前报错 |
| 本体类失效或不在可用范围 | 标记待确认并提供重新选择；关联未确认前不宣称可用 |
| 搜索没有匹配类 | 显示无匹配结果，可清除搜索；不自动创建本体类 |
| 保存中 | 按钮显示保存中并禁止重复提交 |
| 保存失败或配置冲突 | 保留输入并展示可读错误；重新读取当前配置后处理，不覆盖其他字段或别人的修改 |
| 保存成功 | 返回列表、更新有效数量和自定义规则；不能据此显示“连接正常”或“实体可查询” |
| 配置或本体加载失败 | 展示加载失败与重试；不伪装成零映射 |

服务端更新契约需校验目标类与当前配置，并只修改指定的文档类型规则，保留其他 `field_mapping` 项及连接参数。当前缺少原位更新接口的问题仍需解决；这次未实施接口。

设计核对包括初始列表、选择表单、成功反馈和重复校验四个新增 Frame；错误重试、移除确认及默认覆盖规则写入本节及节点交互说明，尚未构成可点击的应用功能。
