# 属性值边界与根类型核验分工实测（2026-09-22）

已在当前独立 harness 中实现两项调整，并用同一真实封面的已保存观察重新执行
属性对齐与证据核验。完整封面的编号取值为 `DP-C-PI-S-X2419 2601 04`，完整
“编号：……”观察保持不变；移除密级行的对照中，标题通过核验，没有再被以
“不像 CMC 报告”为由拒绝。两组各执行一次，无全文质量或稳定性结论。

编号包含标签作为原文观察是正常的，上一轮 accepted 不能直接解释为违反本体
契约。修订明确区分完整观察与属性值，没有增加“带标签就拒绝”的门槛。

代码变化：

- 属性对齐在已有调用内支持 `span + value_quote`。LLM 根据当前合法属性定义选择
  原字段中的连续原文区间；程序检查位置、重复出现次数和原字段覆盖范围。
  `source_value/evidence` 保留完整观察，`value/value_evidence` 保留取值与其位置。
  原字段不被覆盖，也不按“编号”等领域前缀自动删除文本。
- `whole` 仍允许完整原值；边界不清楚不自动丢弃观察或停止探索。原范围派生的
  lower/upper 规则保持，缺失标记、跨字段取值与伪造引用不能成为属性事实。
- 实体核验与属性/关系核验分别组批、使用独立指令。主体输入明确
  `user_selected/model_review/unconfirmed`，根类型属于用户指定的任务前提，
  不伪装成已由封面证明的结论。
- 属性核验沿用当前主体类型，只核对本项原文、值、含义和归属等条件；不再次
  下发主体类型定义作为待证明任务。明确的类型矛盾通过有引用和主体 ID 的
  `type_concerns` 保存为观察，不在此阶段改写类型或强制改写模型 verdict。
  端点未确认、引文不足、真实归属错误仍沿原规则保留未决或拒绝。
- 图谱属性展示取值、完整原值及取值位置，精确引文可查看原文。
