# 本体层级支持与覆盖重排：实现及章节实测

## 结论与范围

独立 `document_harness` 已接入发现前的本体卡召回、父类扩展、层级支持和贪心覆盖选卡。
新代码默认执行该步骤；语义模型沿用已明确启用的本地配置，启用后的错误不会静默降级。
发现收到预算内的阅读卡，类型对齐优先共同读取这些卡，仍检查未入选的可达类型。
类型、属性和关系的合法 IRI、真实引用及身份边界沿用新 harness 的原有规则。

对指定报告“产品的基本性质”章节，使用修订后的本体及相同的 8 卡/输入预算：

| 选卡策略 | DrugProduct 入选次序 | API 入选次序 |
|---|---:|---:|
| 纯语义精排 | 3 | 未入选（精排原始第 18） |
| 语义相关性加字段匹配 | 3 | 未入选 |
| 再加层级支持 | 1 | 4 |
| 再加覆盖重排 | 1 | 2 |

这是一次章节级排序验证，未调用生成式 LLM、未进行事实采信、未启动或恢复主服务运行。
代码尚未重启发布到主服务；不能把容器内隔离脚本加载了新代码当成主服务已启用。

## 通用算法与边界

1. 从当前文档根可达目录中检索正文候选类型；文档根自身作为已登记对象单独处理。
   原文保留否定、条件和缺失标记。卡片检索文本包含名称、别名、定义和去重属性标签。
2. 使用已有本地嵌入相似度结合原字段标签匹配选取 24 张种子卡。在最终选卡之前，
   沿 `parent_iris` 补入当前可达范围的全部命名祖先，按最短父类距离去重、防循环。
   对扩展后的整个候选池实际精排，补入的父类也获得直接原文相关性分数。
3. 属性匹配按属性 IRI 计一次，继承同一属性的多个子类不重复制造加分。
   `R = 0.75 × 直接相关性 + 0.25 × 属性匹配覆盖`。
   原始精排 logit 以 sigmoid 单调映射到有界数值，不能解释为类型成立概率。
4. `H(parent) = max(0.8^distance × R(seed))`。取最强后代支持，不按子类数量求和。
   没有相关种子时不会仅因某个类型较宽泛就补入并加分。
5. 每次选择最大增益的可容纳卡：
   `gain = 0.50R + 0.25H + 0.25新增属性覆盖 + 0.40新增上位层级覆盖`。
   某个上位卡对自身层级完整覆盖，其后代只提供按距离衰减的部分覆盖。
   已覆盖内容按边际增益扣除，避免多个相近子类持续占用名额。
6. 最多 8 张阅读卡，按实际剩余请求 UTF-8 字节上界装入，卡片整体保留、不截断定义。
   结果记录各分量、父类支持来源、实际选择增益、预算用量和未入选原因。

所有系数均为本次通用策略的初始值；实测前已确定，没有根据目标 IRI 或实测排名修改。
该算法不是学习完成的精度模型，也不保证任何固定 K/有限上下文绝不漏卡。
对未入选类型，类型对齐仍保留原有分批检查；排序不是新的事实证明门。

原文类别被否定时仍可能获得高相关度。当前实现没有额外进行否定推理或事实判断，
由后续类型消歧/原文核对处理。本次前八仍包含生物制品、中药制剂等未获证实的候选，
以及构造材料等噪声候选；不能据此宣称整个候选集语义正确。

## 接入与状态

- `ranking.py` 使用独立协议 `harness-card-ranking-v1`，只复用通用本地模型基础设施，
  不导入旧 extraction 排序服务、候选协议或 evaluation 模块。
- `discover.schema_guidance` 包含选中的阅读卡和用途说明；排序分数不作为 LLM 证据输入。
  输出仍为原文提及、原字段和关系标签，不在发现阶段强迫输出本体类型。
- 窗口业务状态只保存实际使用的 `guidance_class_iris`。类型菜单能合批就合批；
  超预算时优先保留引导卡组，然后读取其余目录。冲突类型仍在同一上下文中联合比较。
- 精排结果独立存于现有结果表的 `harness:rankings`，按运行、冻结目录、原文、策略和
  字节预算确定复用键。请求记录与模型操作/耗时保留；失败记录不充当成功缓存。
  排序结果不进入实体/事实计数，也不复制到每次更新的业务工作状态。
- 本地模型按有界 batch 调用，单次工作进程内复用已计算的卡片向量；模型会话结束时关闭。
  暂停/继续复用已保存的排序结果，调用遵循原运行的拥有者及执行租约边界。

## 实测输入与对照口径

- 文档：`upload-a255fd30-192c-4f81-92df-5f76a56b8383`。
- 原件 SHA256：`1156ca7b694c5af10afa393a5df4158ad4f9528901eab560ae2cf96e55b6d44b`。
- 原文复用此前冻结的本章 21 个来源单元、19 个字段，逐项与原实验输入比较相等；不包含简介。
- 本体：从当前权威 TTL 加载到隔离 Owlready2 World，包含已修订的 API 别名、属性归属及
  `describes` 并集范围。新快照：
  `20ab54f733ea7f9361e5ec4b3371a00826474c0f3c0d013f79bf376541753225`。
- 模型：配置中的本地 BGE-M3、BGE-reranker-v2-m3，CUDA 0 / float16；完整权重身份和
  数值环境见 `ranking.json.model_identity`。
- 24 张种子卡，经通用祖先扩展形成 28 张精排候选卡。

四种选择策略复用完全相同的这份精排输出、候选池和预算，只有排序/选卡公式不同。
这没有单独衡量祖先扩展的因果效果，也不能与修订前本体、不同卡片文本的历史排名
直接对照成提速或召回率增长。目标名称仅用于结果统计，不进入算法或额外模型指令。

实际语义排序耗时 **83.06 秒**，记录 **42 个模型基础设施操作**。
其中包括模型初始化及嵌入/精排，不能当作纯覆盖重排的耗时。
选中卡片预算用量 19,701 字节；组装的发现请求保守输入上界 **32,472 / 32,768**，
实际包含阶段指令和输出 Schema。该请求已保存，未发送给生成式 LLM。
