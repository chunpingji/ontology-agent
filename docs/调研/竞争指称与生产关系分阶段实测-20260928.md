# 竞争指称与生产关系分阶段实测

日期：2026-09-28。状态：原型工程验证、两轮真实模型矩阵及端点补测已完成；完整识别验收未通过，未部署。
依据：[方案评估第 9 节](Mock身份键候选数组引导指称识别方案-20260928.md#9-保留竞争指称解释再核对生产关系的方案评估)。
用户授权按建议调整后实测。本轮对应 H02d，未部署线上 Harness。

**结论：显式成员协议下，核心句三次均保留整体/成员竞争解释，并最终接受两个正确编号；
其中两次最终关系保持未决，一次错误采信备选关系。第二轮完整矩阵通过 5/12，不能认定方案稳定通过。**
明确择一的候选能够正确生成，但核验仍混淆“选项命题成立”和“已选中具体地点”；
“分别在两处生产”还会被误判为备选。端点补测修复了无计划时仍提出关系的问题，纯车间清单识别仍失败。
共 68 次真实调用；工程测试最终 21 passed。

## 1. 已实施的实验协议

新增[隔离入口](../../backend/app/evaluation/harness_competing_candidate_probe.py)，
复用现有 DOCX → IR、逐字引用、冻结本体、Mock 声明映射查询、模型客户端及调度。
使用当前本体定义的 `ProductionArea.areaIdentifier` 与
`ClinicalSampleProductionPlan — producedInArea → ProductionArea`；未改 TTL。
协议约束见[实验契约](../../specs/036-mapped-entity-query/contracts/competing-candidate-probe.md)。

| 阶段 | 模型任务 | 程序约束 |
|---|---|---|
| 指称候选 | 提出整体/成员编号表达及其逐字定位、竞争对象分组、可空的计划提及 | 不根据斜杠拆分；不同分组不同时物化；分组内成员不得重叠 |
| 属性与关系对齐 | 结合逐项完整值查询选定分组或未决；分别判断参与方式、是否择一、时间方式、极性 | 关系引用同一分组内合法成员；无计划证据不得生成确定关系；不重写编号 |
| 独立证据核验 | 分别核验分组 I、逐成员编号 A、计划 P、参与关系 R、时间 T | 编号不依赖计划地点已选定；关系依赖两端；并行单独采信；引文归属冲突拒绝应用 |

`options` 保留为一个关系选项组，不展开成两个车间均被选用的肯定边。
`all/single` 才能投影为对应计划的关系边；即使接受共同参与，时间未采信也不补成并行。
模型可以保留未决或拒绝候选，程序不得补填参考答案。来源身份始终为 `not_checked`。

本轮是**候选类型已提供的单句协议原型**：直接提供两类相关本体卡，不运行正式类型发现/语义精排，
不调用生产 Harness controller，也未接入公共图协议。生产计划的原文提及仍由模型自行发现，
不提供预造计划实例。不能将本轮结果称为完整文档图谱引擎验收。
编号候选由模型选定分组的逐字表达派生，绑定到本轮明确限定的 `areaIdentifier`，
后续模型独立核验是否接受；没有让模型再从完整属性菜单重写编号。
这验证了该范围内的成员归属与采信，不能宣称生产属性对齐控制器已经修复。

首轮使用二维数组表达分组，实测暴露对象与编号层级混淆、把生产选项当成互斥指称解释的问题。
第二轮改为当前代码中的显式 `Member.id + expression_ids`，向关系阶段提供逐分组的成员菜单，
用 `member_ids` 引用端点；每种分组需覆盖已提出的最小编号片段，禁止遗漏另一备选提及。
提示与字段说明同时明确：整体复合编号需有独立整串表达，选择指称解释不代表选择生产地点，
组 anchor 必须覆盖所有成员。这是一组工程修正，不是只改变一个因素的消融实验。
两轮采用相同输入、来源场景、本体和模型配置，首轮结果未覆盖；各自预算 45 次/2400 秒。

## 2. 输入、参考与预算

从原句新建 DOCX/IR，不复用上轮的已正确分组状态。核心重复三次，九个边界例各一次。
每次最多三个模型阶段；应用约束失败时停止该样本后续阶段，并继续其余样本。
第一阶段读取真实映射来源键的字面召回，第二阶段前对模型提出的**全部表达**逐项精确查询。
缺记录/无记录使用独立 SQLite 来源表，未修改共享 Mock。

| 用例 | 输入特点 | 开发回归目标 |
|---|---|---|
| members × 3 | 计划于644/642车间完成本次临床样品的生产。 | 保留整体/成员竞争解释；目标成员编号分别 644、642；生产方式未决 |
| alternative | 选择644车间或642车间之一，尚未确定 | 两个编号；同一组选项，明确择一 |
| both | 分别在644车间和642车间安排生产，未说明时间顺序 | 两个均参与，时间不明 |
| parallel | 同时在644车间和642车间并行生产 | 两个均参与，并行 |
| sequential | 先在644，完成后再在642，不同时进行 | 两个均参与，先后 |
| composite | 仅一个车间，完整编号644/642，不代表两个 | 单对象复合编号；无临床生产计划实例 |
| missing | 核心原句，来源仅有642 | 不因缺记录丢掉644提及；保留竞争解释 |
| no_records | 核心原句，来源为空 | 来源完整未命中与文档指称分开判断 |
| renamed | 一个车间，旧编号644，新编号642 | 同一对象两个编号；单地点计划关系 |
| no_plan | 生产区域清单列有644车间、642车间 | 两个车间；不制造生产计划及关系 |

这些是开发回归参考，未经业务专家批准，不是正式金标。核心“两成员”是用户期望的识别目标；
对于原文与来源不足以排除复合编号的情况，保留未决比错误断言更合适，但未决不计目标识别成功。
任何参考值均不进入识别输入；反例的 Mock 数据也是待核对来源，不能作为原文关系证明。

沿用 `Qwen3.6-35B-A3B`，revision
`0b21525e972670ed59e1812e170b27c26355381f0656ecc4e25617ece7dac58b`，temperature=0.1，
reasoning=none / thinking=false；输入保守 UTF-8 字节上界 32,768，输出上限 16,384 token。
预算为 45 次模型调用、2400 秒；本轮无失败自动重试。

首轮入口的 `strict_pass` 只计算已接受编号与关系语义的子评分。
在查看首个模型回答前，另行固定了[完整验收口径](../../backend/data/evaluations/harness-competing-20260928-analysis/acceptance-criteria.json)：
还须正确发现/排除计划主体，歧义句须保留整体编号与两个成员的两种竞争分组。
候选覆盖独立于后续流程完成统计，不能因后续阻断把已产生的候选信息清零；
所有未完成样本仍保留在总分母。
第二轮入口已把上述计划主体与竞争解释条件纳入 `strict_pass`，最终分析对两轮使用同一完整口径。
第二轮运行期间发现一处**评分器缺陷**：裸斜杠的关系参考为未决，旧评分却要求中间对齐阶段
必须直接返回 `unknown`，会错扣最后独立核验已判未决的样本。
最终评分修正为检查实际输出没有被接受的关系/边，且 R 的最终判断为 `unresolved`；
没有核验、端点缺失或误接受选项仍不能通过。新增一正一反回归测试验证该口径。
两轮原始回答、状态和旧分数保持不变，修正结果另存分析产物。评分修正当时已用 AST 比较确认
只改变离线 `score()`，没有改变识别提示、Schema、输入或执行代码。
之后无计划端点约束的独立修正和补测另见第 3.3 节，不与评分修正混为一项。

## 3. 实测结果

### 3.1 首轮：二维数组分组

核心三次已完成尝试：

| 重复 | 指称候选 | 后续结果 |
|---|---|---|
| 1 | 只有644、642表达；一个分组、一个成员内放两个表达，理由却声称两个解释 | 关系引用成员索引0、1，但分组仅一个成员；`relation_member_outside_partition` |
| 2 | 有单对象双编号、两个对象两种分组；没有整串644/642表达 | 对齐优先选单对象；独立核验将身份、编号和关系均保留未决，计划接受 |
| 3 | 与第1次同类结构 | 同一端点越界拒绝 |

以上均为真实输出，没有程序替模型拆分或补编号。核心最终编号目标 0/3，完整竞争分组覆盖 0/3。
首轮共 12 次尝试，7 次完成全部阶段，5 次被应用一致性检查阻断。编号目标通过 2/12，
完整目标通过 2/12（共同参与且时间未知、明确并行）；29 次新调用。

### 3.2 第二轮：显式成员引用

核心三个重复均正确提出 `644/642`、`644`、`642` 三个表达，并保留整体单编号与两成员分组；
最终两个成员分别接受正确编号。关系对齐均倾向推断选项，但第 2、3 次独立核验最终保留未决，
第 1 次错误接受 `options`。因此按最终输出评分：编号 3/3、完整目标 2/3，尚不能声称稳定通过。

明确择一例已正确输出两个成员、两个编号，以及 `options + exactly_one` 候选；
但 R 核验以“具体指向哪个对象未定”为由将整组选项关系判未决。
它仍把“选项命题有原文支持”与“已选中具体车间”混为一谈。
共同参与但时间不明例则将“分别在…和…”误判为 `options` 并最终接受，混淆 AND 与 OR。

第二轮逐项最终结果如下，所有阻断和未决均保留在分母：

| 用例 | 最终编号/对象 | 最终关系 | 完整目标 |
|---|---|---|---|
| 核心 × 3 | 三次均为两对象，分别644、642；三次均保留整体/成员竞争解释 | 两次未决；一次误接受备选 | 2/3 |
| 明确择一 | 两对象、编号正确 | 候选 `options + exactly_one` 正确，核验因未选定具体地点而将整组判未决 | 未通过 |
| 共同参与、时间不明 | 两对象、编号正确 | 错把共同参与判为 `options` 并接受 | 未通过 |
| 明确并行 | 两对象、编号正确 | `all + parallel` 接受 | 通过 |
| 明确先后 | 两对象、编号正确 | `all + sequential` 接受 | 通过 |
| 单个复合编号 | 候选保留整体编号，后续因无计划却提出关系被阻断 | `relation_without_grounded_endpoints` | 未完成；补测见下节 |
| 仅有642来源 | 两对象、编号正确，未丢掉库外644 | 最终未决 | 通过 |
| 来源全空 | 接受一个对象，编号644/642 | 接受单地点关系 | 未达到两成员目标 |
| 同对象旧新编号 | 一个对象，编号644和642均接受 | 因“未确定选用哪个编号”将本应单地点的关系判未决 | 未通过 |
| 无计划的车间清单 | 正确提出两成员候选，但对齐以没有计划为由不选择指称解释 | 后续 I 却判 accepted，触发 `cannot_accept_unselected_partition` | 未完成 |

第二轮共 12 次尝试，10 次完成、2 次应用阻断；最终编号目标 **9/12**，完整目标 **5/12**。
35 次新调用。若只看“关系候选能否提出”，明确择一与改号例已有正确候选；
失败发生在最终语义核验，不能把“候选正确”和“约束已正确采信”合并报告。

候选中的编号分组与参考完全一致的覆盖为 10/12。并行例额外把“644车间”等称谓当编号候选，
复合编号例把整串与短编号同时分配给单对象；最终属性核验可拒绝部分多余值。
因此最终编号正确也不说明第一阶段所有候选均正确。

### 3.3 无计划端点修正及补测

两轮复合编号例均没有发现临床生产计划，却因关系 Schema 仍允许提出生产关系而阻断。
当前原型已按实际端点限制菜单：`plan_anchor=null` 时只允许 `participation=none`、空成员关系列表、
无选择/时间结论；指称选择与编号核验仍可继续。这是合法端点约束，不是程序替模型选择编号。

对第二轮中两个无计划样本（复合编号、车间清单）全部补测，不按最终成功与否筛选。
复用它们相同的真实第一阶段输出、完整值查询反馈、原文及本体卡，重新调用对齐和核验模型；
两组对齐 payload 与各自原请求完全相同，仅 Schema 中关系成员、参与方式、选择和时间四项约束改变。
无新发现调用或来源查询，不计为两次从原句开始的独立完整重复。

- 复合编号：完成后续核验，接受一个对象、完整编号 `644/642`，没有计划或生产关系，**通过**。
- 无计划车间清单：仍因没有计划而不选择指称解释，后续又接受未选中的 I，
  被 `cannot_accept_unselected_partition` 拦截，**未通过**。不把拦截当作识别成功。

补测 4 次真实调用，一次完成、一次应用阻断。当前代码包含该端点修正；
第二轮 5/12 是完整矩阵的原始执行结果，不能用补测结果拼成一次全新的完整矩阵分数。

### 3.4 对方案的判断

分层方向可保留，显式对象引用和绑定字段比二维数组更易被该模型正确使用。
但两个完整矩阵之间同时调整了输出结构、成员菜单、覆盖约束和提示，且边界各仅一次，
不能单独归因于某个字段或宣称统计稳定提升，更不能将结果直接等同线上 Harness 质量。

当前剩余问题有明确的原始回答依据：

1. **指称判断仍受计划是否存在影响。** 无计划清单已提出正确两成员，对齐却以无计划为由不确认它们。
   实体解释与关系任务仍在同次对齐调用中，提示层面的分工尚未消除这项干扰。
2. **AND/OR 含义混淆。** 模型把 `options` 解释成“备选/并列”，会把共同参与也放进去；
   裸斜杠有时又被“通常表示选择”的常识补成确定选项。
3. **命题支持状态与实际选择状态混淆。** 明确择一的选项集合有原文支持，但实际选中对象未定；
   模型将后一种未定传播到前一种核验。改号例还把“一个对象的两个编号”误当作待选择的两个指称。
4. **再次调用同一模型不保证核验独立。** 部分理由引用“根据候选I的定义”来接受单对象，
   没有独立证明该分组；服务端能拦截引用矛盾，无法仅凭结构校验发现 AND/OR 语义错误。

后续最小修正应聚焦：独立完成指称/编号采信后再安排关系任务；将关系组的原文支持与最终地点选择分开；
共同参与、备选和时间各自要求决定性原文依据。无来源且原文仍歧义时保留未决，不能把未命中变成单对象证明。
这些后续语义修正尚未实施或实测。本轮不满足完整 H01/H02 或上线验收。
