### 候选和核验的具体问题

第一组的保存结果为 `undetermined / complete=false`，原因包括
`fact_source_outside_scope`、`source_excerpt_mismatch`、`ambiguous_source_quote`。
模型从本次不允许作为事实的上下文建立主体，多处单位引用为空，重复的“否”缺少消歧上下文。
原文存在这些文字不等于该次调用获准使用；这一组没有进入事实图。
见[来源问题](first-region-issues.json)和[区域结果](first-region-outcome.json)。

第二组 8 个属性候选中，分子式、正文分子量、项目代码、中英化学名、性状这 6 个字段
与局部原值匹配，但主体类型/身份仍未证明。另外两项存在明确语义问题：

- 将“项目名称：HRS-1597”映射为 `productIdentifier`，并漏掉明确的 `projectName` 映射。
- 将 `CAS：N/A` 的缺失/不适用标记作为 CAS 实值。

记录主体被模型判为 `DrugProduct`，但当前本体定义指向制剂，原文另有 API、粉末和片剂的
不同层级；标题和同名不足以解决类型及身份问题。确定性门将主体指称核验置为
`record_composition_source_coverage_missing`，依赖它的属性没有入图。
正文分子量 `500.60` 与设备表残留物栏 `500.18` 的并存也未完成跨区域核对。

已保存的核验器曾错误支持 `productIdentifier`，理由为“虽然原文标签为项目名称，但根据
任务逻辑及 e1 的身份定义”认作唯一标识。这说明增加一次 LLM 核验本身不能保证消除语义误报。
该结果仍被未决实体依赖门阻止，不能说页面已产生错误实线。
见[核验判定摘录](verification-decisions.json)与[独立候选核对](candidate-review.md)。

事先选定的 11 个样例没有任何一项形成最终合格事实：正文分子式/分子量已有待定候选，
产品层级未决；“否”相关候选未通过来源门；设备、备选编号、清洁方法、存放条件和毒理
试验等尚未完成合法核验，保留未评。此样本不能用于计算全文 precision/recall，
6 个字段的文字匹配也不能报告为“6/8 最终事实准确率”。

### 中断与恢复

首次中断距离上一组已发布进度约 900 秒，与当前无持久进展门限吻合；执行器的该门限
能停止在途模型。请求记录没有单独给出触发源，本轮没有独立复现，故不将此推断写成已证明根因。
已完成的发现及前两批核验结果仍在。

继续操作被接受后，没有新增模型请求；重建当前工作范围时抛出
`record_discovery_scope_changed`，并被公开接口标记为 `CHECKPOINT_MISMATCH`。
这与第二次预检的 GPU 探测/排序身份变化是两个不同故障。当前公开契约对
`blocked_dependency` 只允许取消/删除，不支持继续。本轮保留原状态和结果，
不改写指纹、检查点或数据库状态来制造恢复成功。

随后从冻结本体、IR 和 41 条当前搜索记录做只读重建，没有重新调用模型或排序：
`catalog_hash`、`search_scope_hash` 均相等，唯一差异是保存的卡片集合为 63 张，
恢复得到 62 张，缺少 `f4769ef0a737697ec28be5a594f557cfb592aa95c46bfa3fee1e53c89b295485`。
它是比较候选区域时产生、但未选用的 `DrugProduct` 投影卡：
`RecordSearch.admit_dependency` 在遍历候选时调用 `_projected_card`，把临时卡插入共享字典；
执行器将该字典的所有 ID 保存，而 `restore` 只根据实际队列和区域卡配方重建。
因此这是派生缓存与当前工作状态不一致造成的错误拦截，不是原件或本体范围发生变化。
精确复现见[范围差异](recovery-scope-diff.json)与[恢复调查](recovery-review.md)。

最小修复方向是候选比较不注册临时投影，只为实际使用的卡保存重建配方，并覆盖投影卡被
消费后的恢复。完整卡集合校验仍须保留。本轮完成根因定位，尚未修改该恢复实现或验证修复；
不将只读重建成功等同于真实运行恢复成功。

### 结论与后续验证门槛

目标图和候选发现机制可以运行；当前实现的有效产出、核验准确性及暂停继续均未达到本轮验收。
继续采用“本地 LLM 负责语义候选、确定性结构解析负责原值和证据、本体限定合法映射”的方向，
但本次没有 spaCy 对照，不能声称 LLM 比 spaCy 更快或更准。修正优先级为：

1. 修复已定位的派生执行卡集合重建差异，保持冻结范围核验，并覆盖未选卡和已消费卡。
2. 明确候选允许使用的事实单元；禁止空引文，将 `N/A` 保留为缺失标记；核验字段语义和类型定义，
   不以项目名推导唯一身份，也不以同名合并 API/制剂。
3. 检查核验拆分与无进展门限的实际交互，再以新运行验证完整的实体登记、关系发现、实线及属性原文。
4. 完成真实多谓词合批和全文范围核对后，才报告完整度增长、最终事实质量及速度对照。

这些是由本轮证据产生的后续修正/验收项，不代表已实施或已通过。
