## 真实模型实验设计

使用当前配置的 `Qwen3.6-35B-A3B` 和生产 `call_model`/Schema/通用指令，temperature=0.1，输入估算上限 32768，输出预算 16384。
保存冻结运行代码、本体、原文、请求、原答、用量和独立期望。期望是开发者编写的回归参考，
不是专家金标；不进入识别请求。本实验不能给出全量文档 precision/recall 或发布质量结论。

- A：通用指令与简化阅读卡。
- B：同一指令与卡，加身份属性标记；不提供完整键组、属性定义或作用域。
- C：同一指令与卡，提供完整身份语义。
- C_tool：以 C 的结果为起点，通过现有原文定位器返回位置、引文错误及重叠情况，再调用
  一次同模型。工具不返回正确对象数量、正确编号归属或金标，也不代替语义判断。
- C_repeat：以同一个 C 结果为起点，仅让同模型再次核对，用于区分额外调用与工具反馈。

数量、编号字段归属、可定位且不重叠分别评分。字段评分检查参考标识是否逐对象保存，
允许同时保存日期等其他原文字段；它不等同于编号本体属性采信，后者通过真实段落全流程
单独核对。工具实验是固定一次反馈，不代表已实现自主工具选择或完整 Agent 工具循环。

## 真实原句全流程

原始段落使用修订后的完整冻结本体，从空状态运行发现、类型对齐、实体核验、属性/关系
对齐及证据核验，共 13 次模型调用；没有向模型注入三个正确成员或已接受类型。

结果：发现仍将 `611/642/646车间` 合成一项；后续实体核验拒绝整组，最终 **0 个已采信
生产区域、0 条区域编号属性**，没有恢复为 3 个成员。`producedInArea` 候选因端点未确认
保持 unresolved，未将旧边复制给不存在的新节点。生产计划的批数、用途和批量上下界正常
采信（此处报告系统采信状态）。窗口的 `scope_complete=true` 仅表示已执行该窗口，不能代表成员召回达标。

该结果否定“接通身份信息即可保证本例成功”，也不能把拦住整组候选称为问题已修复。

这组实验主动提供可定位的候选假设，以便把发现失败与核验能力分开观察；未将这些候选
当成模型自行发现的结果。属性实验的主体类型已确认也是测试前提。

| 输入假设 | 期望 | 真实结果 |

| 整个 `611/642/646车间` 作为一个生产区域 | 不可作为单个区域采信 | accepted，反例失败 |

这与单独核验整组候选时的 accepted 相矛盾，表明独立调用结果不稳定，尚不能把数量
核验作为稳定门禁。本实验没有重复采样，不能把差异只归因于上下文或单个元数据字段。拒绝整组也不等于补齐三个正确节点：本轮未新增自动拆点或复制旧边。

## 工具边界的实证

纯定位工具只能证明原文位置和引用范围。真实完整句子的第一次完整定位反馈超过输入预算，
调用前失败；紧凑版本去掉重复原文和物理元数据后为 **31990 字节预算上界**，在原有 32768
预算内执行，但仍输出一个车间候选，并虚构了原文不存在的字段标签“生产区域编号”。
未截断原文、本体定义或完整键组。该标签会被现有原文解析门禁拒绝。

专用语义工具改为直接输出“候选类型＋指称 anchor＋编号谓词及引用＋解释类别”，同样使用
当前本地模型。原句首次输出将 `611`、`642`、`646` 均挂在一组，类别为
`multiple_identifiers_of_one_object`，理由把车间集合视作一个区域。其引用在原文中存在，
不能因此认定分组语义正确。此结果不支持把语义对应能力直接外置后默认上线。


专用语义工具的提议传给发现阶段后，仍为一个区域挂三个编号。工具反例中的单个复合编号、
同对象改号和双系统编号均保持一个对象，三项通过；但目标正例失败，不能以反例通过代替
目标能力验收。独立再次核对和紧凑定位反馈也都保留了一个整组车间候选。

工程评分另补一项回归测试：错误字段标签和跨独立来源的编号值不能被计为正确对应，
**1 passed，0.13 秒**。最终矩阵用修订评分器重新核对所有名称、标签和值引文；原始模型
输出和初版分数保留，不原地改写。

## 评分范围与人工复核

发现对照的 `count_ok` 比较模型提出的全部物理提及数与受控参考，不等同于经类型核验后的
本体实体数量。尤其复合键 C 用例输出“两家机构＋两条记录”，不能表述成“四条记录”或
已经证明错误拆分四个记录实体。该例的明确失败是：机构值没有绑定到对应记录，记录各自
仅保存编号，完整复合键未形成正确归属。原始四个提及及分项指标均保留。

日期/型号/比值用例维持一个设备，没有按分隔符造对象；但将编号只留在 anchor，遗漏了
对应原字段，因此“数量正确”和“编号字段对应正确”分别计分。备选/否定/总量用例的发现
结果不冒充最终关系事实；全流程关系核验只在原始完整段落执行。错卡/无身份标记、对象属性
键组件及预算遗漏等还包含工程契约测试，本次没有对每种组合完成真实模型的最终关系评测。
生产本体没有新增 `owl:hasKey`；复合键均来自隔离 fixture。

## 对四项方案的判断

| 项目 | 判断 | 验收依据 |
| --- | --- | --- |
| 1. ProductionArea 编号与 identityKey | 通过本期工程验证 | 新增 7 条三元组，隔离 World 加载及类型/继承边界通过；无全局唯一或单值公理 |
| 2. reading_card 身份属性与键组 | 通过本期工程验证 | 发现、实际类型核验、共指收到完整语义；不靠名字猜键，不截断键组 |
| 3. 指称—编号对应及工具外置 | 未通过目标验收 | 原句仍合并；定位与专用语义工具都未纠正，额外调用没有实现目标 |
| 4. 独立核对数量、属性和身份 | 部分通过 | 正确/错配属性均正确判定；数量判断不稳定；身份判定匹配 2/5 |

建议保留 1、2 作为领域无关的信息基础。后续需要围绕本轮失败样例，验证能明确表达对象
层级、标识归属和完整键证据的语义任务及模型能力；工具优先承担引用定位和声明完整性检查。
单独增加身份标记、继续叠加自然语言要求或把同一判断移到另一工具调用，都不能被当作已验证
的修复。没有增加线上工具路径、分隔符拆分规则、实例补点或旧边复制机制。

本轮工程检查合计 **228 个不同测试通过**（218＋9＋1，重复执行不累加），Ruff 通过。
真实模型识别验收未通过；主服务未重启/重载，来源运行的冻结本体及图谱未修改。
