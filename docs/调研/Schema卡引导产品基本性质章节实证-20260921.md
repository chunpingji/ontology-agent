# Schema 卡引导“产品的基本性质”章节实证

## 结论

在不修改主流程、权威本体或模型的独立实验中，**原文与字段→相关卡片召回→有卡片
引导的实体构造→类型消歧**能够产生用户预期的候选路径：

```text
CMCReport ── describes ──▶ DrugProduct
```

具体条件是：语义 Top-6 召回后，按统一规则补充召回卡片在当前本体范围内的命名上位类。
单纯使用 Top-6 没有通过该目标。补充组最终保留同一局部实体 `drug_product`，类型为
`https://ontology.pharma-gmp.cn/slpra/drug/DrugProduct`，原文依据是
“制剂剂型：口服片剂”。关系谓词为当前 CMCReport 卡上的
`https://ontology.pharma-gmp.cn/slpra/drug-development/describes`，方向及 range 合法。

这是候选路径可发现的验证，**不是完整实体构造质量或事实采信通过**。模型仍把 19 个
原字段挂到一个产品对象，并额外提出指向未登记 API 端点的关系；补充组返回
`complete=false`。没有运行事实采信，也没有将任何结果写入主服务图谱。

## 实验步骤与对照

查询直接由该章节的原文与原字段构成；卡片检索文本来自名称、别名、定义、属性语义
和关系语义。对 137 张卡执行嵌入召回，取 24 张精排，再取 Top-6。

第一组按原始 Top-6 实际构造、消歧。该组未达到目标后，增加第二组实验：对每张
召回卡统一沿 `parent_iris` 补充当前可达卡片中的上位类型。此调整由第一组结果启发，
属于探索性对照，不是预注册或统计显著性实验。两组原文、模型和提示相同；模型
温度非零且未固定随机种子，不将单次差异当作稳定准确率或严格因果估计。

| 对照项 | 原始 Top-6 | Top-6 加通用上位卡 |
|---|---|---|
| 实际卡片数 | 6 | 8 |
| 构造结果 | 错提 BiologicalProduct，19 字段全归一个对象 | 提出 DrugProduct，仍将 19 字段全归一个对象 |
| 类型消歧 | 返回 null，指出候选卡缺少适合的普通类型 | 同一局部 ID 保留 DrugProduct，引用 S14 |
| 关系结果 | 1 条 describes 提议，类型消歧后不能形成合法目标路径 | 1 条合法 describes 候选；另有 1 条悬空成分关系 |
| 模型 complete | true（不代表语义正确） | false |
| 已采信事实 | 0，未执行事实采信 | 0，未执行事实采信 |

原始精排 Top-6 为：细胞毒 API、生物制品、β-内酰胺类药物、青霉素类药物、细胞毒药物、
中药制剂。API 第 11，DrugProduct 第 15。多个具体类别在原文中是否定字段，相似度
仍将相关类别排在前列，因此分数不能作为类型成立的证据。

上位卡补充规则没有目标名称或 IRI 特判：由召回的 β-内酰胺类药物等子类补入
DrugProduct，由细胞毒 API 补入 API。补充组复用同一份真实召回结果，没有重算排名，
也没有手工提升目标卡分数。

## 实体与字段质量核对

- **DrugProduct 有直接候选依据**：S14 为“制剂剂型：口服片剂”，符合最终制剂类型。
  名称为 null、局部 ID 为 `drug_product` 是允许的；不应据项目名称推导全局产品身份。
- **字段归属仍未解决**：分子式、化学名、粉末性状和溶解性与最终片剂不是同一层级。
  将所有字段挂在 DrugProduct 下不能作为正确属性结果。消歧虽然选对类型，仍未纠正
  原对象的字段混合；模型理由还部分沿用了“已保存实体的角色为药物产品”。
- **关系证据尚非完整证明**：`describes` 原答只列 S1/S2 两个章节标题；类型证据另列
  S14。它们可作为可追溯的组合候选上下文，但本次没有完成关系的独立原文核验，
  不能显示为已采信实线。不能声称模型在关系 evidence 中已经完整引用了 S14。
- **悬空关系被保留为问题**：原答另提出
  `drug_product → hasActiveIngredient → api_candidate`，但没有输出该 API 实体。
  首次消费因此失败。随后仅调整实验消费器，用同一份已付费原答保存有效实体及
  已登记端点关系，将该悬空边写入 `construction-issues.json`；未重新调用构造模型，
  未补造端点，未隐藏原始失败。通用知识“药物产品由活性成分构成”也不能证明该具体关系。
- **缺失与否定保留**：F7 的 `CAS=N/A` 原值和 `missing=true` 保持；“否”不当缺失，
  “无需灭活”不能推为“不可灭活”，复合分类否定不能任意拆为多个属性 false。
- 当前 `describes` 注释包含 drug substance，但正式 range 不含 API。实验没有扩宽
  range，也没有为了连边将 API 自动改成 DrugProduct。

## 实际成本与验证

共享语义召回总耗时 **91.26 秒**：初始化/制品与设备核对 18.00 秒、嵌入 59.89 秒、
精排 13.37 秒。共 41 个模型基础设施操作，记录于 retrieval.json；第二组仅复用结果
并作本体上位卡展开，不重复计这部分费用。

整窗运行范围不同，不能据此报告整体提速。

四个 LLM 响应都通过本次动态 JSON Schema 检查；实体 ID 在交接中保持不变。
原字段与模型引用共 121 次引用校验均与原文字符区间一致。JSON Schema 合法不等于
端点存在或字段归属正确，悬空边在独立引用关系检查中失败，已如实记录。

未修改、部署主流程，没有改权威 TTL，没有执行全文、最终 precision/recall 或速度验收。
本次只运行真实实验与结果校验，没有重新运行主服务工程回归测试。

## 后续实施需要保留的结论

1. 卡片召回需要通用上位类型补充与未匹配出口，不能把 Top-K 当封闭世界。
2. 对象构造必须处理物质、制剂等角色下的字段归属；类型标签选对不等于实体 JSON 正确。
3. 实体登记后再用已登记端点约束关系输出；单条坏关系不能抹掉已保存实体，但必须报告原因。
4. 类型依据、关系依据与原字段来源均保留，后续核对可明确组合原文，不以 SHACL 作严格识别门。
