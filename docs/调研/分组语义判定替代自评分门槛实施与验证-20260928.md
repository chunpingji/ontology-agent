# 分组语义判定替代自评分门槛：实施与验证（2026-09-28）

已取消指称分组中 `confidence < 0.85` 的硬性否决，改为明确的语义判定加可核验约束。消息协议升级为 `document-harness-v3`。自评分保留在原答和当前状态中，不决定分组是否登记。工程回归 339 项通过，真实 GPT 阶段复测 8 次完成；原始斜杠句仍被模型明确判为语义未决，不能宣称核心拆分目标通过。本轮未重启部署。

## 实施规则

[协议定义](../../backend/app/services/document_harness/protocols.py)的 `ReferentSelection` 新增必填 `verdict`：

- `supported`：原文语义支持所选完整分组，必须提供非空分组 ID、决定性原文片段与理由。
- `unresolved`：关键证据不足或实质歧义尚未消解，分组 ID 必须为 null。不能只给一个更倾向的分组，再靠低分暗示未决。

提示要求核对编号边界、成员归属、对象层级、复合编号/改号及竞争解释。外部命中、分隔符、编号不同本身不能决定对象数；来源全局身份限制也不自动否定有据的局部指称。

[正式决策函数](../../backend/app/services/document_harness/referents.py) `resolve_selection` 不读取 confidence。它在候选已经通过合法属性、原文范围、完整覆盖和成员不重叠等校验后，要求 supported 且选择证据覆盖全部成员，才允许登记。矛盾消息、未知分组或未知片段仍被拒绝；证据未覆盖全部成员时保留未决，保存 `selection_issue=selection_evidence_does_not_cover_members`，观察与实体理由同步说明缺口。原始 supported 回答不被改写，便于区分模型判断与程序约束结果。

登记出的成员仍为 candidate；实体、属性、关系及来源身份不是因此自动采信。该改动仅针对当前问题所在的指称分组阶段，其他阶段的规则独立，没有全局删除数值门槛。公开图谱结构不变，没有新增数据库表、本体修改或模型配置开关。新运行默认采用新协议，旧消息不补写 verdict、不转换为 v3 结果。

## 工程验证

[新增回归](../../backend/tests/test_document_harness/test_referent_decision.py)共 18 项，覆盖：

- 同一 supported/unresolved 判定分别使用 0、0.77、0.84、0.85、1.0，自评分不能改变登记结果。
- 0.77 的 supported 加完整证据可登记；1.0 加不完整证据仍未决，并保留具体失败原因。
- supported + null、supported + 空证据、unresolved + 非空分组均拒绝；高分不能替代缺失 verdict 或选择未知分组。
- 保存后的低分 supported 结果继续时不重复调用或登记；来源身份仍为 not_checked。

同时更新现有 fixture 和协议版本预期，没有放宽旧的编号覆盖、重叠或来源验证断言。首次定向检查发现新增测试误读观察字段 `value`，已依据实际契约改为 `reason`；生产行为断言保持不变。

## GPT 阶段实测

入口：[harness_referent_decision_probe.py](../../backend/app/evaluation/harness_referent_decision_probe.py)。继续使用用户授权网关的 `gpt-6-sol`，只调用选择阶段：

1. 原始斜杠句和明确并行句分别复用上一轮选择调用 027、036 的原文、类型、候选、片段与来源反馈，逐项确认 payload 相同；新 Schema 要求显式 verdict，各真实调用重新生成完整回答。
2. 用两个新建单句 DOCX 验证显式复合编号及明确歧义。两例提供相同的整体/两成员竞争方案；原文与片段重新定位，不伪造历史片段位置。来源候选沿用冻结输入，没有实时查询 Mock。
3. 所有回答通过当前生产 Schema/类型验证，候选经正式 `validate_partitions` 校验，选择经正式 `resolve_selection` 决策。参考预期仅用于返回后评分，不放入模型消息。

这是固定候选下的选择阶段试验，不包含本轮发现、类型、属性、关系或完整 Engine 运行，也不替代整份文档质量验收。生产模块快照与当前工作区字节一致。

| 场景 | 次数 | GPT 新回答 | 正式决策/目标结果 |
|---|---:|---|---|
| `计划于644/642车间完成本次临床样品的生产。` | 3 | 全部 unresolved；自评分 0.88、0.87、0.91 | 保留未决；两成员拆分目标 **0/3** |
| 明确“644车间和642车间并行生产” | 3 | 全部 supported；0.98、0.98、0.97 | 两个成员、编号分别归属，阶段目标 **3/3** |
| 原文明示 `644/642` 为完整编号，斜杠属于编号且指一个车间 | 1 | supported；0.99 | 保留一个复合编号成员，**1/1** |
| 原文明示两种解释均可能且资料无法确定 | 1 | unresolved；0.99 | 不登记任一解释，**1/1** |

按预设目标合计 **5/8**，不将原句未决移出分母。明确并行的这里仅指成员分组通过，不冒充本轮并行关系已经重测。

原句新回答的决定性理由是：斜杠可能属于复合编号，也可能并列两个车间；原文没有进一步消除歧义，外部单号命中不能替代这一语义判断。即使自评分超过旧门槛，也不会把 unresolved 变成 supported。相比上一轮“选择 P2、分数 0.77 被程序拦截”，现在模型明确表达未决，程序依据判定及约束执行。旧 0.77 回答没有被人工补写 supported 后重新计为成功。

这证明硬门槛已被替换、显式状态与证据约束可执行；它没有证明原句一定可以拆成两个车间。该语义质量问题仍需更多原文依据或单独明确来源键约束在局部分组中的证明权限，不能仅通过调整分数制造通过结果。
