# CMC 设备独立参考与原文复核计划

本参考是助手逐项阅读后的手工参考，未经领域专家裁决，不是专家金标，也不是完整关系图谱金标。仅供本轮识别后的评价；`reference.json`、其中的行号、编号及选择条件不得进入检索、模型提示词或工具输入。主实验应继续自行从全文检索设备记录。

参考来自指定报告 `upload-23c872fb-3ab1-41de-a705-dd4b162dfa09` 的同一冻结 IR，已读全部 **447 个单元、5398 个原文字符**，以及当前静态 `backend/app/resources/equipment_archive.json` 的 **211 条记录**。未读取本轮未来预测。`reference.json.source` 固定输入路径、SHA-256、analysis/document/structure 身份。`build-reference.py` 只读这两个输入，使用人工核对的原文标注生成参考；所有引文均通过 `DocumentIR.resolve` 回放校验。

## 档案属性与冲突口径

真实存在的一处**属性值差异**是 CT64610：设备需求表 row 4/column 4 原文为“不锈钢衬HALAR”，Mock `/113/material` 为“316L不锈钢”。应保留两个有独立来源的值并标记待核对，不能用档案覆盖文档。由于 Mock 未明确否定衬层，这并不能单独证明物理材质互不相容；参考将“值不一致”和“已证明的语义矛盾”分开计数，后者为 0。

RE64611/RE64613 的文档名称“200L/500L反应釜”与 Mock“搪玻璃反应釜”是可相容的不同描述，不能当作冲突。两个 PF 的“不锈钢”与“316L不锈钢”是档案更具体的牌号，不能直接判冲突。本次没有设备编号或规格型号的文档/Mock 值冲突，不能为了测试增加一项。

DE64603 在 211 条档案中无精确编号；DE64203 虽具有相同“真空干燥箱”名称及“24盘”规格，但编号不同，不得用名称/型号相似度替换。Mock 的位置、车间、区域属性若引用，只能标为 Mock 来源，不能伪装成报告已证明的设备事实。

## 源文复核与评价步骤

1. 在预测前冻结参考及档案文件哈希。识别过程仅使用主实验自行检索的记录；不按本参考选择片段。
2. 先对预测逐条回放原文引文，分别检查编号提及、名称/编号归属、表头、逻辑行与备选条件，再看工具是否接纳。
3. 将“18 次物理提及召回”“6 个不同编号召回”“5 行字段绑定”和“3 次或条件保留”分开评价。检索未选中与模型读到后遗漏也分开记录。不是所有片段都进入提示词时，不把片段内召回冒充全文召回。
4. 对 5 个已知编号核对精确匹配；对 DE64603 要求 `not_found`，并核查没有被错误替换成 DE64203。档案查到记录不等于同一报告的全部关系已成立。
5. 设备与过程的关系需核对谓词、方向与“计划/需求”语境；两个 PF 关系必须附备选条件。本参考没有给整个报告的所有关系打金标，未覆盖关系单列未评分。
6. 比较文档与 Mock 属性时分开原文值、档案值、条件及差异类型；仅 CT64610 材质记为真实值差异候选，不将相容描述计错。
7. 仅在证据与语义成立后评价字符串类型/SHACL 表示校验。保留技术失败、未尝试和未决，不能仅在成功样本上报告整轮通过率。

## `validate_metric` 对三个文本属性的可复用性

源码检查依据：`ontology/slpra/slpra-equipment.ttl` 的 `equipmentID`、`equipmentName`、`modelSpecification` 均为 `xsd:string`；`backend/app/services/extraction/tool_validation/metric.py` 已按槽位类型处理字符串；`ontology_guided/value_constraints.py` 对字符串仅执行 `raw.strip()`；`tool_validation/shacl.py` 使用固定 `metric-representation-v1` 对单个 literal claim 的 raw/predicate/value 和 focus 覆盖做检查。

这三个属性可以复用现有函数，条件是传入冻结的 `SlotSpec`、原文 `raw`，并由可信调用方完成实际 source/owner/field 绑定检查。`binding_issues=None` 会保留 `binding_not_checked`；不能让模型自行提供空错误列表或 `semantic_status="supported"`。在语义未核验时，字符串可做类型预检查，但不会给出正式规范值或 SHACL 合格结论；语义与绑定检查都通过之后，才执行当前固定 SHACL profile。

复用的验收含义应限定为：**“有原文证据和语义判断前提的字符串表示检查”**。其预期 `quantity=None`、`unit_checks.status="not_required"`；即使 `normalized_value` 有值、SHACL 覆盖并符合，也不属于数值/单位校准。`200L`、`10英寸3芯`、`600`、`24盘` 在 `modelSpecification` 中必须保留为型号字符串，不能为了演示单位换算而拆成物理量，也不能将 `600` 推成直径毫米。

现有 profile 不校验设备编号正则、跨实体唯一性、档案身份、型号的工程含义、文档/Mock 相容性或 alternative 关系。空字符串也不能仅凭该 profile 排除；候选输入和证据核验仍须拒绝无实值。SHACL 成功不提升这些未覆盖能力，且 `fact_eligible` 仍为 false。

本任务只完成源码可复用性审查及参考引文回放，没有另行调用模型、构造数值指标或宣称这三个属性已通过本轮模型抽取验证。
