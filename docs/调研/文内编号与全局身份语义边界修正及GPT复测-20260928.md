# 文内编号与全局身份语义边界修正及 GPT 复测（2026-09-28）

本轮针对 GPT 已识别车间编号，却在证据核验中以“缺编号体系/范围”将编号判为未决的问题。修改属性对齐与证据核验提示，明确文内编号事实和来源全局身份是两个判断。代码默认启用，本轮未重启部署，也未切换线上默认 Qwen 模型。

同输入对照从旧提示 **0/6** 改善为新提示 **6/6**，四项边界试验 **4/4** 符合预期。当前协议下，明确并行句从空状态成功采信两个编号与并行关系，来源身份仍未确认；原始斜杠句另因上游分组置信度不足未通过完整目标。因此该属性核验问题已有针对性改善证据，完整 H01/H02 仍未通过。

## 修复范围

原因位于旧提示“身份属性须有实例、命名空间及范围依据”。它把全局身份确认所需条件加到了文内编号值上，而本体原文仅规定范围不明时不声明全局唯一。新提示要求：

- 依据原字段或称谓上下文，核验编号含义、完整原值、对象层级及成员归属；不要求原文复述本体属性标签。
- 缺少命名空间、组织/场地或唯一性范围，不自动否定有原文依据的编号属性。
- 名称中的任意数字、数量、其他对象编号、外部命中及先前绑定均不能替代语义证据；有反证拒绝，缺证未决。
- 属性定义若实质要求特定体系或认证状态，仍须满足该限定。
- 属性采信不改变来源 `identity_status=not_checked`，不确认跨文档同一性或执行合并。

正式修改在 [protocols.py](../../backend/app/services/document_harness/protocols.py)，同步[需求](../../specs/036-mapped-entity-query/spec.md)、[计划](../../specs/036-mapped-entity-query/plan.md)、[契约](../../specs/036-mapped-entity-query/contracts/harness-grouped-alignment.md)与[复测步骤](../../specs/036-mapped-entity-query/quickstart.md)。没有修改本体定义、数据库、来源映射、模型输出值或采信门槛。继续使用 `document-harness-v2` 片段 ID 协议。

## 试验设计

复用用户授权的 Responses 网关，请求模型 `gpt-6-sol`。密钥仅由隐藏终端读入，不写入脚本、命令参数或产物。复用既有 SSE 传输及 Schema 适配，对返回继续执行原生产 Schema 和类型协议校验。

依据[官方评测建议](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，固定输入并加入典型及边界反例。这里的参考是开发回归预期，不是专家完整文档金标。请求 temperature=0.1、reasoning effort=none、输出上限 16384；实际网关返回采样参数另随汇总保存，不假定请求值被原样执行。

43 次返回的模型标识均为 `gpt-6-sol`，返回 temperature 均为 **1.0**；网关未提供可冻结的权重 revision。旧/新两组使用相同请求参数及网关，不能将其描述为实际 temperature=0.1 的试验。

1. **同输入提示对照**：取历史 GPT 失败的属性核验请求 `paired-03/call-012.json` 和 `call-040.json`；每句旧/新提示各三次，交替调用顺序。核验 Schema 与当前实现一致，保留原实体枚举顺序；原文、属性定义、成员绑定、来源候选及采样请求均相同，唯一试验差异为证据核验 instructions。新输出均由本轮真实 GPT 生成。
2. **四项边界试验**：以历史请求为基础构造无来源候选、成员错配、名称数字反例及属性自身要求认证的请求，逐项预先明确预期。它们是受控阶段试验，不冒充完整文档运行；认证限定例只改试验输入定义，未改线上 TTL。
3. **当前完整流程**：两条单句分别从空 Engine 执行当前正式控制器。原文、本体及精排冻结并检查输入 hash；所有发现、类型、片段候选、属性、关系、证据及共指回答重新调用 GPT，不回放历史模型回答。并行例由用户输入给定计划根，不算模型新发现正文计划。

来源查询使用正式服务与 PostgreSQL 只读事务；运行图谱保存在隔离目录，没有提交业务事实。预算为 50 次请求、1800 秒。活动入口为 [harness_identifier_semantics_probe.py](../../backend/app/evaluation/harness_identifier_semantics_probe.py)。
