# Qwen 与 GLiNER：中文指代、NER 和属性归属实测

2026-09-20，已执行真实模型推理。**本组样本中，旧 GLiNER 能完成名称识别，GLiNER2.5 能抽取简单产品记录，但属性归属在交换“前者／后者”后出错；Qwen 能正确随指代交换属性归属，但证据引文存在改写。** 这是一个原句加两个合成对照句的案例测试，不是通用准确率、领域金标评测或部署验收。

## 输入与模型

三个模型都读取以下原文，不输入参考答案，不微调：

1. `original`：`iPhone是apple公司乔布斯设计的智能手机产品，其创新型的设计显著区别于传统Nokia功能型手机`
2. `former_innovative`：`iPhone与Nokia手机进行对比，前者的设计具有创新性，后者采用传统设计。`
3. `latter_innovative`：`iPhone与Nokia手机进行对比，后者的设计具有创新性，前者采用传统设计。`

原句按“原文声称什么”抽取，不核实产品设计史。两个对照句是为检验局部指代构造的输入，不作为现实产品结论。

| 项目 | 本次实际配置 |
|---|---|
| Qwen | 服务返回 `Qwen3.6-35B-A3B`；temperature=0，thinking=false，输出上限 3000 tokens；每句一次，共 3 次请求，无模型重试 |
| 旧 GLiNER | 本地 `urchade/gliner_multi-v2.1`；运行包 `gliner 0.2.29`；项目中文 splitter，flat NER |
| GLiNER2.5 | `fastino/gliner2.5-multi-v1`，包 `gliner2 2.0.0`；boundary；char splitter；允许重叠跨度 |
| GLiNER 阈值 | 0.5 为主结果；事先固定 0.3 为诊断结果，两组均保留 |
| 执行资源 | 两个 GLiNER 均为 CPU、4 threads；Qwen 使用现有服务。资源及模型大小不同，不作同硬件性能结论 |
| GLiNER2.5 预处理 | 保留原文，不使用默认自动补句点；主实验 encoder 输入 124～223 tokens，均通过 512 tokens 检查 |

GLiNER2.5 revision 为 `aaecfe45db1d828c963717054ccb868e8ad1f1d5`，权重 SHA-256 为 `c1ff4ec0bc00031c15530b8f3c33d3677f27949e6a0cb52e1247a6224b6c5395`，已按本地 manifest 校验。Qwen 声明 revision 为 `0b21525e972670ed59e1812e170b27c26355381f0656ecc4e25617ece7dac58b`，本次只核对配置和服务模型名，未独立核验服务端权重。

各模型使用相同实体类别及任务含义；接口不同：旧 GLiNER 输入类别名，GLiNER2.5 使用任务 schema 及描述，Qwen 使用这些定义及 JSON Schema。没有把某一模型的输出传给另一模型。

## 原句结果

| 检查项 | 旧 GLiNER | GLiNER2.5 | Qwen |
|---|---|---|---|
| 实体 | `iPhone/产品`、`apple/公司或品牌`、`乔布斯/人物`、`Nokia/公司或品牌` | 同样找到四个名称；NER 额外将裸 `Nokia` 标为产品，不符合本次“单独品牌不作产品”的定义 | `iPhone/产品`、`apple公司/公司或品牌`、`乔布斯/人物`、`Nokia功能型手机/产品`；未另列嵌套的 Nokia 品牌 |
| 显式指代 `其→iPhone` | 当前 NER 模型没有此输出任务 | 自定义 `corefers_to` 关系为空；补测指代记录 schema 也为空 | 正确返回 |
| 设计者 | 当前模型不提供归属 | 产品记录返回 `iPhone→乔布斯`；独立关系接口的 `designed_by` 为空 | 返回 `iPhone→designed_by→乔布斯` |
| 设计特征归属 | 不提供 | 产品记录返回 `iPhone→创新型`；属性分类返回“创新” | 返回 `iPhone / 设计特征 / 创新型的设计` |
| 产品类别 | 不提供 | 产品记录为“智能手机” | “智能手机产品” |
| 比较 | 不提供 | 产品记录只保留比较对象“Nokia”，丢失“传统／功能型手机”范围 | 保留“传统Nokia功能型手机”，没有声称全面优于；但比较主体简化成 iPhone，未在该字段单独保留“设计”范围及“显著”程度 |

GLiNER2.5 的原句产品记录（精简展示；置信度不是归属正确概率）：

```json
{
  "产品": "iPhone",
  "设计特征": "创新型",
  "设计者": "乔布斯",
  "产品类别": "智能手机",
  "比较对象": "Nokia"
}
```

因此，**抽对该原句的产品记录，并不能证明完成了通用指代消解**。

## 指代交换对照

| 输入 | 应有设计归属 | GLiNER2.5 产品记录 | GLiNER2.5 属性分类 | Qwen |
|---|---|---|---|---|
| 前者创新、后者传统 | iPhone 创新；Nokia手机传统 | iPhone 创新；未输出 Nokia 的传统设计记录 | 两者均正确 | 两者均正确 |
| 后者创新、前者传统 | Nokia手机创新；iPhone 传统 | 仍输出 **iPhone 创新**；归属错误 | iPhone 传统正确；**Nokia手机也被标为传统**，错误 | 两者均正确 |

在错误的“后者创新”产品记录中，“创新性”字段置信度为 **0.96794**，产品 iPhone 的置信度为 **0.99211**。两者各自看似高分，组合归属仍然错误。降阈值至 0.3 后产品记录不变；属性分类错误也没有修复。

三句的四种独立关系 `designed_by / corefers_to / has_design_feature / differs_from`，在两个阈值下均为空。这仅描述本 checkpoint、本中文 schema 和输入的实测结果，不能推广为所有 GLiNER 关系模型都不支持这些关系。

主实验后补做两项诊断，单独存放，没有替换主结果：

- 使用 `指代关系{指代表达, 先行词}` 结构化 schema，三句均返回空对象。
- 使用官方英文例句和 `works_for / lives_in / located_in`，char 与 whitespace splitter 都返回三条正确关系，说明本地关系接口可以工作。char 模式的地名跨度包含末尾句点，whitespace 模式没有。

## Qwen 的证据问题

仅按语义审阅，Qwen 返回的 5 个指代链接均正确，5 项目标设计特征归属均正确。**这不是 100% 的整体抽取质量**：5 条指代引文中有 3 条无法逐字回放。

| 对照句 | Qwen 原始 evidence | 问题 |
|---|---|---|
| 前者创新 | `iPhone与Nokia手机进行对比，前者...` | 原文没有 `...` |
| 前者创新 | `...Nokia手机进行对比，...后者...` | 拼接及省略，不是连续原文 |
| 后者创新 | `后者设计具有创新性，前者采用传统设计` | 原文是“后者**的**设计”，漏了“的” |

原句的 `其→iPhone` 引文“其创新型的设计”虽是原文子串，但单独不含先行词；独立核验仍需联合前半句。控制句中的部分 `differs_from` 只引用“进行对比”，该引文本身不足以证明差异，需要同时核对两方设计描述。Qwen 的比较输出也应限定到设计方面。

全部 GLiNER 输出中共 96 个被检查的跨度均能按字符坐标回放到原文，包含主实验、阈值诊断及英文补测。**坐标正确没有阻止 GLiNER2.5 的语义归属错误。**

## 本次耗时与成本

下表为主阈值 0.5，模型加载之外的墙钟时间。GLiNER2.5 列为 NER、关系、产品记录、属性分类四次调用之和；Qwen 每句一次请求完成全部任务。

| 原文 | 旧 GLiNER：NER | GLiNER2.5：四任务 | Qwen：全部任务 |
|---|---:|---:|---:|
| 用户原句 | 0.336 s | 1.257 s | 13.313 s |
| 前者创新 | 0.179 s | 0.985 s | 8.871 s |
| 后者创新 | 0.179 s | 0.970 s | 10.272 s |

旧 GLiNER 加载 6.297 s，GLiNER2.5 加载 23.340 s。Qwen 服务已经运行，未测冷启动；两条对照请求均报告 164 cached prompt tokens。现有服务可能有并发任务，本结果不是独占硬件的稳定延迟基准。

Qwen 总计 **3 次成功 HTTP 请求，输入 1,268 tokens，输出 1,687 tokens，总计 2,955 tokens**。GLiNER 主实验 30 次本地推理，补充诊断 5 次，均完成。未调用云端模型、未训练、未改应用配置、未重启服务、未提交业务事实；Qwen 使用既有共享调度并记录正常调用用量。

## 对项目的结论

本案例支持保留 GLiNER 作为实体和属性候选抽取工具；需要可靠局部指代与主体归属时，Qwen 在本组对照中更合适。Qwen 输出仍须核对原文证据，不能把语义正确、JSON 合法或实体坐标正确直接等同为事实通过。

若继续训练 GLiNER，应加入这种“仅交换前者／后者，属性归属就反转”的关系／记录监督，而不只增加 NER 标注。是否有效需另建未参与训练的文档测试集。本次没有实施训练，也不据三个例句替换线上模型。
