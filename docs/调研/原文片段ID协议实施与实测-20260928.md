# 原文片段 ID 协议实施与实测（2026-09-28）

已将编号候选与指称分组选择改为原文片段 ID 协议，正式代码默认启用，尚未重启部署。程序提供片段目录，模型选择 ID，程序还原编号和成员位置；目录缺项允许一次严格定位补充。模型消息协议为 `document-harness-v2`，公开图谱沿用既有结构。

当前 Qwen 的受控回归验证了两成员编号绑定、无 Mock 和缺项补充。第 02 轮明确并行句还完成了属性与关系采信；原始斜杠句仍缺正文生产计划端点，完整 H01/H02 尚未通过。不能将阶段绑定、流程完成或片段定位成功等同于全部语义正确。

## 协议与实现

契约见[正式分组接线](../../specs/036-mapped-entity-query/contracts/harness-grouped-alignment.md)。实现集中在 [protocols.py](../../backend/app/services/document_harness/protocols.py) 与 [referents.py](../../backend/app/services/document_harness/referents.py)。

| 消息/数据 | 当前契约 |
|---|---|
| `evidence_spans` | 程序根据文档 hash、原文单元及字符范围分配 `P...` ID；文本从原文切片 |
| `expressions` | `{id, property_iri, span_id}`；不再输出引文文本 |
| `partitions.members` | 引用 `expression_ids`；程序派生成员 anchor |
| `new_spans` | 仅目录缺项时提交 `{source_id,text,occurrence}`；这一轮表达及分组为空 |
| `referent_selection` | 选择完整分组，证据使用 `evidence_span_ids` |
| 后续编号绑定 | 同时保留 `span_id`、程序还原的值/位置及来源候选，属性映射不能交换或改写绑定 |

目录来自当前可见原文、已定位提及/字段与 Mock 键的逐字出现。同文同位置复用 ID，不同出现或不同文档使用不同 ID。整句和名称默认只作上下文；已定位原字段值、来源键出现可成为编号候选。动态 Schema 只允许表达引用编号候选 ID，选择证据则可引用当前全部目录 ID。

候选资格不证明字段就是编号，也不证明完整边界、对象数量或全局身份。保留 `boundary_status=not_checked` 和 `identity_status=not_checked`。不能仅因键在较长字符串内部出现就裁剪原值，也不能因没有 Mock 记录而漏掉原文对象。

缺项补充必须全部通过逐字定位、范围和重复检查，程序才扩充目录并重问完整分组。每组最多一次，暂停继续不重置机会，调用仍计入既有预算。未知 ID、伪造或拼接引文、再次补充、错误覆盖及成员重叠仍被拒绝。没有加入模糊匹配、领域正则裁剪或按斜杠自动拆分。

本机制替代 H01d 的 `quote_correction` 重抄纠错，不保留旧消息转换。发现及其他阶段原有的定位协议不在本次替换范围内；严格原文校验仍用于新片段登记，不能理解为全系统不再校验证据。评测对照入口同步拒绝旧协议基线，避免以转换后的历史回答冒充新协议模型输出。

## 真实模型方法与评分

模型为 `Qwen3.6-35B-A3B`，revision 为 `0b21525e972670ed59e1812e170b27c26355381f0656ecc4e25617ece7dac58b`，temperature=0.1。没有再次调用用户提供的 GPT 网关。

固定两条单句、本体及精排：

- `members`：`计划于644/642车间完成本次临床样品的生产。`，根类型为 CMC 报告。
- `parallel_plan`：`本次临床样品生产计划同时在644车间和642车间并行生产。`，给定生产计划根。该根不是模型从正文新发现的计划。

每例由空 Engine 新建运行。为固定进入问题阶段，分别回放原真实发现/类型回答 8 次和 2 次；逐项校验请求 payload/Schema 与原始记录一致。自新协议 `referent_candidates` 起均为新的真实 Qwen 调用。精排输入 hash、本体及模型 revision 均核对一致。参考答案不进入识别输入。这是受控阶段/流程回归，不能称所有阶段从头重新调用模型。

来源查询使用正式服务和 PostgreSQL 只读事务，没有修改 Mock、本体或提交业务事实。模型调用有既有调度与用量写入，因此整轮评测不称为只读操作。

阶段绑定通过要求：恰好两个成员，编号分别且仅为 `644` 和 `642`；绑定值等于原文对应位置切片；编号证据位于各自成员范围。`644车间` 不计正确编号，空结果不计通过，`error=null` 也不代表通过。完整流程另核验实体/编号属性是否采信、计划端点、关系参与及时间、流程是否完成。

## 五轮结果及失败保留

| 轮次 | 新真实调用 | 验证内容与结果 |
|---|---:|---|
| 01 | 15 | 初版允许所有目录片段作为编号。明确并行例误把 `644车间`、`642车间` 当编号，最终属性也采信错误边界；斜杠句编号正确，但无计划/关系。失败保留。 |
| 02 | 16 | 区分编号候选与上下文后，两句均采信两个车间及纯编号。明确并行句关系与时间通过；斜杠句仍无正文计划和关系组。 |
| 03 | 1 | 当时关闭 Mock 后没有可选编号，Qwen 返回三个空数组，未产生绑定。属于质量失败，推动恢复原字段值的候选资格。 |
| 04 | 9 | 目录来源完善后的四项阶段矩阵：明确并行、斜杠句、无 Mock 三项绑定通过；强制目录缺项走通补充流程，但补充的是带称谓名称，编号边界失败。 |
| 05 | 3 | 补强通用编号/称谓示例后，仅补测强制缺项分支：先补充纯 `644`、`642`，再选择程序 ID，两个成员绑定通过。 |

第 02 轮明确并行例终态为：两生产区域 accepted；`areaIdentifier` 分别为 `644`、`642` 且 accepted；`producedInArea` 关系组为 `participation=all`、`timing=parallel`，参与和时间均 accepted，positive、无附加条件。流程完成，给定计划根的完整目标通过。斜杠句两个编号虽通过，但正文计划未发现、关系组为空，完整目标失败；本轮未改发现或精排，既有计划卡预算排除问题不属于片段协议修复。

第 04 轮 `no_mock` 只在指称阶段关闭来源查询，两编号仍正确，来源候选各为 0。第 04/05 轮 `missing_spans` 还通过测试夹具移除了进入指称阶段的预提取字段关联，以强制目录缺项；没有修改原文或线上数据。第 05 轮原始回答依次为：

1. `new_spans=[{source_id:"S1",text:"644",occurrence:0},{source_id:"S1",text:"642",occurrence:0}]`，另两个列表为空。
2. 两个 expression 分别引用程序分配的 `P3f6e06c7ffaa8be9634c4ec0`、`Pf404e3d1c69f45914c800dfc`，同一分组内两个成员。
3. 选择该分组，证据引用覆盖两成员的整句片段 ID。

最终修正采用通用 `A17号部件` 示例说明称谓不是编号单位，没有硬编码目标编号或车间规则。第五轮全部运行模块与当前工作区 AST 一致；协议文件仅有末次 Ruff 换行差异，不宣称字节一致。

第 04/05 轮均故意停止在 `entity_review` 前，实体状态仍为 candidate、`scope_complete=false`；这些结果证明指称绑定通过，不代表其后的属性或关系已核验。当前采用的四项阶段结果是第 04 轮前三项加第 05 轮缺项补测，不是单轮 4/4，也不是重复稳定性统计。第 02 轮完整流程发生在最终“原字段值候选及缺项提示”调整前，不冒充最终代码的完整流程重跑。
