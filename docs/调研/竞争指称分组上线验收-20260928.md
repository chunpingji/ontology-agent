## 实际接线

`文档上传 → 本体卡检索 → 发现与查询反馈 → 类型对齐 → 编号竞争分组 → 指称/类型核验 → 属性与关系组对齐 → 分项证据核验 → 当前图谱展示`。

- [referents.py](../../backend/app/services/document_harness/referents.py) 使用实际类型卡的身份属性，从可查询映射每次最多读取 50 条记录，把在当前原文中出现的键数组及完整键组定义注入模型。保留查询完整性与编号边界未核对状态；程序不拆斜杠，也不按键个数确认对象数。
- 同时支持整体编号和多个成员的竞争分组；选择完整分组后，成员 anchor、编号原值与来源候选绑定传给后续属性核验。原始字段继续保留，来源身份仍为 `not_checked`。
- 成员只引用 `expression_ids`，程序从已经校验的编号引文派生成员 anchor；不要求模型重复抄写成员范围，避免独立编号正确但整体 anchor 被重复绑定的问题。
- [relation_groups.py](../../backend/app/services/document_harness/relation_groups.py) 将备选、共同参与、参与未定与时间分开；选项组不展开为肯定边。相互冲突的已采信参与解释回到未决。
- [线上协议](../../backend/app/services/document_harness/protocols.py) 无生产区域类型或具体编号的硬编码；在线模块没有导入 `app.evaluation`。
- 图谱接口增加 `relation_groups`，页面关联关系中显示对象集合、参与状态、择一约束、时间状态及证据。共指投影保留原始成员引用。

本次接线默认启用于新建运行。没有改写既有运行；本次实际使用新运行验收。
