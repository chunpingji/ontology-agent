# CMCReport 结构摘要图谱识别实测报告

日期：2026-09-07。状态：四组预算内试验及独立评分均已结束，最后一组于 16:00:33 UTC 落盘；四组的全量抽取状态仍均为 `incomplete`，不是全文完成测试。

本实验评估[基于文档结构和摘要元数据的关系图谱识别方案](./基于文档结构和摘要元数据的关系图谱识别方案.md)的轻量原型：使用章节标题、分层摘要和本体词项匹配生成提示，调整原文窗口及抽取请求顺序，保持原有语义抽取和独立验证。

结论：本轮观察到更早出现实体、更多命中参考设备，但没有证明整篇关系图谱识别提速或准确率提高。四组都没有保留属性或关系；摘要准备成本为 951.26 秒，加入 GLiNER 后参考命中数未再增加。详见下方结果及[机器生成对比](./evaluations/cmc-23c872fb-20260907-02/comparison.md)。

## 3. 原型实际覆盖的方案范围

| 方案能力 | 本次实现及限制 |

| 结构、摘要及本体提示 | 读取真实节点及摘要，按本体标签、描述与标题／摘要的词项重叠评分；祖先提示按距离衰减。属于确定性词法规划，不是 LLM 语义规划。 |
| 合法类型和关系 | 提示从已有 schema 生成，不创建本体类型或关系事实；未知或明确失效的节点元数据被忽略。 |

| 保留剩余扫描 | 不按低分删除适用窗口和类别；但预算停止后仍有未执行工作，不能视为完整扫描。 |

| 冻结与恢复身份 | 规划指纹进入运行身份；尚未实现完整的分层增量缓存、渐进更新和生产降级流程。 |
| 生产集成 | 本次为独立评测包装，尚非完整正式 API 集成，也未实施自适应删减、主体线索规划或建议范围扩展。 |

## 4. 独立参考与质量口径

参考使用[第 3 版 assistant_silver](../backend/app/evaluation/fixtures/cmc_upload_23c872fb_reference.json)，由独立助手先阅读全部原文 IR 和本体，再建立参考，未以预测输出为标注依据。它没有经过 CMC 专家或人工复核，不能称为人工金标准。

参考总共含 14 个实体、31 个属性和 13 条关系，其中一个 CMCReport 根是外部指定元数据。主指标使用评测器的 `extracted_only`，排除此根，分母为 **57 项：13 个实体、31 个属性、13 条关系**。另含 15 项禁止断言和六个局部穷尽范围；范围外预测保留为未计分，不能自动判错。

应分别报告实体、属性和关系的局部精确率、参考召回率、F1、命中／漏检数量、未计分预测数量及其占比。属性和关系必须匹配主体、谓词、对象或规范值，以及相关证据；原文坐标可回放率另报，不能代替语义正确性。

固定预算下的全参考召回应命名为“预算内参考召回”或“早期覆盖”。未访问范围中的参考事实会形成未命中项，这反映发现顺序和完成程度，不等同于完整运行后的模型漏识别。精确率仅适用于声明的局部范围，单独一个百分比不能代表整篇图谱准确性。

参考中特别保留以下边界：

- 原文产品分子量 500.60 与设备残留物列的 500.18 冲突，只对产品结构节进行局部标注。
- NOAEL 数值缺少源文单位，移至两个不计分观察项，不要求模型按本体猜单位；PDE 的源文单位充分，继续计分。
- 计划生产、可选设备和条件性重结晶不能被解释成已执行事实；毒性表的 `—` 是研究资料不足，不是“否”。
- 禁止项零违反只说明生成候选没有触发所列陷阱；如果尚未访问相应区域，不能据此宣称已验证全部否定和条件处理能力。

完整标注规则见 [reference_notes.md](../backend/app/evaluation/fixtures/reference_notes.md)。

首结果和首关系时间指生产验证器通过的候选首次出现在快照中，排除外部指定文档根；这不等同于独立银标确认正确的首事实时间。当前未单独测量指定关系路径及其必要属性全部就绪的时间。

## 6. 正式实测结果

### 6.1 摘要准备：已完成

独立容器在 14:58:41 UTC 开始摘要，在 15:14:32 UTC 完成；实测墙钟时间 **951.256618 秒**，即约 15 分 51 秒。六批分别处理 20 页、4 页、5 个深层章节、18 个中层章节、8 个上层章节及文档根，耗时分别为 336.36、41.00、27.13、183.96、108.95、252.81 秒。

32 个章节树节点的来源为 `llm=31`、`extractive_fallback=1`；状态为 `completed=29`、`partial=2`、`failed=1`。两个部分状态节点是工艺及工艺描述（`section:51`、`section:52`），失败节点是文档根。页面层的完整来源分布未由冻结 02 保存，因此不能报告“56 个目标全部成功率”。

根摘要的两次调度记录均为 `model_output_truncated`，随后回退为原文摘录。摘要器允许两次尝试，这与正式抽取的单次尝试、零超时重试口径不同。期间曾观察到状态接口短暂超时，但不能将其直接归为根摘要失败原因。

冻结规划器没有排除 `partial` 或 `failed` 摘要，实际接纳全部 32 个节点，包含根摘录；这是本次真实输入，不是纯成功 LLM 摘要对照。提示仍不可作为事实证据，后续验证继续回查原文。

### 6.2 摘要内容风险：独立定性观察

`section:67` 的成功摘要写道：“滤饼在真空干燥箱（DE64603）中45~50℃干燥18~24小时，密封冷藏保存。”父节点 `section:51` 进一步写为“成品密封冷藏保存，有效期24个月。”

原文实际区分两个阶段：

| 阶段 | 原文 | evidence_id |
|---|---|---|
| 甩滤后、干燥前的滤饼暂存 | “所得滤饼称重，滤饼暂存于低密度聚乙烯袋中，密封冷藏保存。” | `259d5da935b24bfffec7df3a122651dd5cb9672c577a54d598f9b3459b44d393` |
| 干燥结束后的成品保存 | 包装后“密封，不超过25℃保存。” | `ecd195abdb4cc333d0740acdb6847c4ac5e29f90727ab310285afd6e60ef8d53` |
| 成品存放条件表 | “密封，双层聚乙烯薄膜袋，不超过25℃保存” | `622cb804a11629b61be543c3a3fff7b4560cba38ef5e13faee283be71b6fa88d` |

这不是说“冷藏”与“不超过 25℃”互斥，而是摘要把中间体暂存要求延伸到了成品，增强了原文未规定的约束。另一节点 `section:73` 则正确保留“不超过25℃保存”。因此 `llm/completed` 仅代表生成状态，不代表事实正确，摘要中的阶段条件也可能向父层传播。

该观察没有追加到冻结参考或本轮评分中，也不能据此认定最终图谱已经出现同样错误。

C、D 都命中了同样四个参考设备：两台反应釜、离心机、真空干燥箱；实体参考召回均为 4/13（30.77%），合并 31 个属性和 13 条关系后，总参考召回为 4/57（7.02%）。两组均有 2 个保留实体不计分，局部精确率不能外推到这些实体，更不能外推到尚未处理的全文。所有组属性、关系参考召回均为 0，精确率因无输出而未定义。

C/D 比 B 多出的参考命中来自真空干燥箱的精确类型匹配：B 已识别同一设备，但使用 `ElectricVacuumDryer`，参考要求 `VacuumDryer`。因此不能把这 1 项差异描述成新发现了 B 完全遗漏的物理设备，也不能在没有专家复核时仅据这一分数判定哪个类型更正确。

首结果时间只表示生产验证通过，不表示首个独立参考正确结果。C 与 B 的首批 31 个 target 相同、类菜单均有 136 个类；加入摘要后首请求输入由 18,545 增至 20,113 tokens。C 首调用前两个模型槽位均空闲，且存在前序运行的缓存影响；首调用耗时由 196.56 秒降至 106.21 秒不能单独归因于摘要。

尤其 D 在 187.99 秒首次保留的只是未评分“压滤器”；不能把此时间称为“更早找到正确参考设备”。C 首批已含 500L 反应釜和离心机。当前产物没有逐次快照的独立参考评分时间线，不补造首个参考正确结果时间。

C 的关系提案进入了四次绑定验证，但验证引用将原本只有“设备清洗方法”的 IR 单元补写成跨节点长句，全部触发 `source_excerpt_mismatch`。D 的关系提案同样存在跨单元拼接，并把 `purpose=subject_evidence / fact_eligible=false` 的已知对象证据当成当前关系事实引用，触发 `source_quote_outside_scope`。因此原文存在设备名不等于当前任务的关系证据合法；这些提案均没有进入最终关系候选。

### 6.4 摘要与 GLiNER 的成本

| 组 | 抽取（秒） | 单独摘要准备（秒） | 冷元数据核算合计（秒） |
|---|---:|---:|---:|
| A | 640.99 | 0 | 640.99 |
| B | 743.35 | 0 | 743.35 |
| C | 654.71 | 951.26 | 1,605.97 |
| D | 676.86 | 951.26 | 1,628.12 |

后两组合计约为 26 分 46 秒和 27 分 8 秒，仍只是本轮部分抽取成本，不是全文时间。摘要缓存命中后的首结果更早，不等于冷元数据场景也更快。

D 确实运行了本地 GLiNER：3 次批量调用，25 条通过原文偏移回放的 span 建议，推理计时共 5.38786 秒；5 次召回请求进入提示路径（关系请求的 GLiNER 建议可为空）。这些是片段建议，不是 25 个正确图谱实体。D 相比 C 未增加参考命中，总抽取墙钟增加约 22.15 秒；首实体结果略早，但不足以建立独立、稳定的 NER 增益。

原文偏移合法也不代表标签正确：GLiNER 提示曾把离心机编号 `CT64610` 标为 `VacuumDryer`、把“丙酮”标为 `Centrifuge`。这些均是 `validated_fact=false` 的建议，不能直接计成最终图谱错误，亦不能据此断言它们造成某个最终结果。D 最终还将 `PF64216或PF64616` 支持为“钛棒过滤器”的唯一实例标识，而另一“压滤器”候选的同一组合标识没有获得身份支持；这属于需复核的身份歧义风险，相关实体在本轮主评分中仍为未评分。

冻结 02 在构造变体前已加载 GLiNER，导致其 `gliner_load_wall_seconds` 字段近零，不能当作真实加载时间；实际加载已包含在 D 的外层 `planner_seconds_this_segment=36.33617` 秒和总耗时中。当前评测入口已修正此观测问题，本轮数据没有因此重跑或替换。

## 7. 判断与后续验证条件

| 问题 | 本次可支持的判断 |
|---|---|
| 环境能否真实运行？ | 可以；已完成真实摘要、四组预算运行、评分及来源回放，不是模拟模型输出。 |
| 能否更早提供实体？ | 本轮观察到首个验证实体时间从 A 的 640.84 秒变为 B/C/D 的 310.28/202.59/187.99 秒；内容、结果类型与共享负载不同，不能当成等质量因果加速倍数。 |
| 摘要是否改善早期参考覆盖？ | B 命中 3 个参考实体，C 命中 4 个，提示了继续试验的价值；单文档、单次、有缓存与预算超出差异，不能证明总体准确性提升。 |
| GLiNER 是否进一步提升？ | C、D 的参考命中、召回和 F1 相同，本轮未观察到额外参考质量收益。 |
| 能否更快、更准地完成关系图谱？ | 尚不能证明；四组均未完成全文，且没有保留属性或关系。 |

下一轮应优先定位表格引用和主体绑定失败：跨单元格证据应表示为多个真实来源引用，不把拼接句伪装为某一个单元中的原文；继续坚持原文回放检查，不能通过放宽引用合法性来增加关系数。另需对摘要中的阶段条件进行复核，并完善局部类型菜单规划；本轮仅排序和提示，没有减少必须处理的全量工作。

要给出全文速度及准确性的结论，需要：领域专家复核并补全实体、属性和关系金标；所有组完成相同全文范围；分开冷／热摘要条件；交替组别顺序并重复运行以控制共享负载与缓存；最后在可比质量下比较全量耗时。当前没有进行这些额外模型运行，也没有按预测结果修改参考集。
