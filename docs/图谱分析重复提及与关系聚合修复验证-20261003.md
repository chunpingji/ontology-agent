## 原因与修复

1. 原物理提及 ID 包含模型生成的 role。父窗口保存局部回答后拆窗重读，同一原文
   位置因角色措辞不同产生多个实体，随后扩大关系候选。现在 ID 只由文档哈希、
   source_id、start、end 决定；合并角色、候选类型、名称、字段及原文证据。
   不同位置、仅重叠位置和同名对象不直接合并，不提前采信类型。
2. 本地完整身份键的共指召回原先依赖外部映射。现在冻结本体明确声明的
   `owl:hasKey` 完整键组也可召回有界待核验工作，要求属性已解析、每组件单值且
   与逐字引用一致。缺少作用域组件或仅有 identity_key 标记不补成完整身份键。
   匹配只提出比较；仍须通过既有模型共指核验、两端原文证明、置信度和组内一致性门禁。
3. 共指投影原先只替换端点，界面仍逐条显示全部断言。现在树、画布和关系详情共享
   展示聚合：主体、对象、非空谓词、极性、完整条件列表和状态必须相同。
   所有原始断言、提及端点、理由、核验结果和证据保留，可展开查看。
   未对齐谓词、不同条件、否定或状态不同的关系继续分开；API 原始计数不变。

## 层级树同名关系目录补修

2026-10-03 对运行 `a12f6c56-f0f5-4aa0-8316-136ced39a7ba` 只读核查发现：
根节点下 41 条“使用设备”关系已有谓词，15 条同名关系尚未对齐。
原层级树以谓词 IRI 分组，空谓词则回退到每条候选的 ID，因而生成了 16 个同名目录。
此前的断言聚合只处理相同端点和语义，不解决这类导航目录重复。

本轮修改前端共享分组逻辑：

- 同一主体下，已对齐关系仍按谓词 IRI 分组；不同 IRI 即使同名也保持独立。
- 未对齐关系按原标签分组；若同一主体下只有一个同名的已对齐谓词，则共用该展示目录。
- 目录与成员显示待对齐标记；不向候选写入目录的谓词，不改变端点、证据、否定、条件或采信状态。
- 层级树、关系图及祖先路径展开共用分组结果，不跨主体归并，不凭相似名称匹配。

对同一份真实图谱响应进行修改前后纯展示计算：“使用设备”目录 **16 → 1**，
其中 **15 项待对齐**。根层 223 条展示关系以及全部 479 条展示关系及其原始断言均保持，
无后端写入、无模型调用。
