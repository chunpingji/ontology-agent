## 5. 质量判定与已知风险

自动化回归为 **287 passed、13 subtests passed**，另有 4 条已有依赖警告；相关改动 Ruff 通过。覆盖包括完整/非连续引用、重复子串拒绝、多段落 cell、合并行、单位/图例、根边到子属性、范围外错误主体拒绝、可靠身份归并和失效依赖闭包。这证明实现契约，不证明真实模型的语义准确性。

已确认 schema 中 DrugProduct 描述为 “A finished dosage form drug product that bears a clinical drug role.”。原文简介明确将 2025 年两次历史供样形式写为原料药，后接 2026 年本次临床备样计划，但没有在该句重新说明剂型；另有“制剂剂型：口服片剂”，毒理表格又以“活性成分(API)”列头标识 HRS-1597。不能因此断言没有制剂信息，也不能将 API、临床批次与成品制剂合为同一实例。

现有 `ActivePharmaceuticalIngredient` 是独立类，不是 DrugProduct 子类；`CMCReport.describes` 正式 range 仅 DrugProduct。但 describes 的注释包含 drug substance，drugSpecification 的注释也包含原料药，与 finished-form 类定义存在内部不一致。API 当前属性菜单仅有 OEL/PDE/productIdentifier，分子式、分子量、性状等在 DrugProduct 菜单；只扩大一条边的 range 仍不足以准确表达 API 属性。

更正：API 不在根的直接 range，并不意味着必须调整本体才能继续。现有 DrugProduct→hasActiveIngredient→API 已提供合法二跳路径；此前要求先补根到 API 关系或作语义选择的建议过度，已撤回。后续保持现有本体，先解决多章节实体召回和根关系验证，再验证 API 归属。两类对象的区别仍需遵守，但不是本次继续实验的前置授权障碍。CMCReport 的生产计划、合成路线、设备等独立直接关系也不依赖 describes，不能把它们的检索或抽取失败归因于该类型限制。

评测必须分别报告主参考 TP/FP/FN、正确根路径、子属性、多跳覆盖、未评分候选、拒答、路由阴性、待处理记录及引用/归并错误。语法合法、坐标可回放、生产验证 passed 和专家认可不是同一件事。即使所选记录队列耗尽，路由阴性仍不构成全文无遗漏证明。

原始输入、模型请求/响应、候选和图谱均可能含文档机密内容，归档应沿用原文的访问权限。隔离评测不写生产事实，但共享模型调度与用量记录仍会产生。

最后一次 API 检验暴露了相反方向的错误：call 52 已同时引用 Product 代码和 API 名称/列头，满足当前程序的“双端引用存在”检查，却以已建立的 describes 作为组成桥接。**双端各自有证据不等于两端之间的谓词得到证据支持。** 同份报告、同名及根可达性都不能推导 hasActiveIngredient。当前引用闭包保证来源和版本一致，未能排除此类语义假阳性；不能将通过的边改写为已被拒绝来美化结果。
