# 图谱分析阅读吞吐优化验证

日期：2026-10-02。对应运行 `c00892e7-8d56-4ae0-ba19-14c92e0fb87c` 的阅读吞吐问题。
本次修改在已有四阶段重构工作区上实施，不改变后续事实采信条件。

## 问题与实现

原运行前 18 次完成调用包含 12 次来源查询草稿、2 次普通发现、4 次来源反馈修订。
输入 294,254 token，输出 21,964 token，累计调用耗时 471.38 秒（并发调用相加）。
页面 2,426 的单位是原文字符，表示按原文去重的局部结果已保存范围，不是字节或最终事实覆盖。

旧实现的直接瓶颈：40 个原文片段先于 4,800 字符触发切窗；输出达到 12 个提及
即判为未完成，包括模型明确 complete=true 的结果；递归子窗重读与来源反馈修订
反复携带本体卡、阶段说明和展开 Schema。

本次实施：

- 初始片段上限提高至 192，字符目标仍为 4,800；长表格按完整物理行打包并保留表头。
  超预算单行沿用调用前拆分，不截断证据，不将同行视为同一对象。
- 发现输出容量提高为 48 个提及、64 个关系线索、合计 64 个补充原字段。
  明确 complete=true 且原文引用合法时，不因恰好达到数组上限再次拆窗。
- complete=false 可报告 read_through_source_id。程序将有效完整前缀坐标写入现有窗口行，
  只续读剩余主范围，必要表头、标题、主体上下文仍可引用但不能重复登记其中对象。
  已读前缀与完整叶窗口的覆盖合并去重。暂停后加载现有计划和已付费回答。
- 辅助来源、窗口末来源、同一物理段落的重叠切片不能用来越过未读范围。
  没有有效游标或原文引用失败时保留未完成状态，沿用有界拆分。
- 原文发现说明去除重复措辞；可读 Schema 使用共享定义与字段枚举，不重复展开
  相同字段结构；解码 Schema 继续严格约束。无语义作用的 title/default 元数据省去。
- 草稿只在 lookup_refinement_required=true 且存在查询时进入来源反馈修订。
  清楚的提及直接保存，来源匹配沿用后续语义阶段查询；不以来源匹配认定身份。

模型消息协议为 `document-harness-v8`，公开服务域仍为 `document-harness-v2`。
加载新代码后新建运行默认采用优化；旧协议运行不转换、不删除、不改变冻结策略。

## 真实模型抽样

使用原运行冻结原文、冻结本体与首批阅读卡，通过现有模型配置调用。
抽样为独立发现消息，不写原运行工作状态，不执行后续图谱对齐/事实核验，
不能当作整篇 precision/recall 验收；消息使用普通发现输入，不包含来源查询草稿。
调用产生现有调度/用量记录，不称为纯只读检查。

初次调用返回 38 个提及并声称完成，其中一条 anchor 将不连续编号与共享称谓拼接。
精确引用检查拒绝该结果的完整覆盖。随后补强连续引文提示，没有修补原答或放宽检查。
这次失败抽样实际消耗输入 31,263 token、输出 3,590 token、68.54 秒，不排除其成本。
