## 1. 原文发现：输出生成时间占主导，输入指引也很重

23 次成功调用平均 101.2 秒（调度账本的实际请求时间），累计生成 93926 个
输出 Token。每调用的输出 Token 数与耗时相关系数为 **0.9994**；简单线性拟合为
每输出 Token 约 0.024 秒、固定耗时约 3.6 秒。该运行的延迟主要随结构化回答
长度增长，仅缩减输入不应被直接等同于同比缩短耗时。现有账本没有首 Token 时间，
不能进一步分解上游预填充、网络和逐 Token 生成时间。

## 2. 类型对齐：目录分片和父子类比较放大了调用

本体快照有 343 张类型卡，根可达目录为 143 类。当前 345 个正文提及已有类型
输入哈希，但 96 个模型回答累计给出了 **1049 个提及类型判断**，约为 3.04 倍。
这是相同提及跨菜单分片及二次比较被多次判断，不意味着创建了 1049 个实体。

| 类型调用分组 | 调用数 | 累计耗时（秒） | 输入 Token | 输出 Token |
|---|---:|---:|---:|---:|
| 菜单恰好两类 | 65 | 621.959 | 411840 | 16339 |
| 其他菜单 | 31 | 1422.787 | 710598 | 55760 |

65 次两类比较中，依据本次冻结本体的父类链核对，**56 次属于父子类组合**，
合计 **565.812 秒**。例如设备/反应器、设备/离心机、工艺物料/溶剂。
父类菜单和子类菜单分别产生有依据的候选后，当前代码会将它们当作多个候选，
再请求模型比较。真正存在角色竞争的菜单仍必须独立核对，不能仅按父子关系或
自报置信度直接选子类。

可核对的调用链：

1. [controller.py](../backend/app/services/document_harness/controller.py) 的
   `type_alignment` 首先尝试全部可达类型；超过预算后按指引/其余类型分片，必要时再分片。
2. 同一提及在多片中获得候选后，再按候选菜单分组执行 `compare=True`。
3. [planning.py](../backend/app/services/document_harness/planning.py) 的
   `context_window` 从完整的 `base_window.sources` 和 `base_window.fields` 开始，
   只做补全，不因选中少量提及而收窄上下文。

因此，即使一批只判断 1–5 个提及、两个类型，也会携带完整窗口的来源。
两类比较仍包含 20–82 条来源；96 次类型请求共发送原文文本 201869 字符，
其中两类比较发送 142307 字符。类型请求的可读输入中，来源占 33.5%，
类型卡占 31.2%，实体和字段占 24.2%，可读 Schema 占 10.8%。

这解释了为什么已经用原文发现提出候选类型后，类型对齐仍需约 2045 秒：
后续在完整目录上重新分片判断、重复生成带理由和引文的回答，再做小菜单比较。

## 优化建议及验证口径

以下是建议，不表示已实施或已验证加速幅度。

1. **先保护语义完整性，再按语义边界拆分与语境路由减少重复处理。** 片内实体筛选和
   属性／关系的任务上下文筛选已经存在；类型小批次仍携带完整阅读片。收窄这部分输入前，
   应明确子片所需的主体、完整字段、表头、条件、步骤及回指原文，避免长度裁剪丢失语义。
   具体见[语义分片与语境路由设计](图谱分析语义分片与语境路由设计-20261004.md)。
   同时评估让竞争类型在一次判断中共同出现，减少父类/子类在不同菜单分别获选后再比较；
   父子关系只能辅助组织目录，不能替代原文类型证明。新增边界分析与路由的成本也须计入评测。
2. **压缩模型回答及重复输入结构。** 可以评估内部类型别名、共享定义和更短的理由，
   由程序还原权威 IRI 与证据；发现阶段仅保留完成原文发现所需的指引。
   本次耗时与输出长度高度相关，应同时减少重复输出，而不只压缩输入。
3. **减轻最新展示缓存的同步全量重建。** 优先复用已加载的当前业务状态、按变更键维护
   现有展示缓存，避免每批全量读取、deepcopy 和哈希大对象。保持一份权威工作状态和
   一份最新展示缓存，不新增历史快照或另一套恢复状态。
4. **再评估阶段内独立批次的有限并行。** 保持阶段顺序及依赖约束；并行主要减少实际
   经过时间，不减少累计调用时间、Token 或重复语义工作，不应替代前面三项。

验证应固定同一文档、本体、模型与策略，新建运行，分别对比实际经过时间、各阶段
累计耗时、类型调用数、提及判断次数和 Token；同时核对阅读覆盖、提及/字段/关系
召回以及原文证据、否定和条件。不能以缩小候选范围或漏读来达成表面加速。

本次完成的是线上账本分析、请求结构统计和当前暂停状态的只读性能测量。未修改业务
代码，未暂停/继续运行，未重启服务，未执行新的真实模型评测。
