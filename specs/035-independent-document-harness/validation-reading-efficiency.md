# 阅读效率修正与真实 GPT 实测

日期：2026-10-01。对应 RE-FR-001—006。本文区分工程回归、真实阅读实测及部署生效检查，不把候选提及当作已核验事实。

## 已实施的行为

1. `Window.payload()` 明确 `reading_scope`。实体锚点必须完整属于主区间；辅助来源仍可作为证据和回指先行对象，不能重复登记其实体、文档根字段或无归属字段。预提取的独立字段也按原文值范围过滤。
2. `freeze_catalog()` 在引擎的现有锁内复用按根类型编译的目录。本体修改、重新加载、恢复 World 和关闭时清空缓存；不跳过来源映射版本核对，不新增持久快照。
3. 多张阅读卡共享完全相同的关系和身份属性定义，保留 `class_iris` 适用范围、身份键组、作用域和注解。关系范围保留原始并集、交集、限制表达式；合法性校验继续使用完整目录。实际共享体积参与预算，卡片数量上限仍为 8。
4. 来源查询无候选时直接登记草稿，并分别保存未命中、不完整或映射变更结果。有候选但无需改动原文发现时，`replacement=null`，只返回来源建议；确需修正才返回完整替换。原字段保留，保留字段不重复占用当前回答容量。
5. `processed_characters` 统计有局部结果的主区间；`complete_characters` 只统计确认完整的叶窗口，两者按原文区间去重。前端同时显示“原文范围已处理”和“完整覆盖”，说明二者口径。

新模型协议为 `document-harness-v6`，卡排序协议为 `harness-card-ranking-v2`。默认仍为两窗口并行。旧运行不转换；旧阅读响应缺少新计数时返回 `HARNESS_NEW_RUN_REQUIRED`，避免产生 HTTP 500 或伪造新口径进度。

结论：固定输入的阅读覆盖推进和调用利用率显著改善；仍存在容量触发拆分、定位歧义和模型接口长尾。
上表覆盖范围不同，不能把总 token 差额当作同等完整任务的成本降幅；没有独立金标，不宣称事实质量不变或完整图谱固定倍数提速。
