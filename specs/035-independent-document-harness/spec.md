# 独立的原文驱动图谱 Harness

## 目标与范围

用户于 2026-09-21 要求彻底隔离原文档分析引擎，按已确认设计重新实现整个
harness 及各阶段协议，不使用旧协议。新建文档图谱运行默认启用本特性。
原件、物理文档结构、鉴权、运行控制和本地模型基础设施可复用；旧识别引擎、
候选/核验/执行卡/恢复协议不得作为新流程的依赖或中间转换格式。

## 已澄清的设计意图

2026-09-28 用户授权接入已映射 Mock 查询的最小发现反馈：发现草案可请求一次有界本地查询，
返回后再输出完整发现结果并登记。原文、本体、来源数据分开解释；来源候选不证明身份或生产关系。
沿用当前状态与模型账本，暂停继续复用已保存输入/回答。细节及本轮范围见
[036 规范](../036-mapped-entity-query/spec.md)，正式来源身份核验和全图质量验收不包含在本轮可行性试验中。

- 原文驱动发现：围绕真实指称共同阅读字段，先保存实体提及、原字段和关系线索。
  发现不要求实体已经通过完整本体类型证明，不以实体未采信阻断其他原文的阅读。
- 发现前按原文召回当前可达类型卡，在最终截断前统一补入命名父类；按距离衰减的
  层级支持和属性/上位层级覆盖重排，优先避免遗漏宽泛类型，不指定领域名称或 IRI。
  阅读卡仅引导对象构造，排序分数不是类型或事实证据；类型对齐保留未入选类型的检查。
- 同一阅读范围的原文来源权限一致；不得让主体名称可见却不可用于提及。
  标题和表头可帮助解释归属，但共同阅读不证明同一身份。
- 本体对齐阶段才选择当前卡片合法类型/属性/关系 IRI；无法匹配的字段保留观察。
  原文关系标签是线索，不是任意生成的新本体谓词。
- 合法但尚未核验的关系为虚线；原文证据核对通过的关系才为实线。
  核对结合两端原字段、谓词标签与定义、方向、角色、极性和条件。
  不要求一个句子包含完整三元组，不要求先通过属性 SHACL 才能核对关系。
- 名称不推导全局唯一身份；不按同名合并角色、阶段或不同物理提及。
  N/A 等原文缺失标记保留为缺失观察，不补造值或将未知解释为否定。
- 保留未采信候选、逐项原文和理由；调用有进展、候选有产出和事实已采信分别计数。
- 每次模型输出上限为 16384 token；按输入/输出预算进行有界分批。
  全文未读完或批次输出不完整时，不声称全文完整度或最终准确率达标。
- 模型响应流在终态前中断（`model_stream_incomplete`）或模型请求失败
  （`model_request_failed`）时，当前阶段最多自动尝试三次；
  每次尝试计入调用次数和耗时，暂停后不再发起下一次请求。已保存的完整回答直接复用。
- 只需要暂停和继续，不支持历史回退；一个当前恢复入口、一份分区权威状态、
  一份最新展示缓存，模型请求/回答与成本独立保存。GET 不启动模型任务。

## 验收场景

1. 名称与多个字段同节出现时，输入保留主体依据和字段；候选以真实指称组织，
   不为每个字段制造实体。没有类型依据也能保留可定位提及。
2. 同名但不同角色的提及保持独立；合法谓词不跨主体卡借用；无匹配字段可观察。
3. 引文必须精确定位原文；空、错位、歧义和跨范围引文不能成为采信证据。
4. 关系候选在核验前已保存并可见，不因端点类型未采信而消失；类型或关系缺证
   保持未决。关系采信需端点语义与原文归属成立。
5. 发现、类型对齐、实体核对、属性/关系对齐、证据核对各有独立输入输出契约，
   当前输出 Schema 同时用于模型阅读与解码约束，不使用旧协议。
6. 暂停后继续使用当前状态和已保存回答，不重复消费或重发已保存模型调用。
   新运行不调用旧 worker；旧运行不转换成新协议恢复。
7. 新界面显示候选、事实、来源、未采信原因和阶段成本；刷新纯只读。
8. 新运行实测报告首个有效提及、首条合法关系候选、逐项来源及阶段成本；
   工程通过与真实模型产出分开报告，不把有限截面当作全文质量评测。
9. 表格实体可直接选择已有物理来源定位，无需重复抄写名称；同名异行、合并单元格、
   同格多段和局部指称保留真实位置，行上下文不自动证明单一主体或实体关系。
   每个实体必须提供有效定位；登记失败不能因模型声明完成而静默漏计。

## 原文观察与端点确认解耦（2026-09-22）

用户要求基于已部署实测中的生产计划与批量范围案例验证二跳及更深实体。
澄清：跳数按文档根到实体的关系边数计算；报告→计划为一跳，计划→车间为二跳。
本次规则适用于任意深度，不把一跳计划的结果冒充二跳以上验证。

- 原文发现先保存段落中的字段标签、完整原值、精确引用和候选主体关联；即使主体
  无类型、未确认或被拒绝，观察仍可读取。候选主体关联不是实体身份或属性事实。
- 无专有名称的具体计划、步骤或记录可以用原文指称定位。显示标签和角色名称
  不得被核验器误当作原文专有名称；仍须核对其具体存在、类型及限定。
- 确认主体类型后，原文范围可按当前属性定义分别映射下限、上限等合法属性。
  保留完整原值、单位和同一来源，不凭 IRI 后缀推断语义，不填造值或隐式换算。
  同一字段的不同范围组件不能同时写入同一个谓词；冲突时保留完整观察和理由。
- 属性观察、主体类型确认和入边/出边关系确认相互独立。缺少已采信关系路径
  不阻止保存观察或核验主体已有属性；属性采信仍要求主体与原文语义成立。
- 暂停继续及后续窗口确认主体后，复用已保存观察进入属性对齐，不丢失、不重复创建。

验收：真实原文保存 `批量3.8- 6.6kg` 及候选计划，确认后分别核验 3.8、6.6；
用真实文档中的二跳以上对象及通用反例检验路径不构成采信门，报告各自达到的深度。

## 根节点与无显式标签的原文观察（2026-09-22）

独立文本可以结合上下文提出属性候选，不要求原文采用“字段名：值”的形式。
发现输入始终提供用户选定根类型的合法属性语义；新增 `document_source_fields`
保存未被预解析为字段的根节点原文。字段标签允许为 null，值仍须精确引用。
“密级”等属性名称来自随后当前合法 IRI 的语义对齐，不能伪装成原文标签。
原文观察、归属与属性语义继续独立核对，不凭报告类型或空白签署栏补造属性。
文件元数据与正文证据不同；本次独立文本修复不把文件哈希、登记版本等伪装成正文引文。

## 属性值边界与核验职责（2026-09-22）

- 完整原文带有字段标签是合法观察，不因此拒绝属性或阻断后续探索。
  属性对齐可以根据当前属性定义选择原值中的精确连续区间，完整观察与来源继续保留。
  禁止借用同窗口其他字段的值、伪造引文或按领域前缀自动清洗；单位、否定和限定词
  是否可省略由属性含义及证据核验决定。范围上下限仍沿已确认主体的现有派生规则。
- 用户选定的根类型是本次任务前提，与原文核验确认的正文实体类型明确区分。
  属性/关系核验沿用主体的当前类型状态，只核对本项原文、语义、归属及方向等条件，
  不要求局部封面再次证明完整文档类型。实体指称与类型继续由实体核验负责。
- 有原文依据的类型疑点单独保留并指向相关主体，交由类型处理；不得在属性核验中
  暗改主体类型。程序不把模型拒绝强制改成采信，也不放宽未确认端点或引用检查。

验收：编号原文与取值分别保存并定位；错误/跨字段/缺失值引用不能产生事实；
真实封面及移除密级行对照中不因根类型重判拒绝标题，章节标题等归属反例仍可拒绝。

## 原文观察的本体上下文展示（2026-09-22）

用户要求按观察类别、主体、本体卡和属性映射解释大量原文观察。

- 展示改为“原文观察与对齐结果”，观察保留不等于未采信；已采信属性仍关联原字段。
- 区分原字段、实体提及、关系线索、范围提示和校验异常，模型调用失败单独展示。
- 每项展示候选主体及其类型、状态；实际发现参考卡与属性对齐所用类型卡分别展示。
  阅读窗口可以参考多卡；文档根的属性指引单独注明，参考卡不能被当成已确认类型。
- 属性显示名称、完整 IRI、所属命名空间、定义域及当前采信状态和理由，区别主体
  类型卡与属性定义来源。定义域保留并/交集语义，不将继承属性误标为子类独有属性。
- 同一字段在不同主体、类型卡和属性菜单下的对齐理由不得互相覆盖。已采信映射和
  其他菜单未匹配可同时展示；缺失关联时明确未记录，不凭相似词或当前类型推造。
- 提供类别、主体和处理结果筛选以及折叠详情；筛选与展开仅读取当前结果，不触发模型。

验收：同一原字段在报告卡未匹配、在中间体卡成功时，同时显示各自主体、卡和结果；
跨本体继承属性显示实际谓词命名空间与定义域；多映射、未定主体、无卡、引用失败和
调用失败不伪装为已采信或全文否定。GET 不写状态、不启动识别。

## 图谱分析 V2（2026-09-22）

依据 `design.pen` 的「图谱分析」Frame 实现现有独立 Harness 结果页面：

- 头部按确认截图显示标题与简短说明，右侧为「返回文档分析」「刷新结果」；当前文档卡
  显示文件名、任务根类型、真实阅读范围状态和运行状态。更新时间指页面成功读取结果的
  时间，不伪造服务端更新时间或将真实数据标为「示例数据」。返回保留文档及当前运行，
  已有运行的结果页不重复显示应用分析标题、顶层 Tab 和报告选择表单；暂停/继续仍可用。
- 「实体图谱与属性」「各阶段模型成本」「原文观察与对齐结果」采用三个 Tab，默认
  显示实体图谱；每次仅显示一个分区。切换保留实体选择、展开和筛选/分页状态，不产生
  模型调用。实体查看观察、观察定位主体时自动切换到对应 Tab。
- 默认选中文档根；层级树与关系图共享实体选择，右侧联动实体属性、关系、观察和本体目标。
  根按 `role=document_root` 识别，不用数组首项冒充文档根。按正向、非拒绝、肯定且无条件
  的关系计算最短展示层级；候选关系保持虚线，多父和环路以引用保留，不重复展开子树。
  否定、条件、拒绝关系继续可查但不建立无条件根路径。未连接实体单列，不补造连边。
- 支持实体/属性搜索、实体状态筛选、展开层级和逐项展开。搜索保留匹配节点的祖先路径。
- 层级树在同一父实体下按谓词 IRI 合并关系分组（如“使用物料”），支持分组展开/折叠；
  各对象保留独立的关系状态与实体选择，分组不增加实体距文档根的层级。
- 关系图采用相同的父实体和谓词 IRI 分组；默认显示谓词分组节点，用户展开后再显示全部
  对象及各自关系线，实线/虚线、状态和限定信息仍按单条关系保留。
- 关系图在桌面宽度采用左右布局，左侧为可展开图谱，右侧为当前节点属性面板；点击实体
  节点立即更新右侧的属性、关系、观察和原文依据，窄屏按图谱在上、详情在下排列。
  未记录的类型卡不可从实体当前类型倒推；完整原值、属性取值引用和声明依据分别展示。
- 阶段成本默认展开，显示实际调用次数、累计请求耗时、输入/输出 Token 和耗时占比。
  缺失用量仍为未知；不推算金额或识别完整度。
- 观察列表提供类别、主体、处理结果、文本筛选及分页。展开详情保存每个主体/卡/菜单
  的独立结果，显示发现参考卡、实际对齐卡、谓词 IRI、命名空间、定义域和采信原因。
  调用失败单独显示；从观察可定位主体与精确原文。默认显示全部观察，主体联动由用户选择。
- 沿用当前运行鉴权、暂停/继续、读取接口；页面浏览不产生模型调用。
  本次只改展示，不新增数据库、模型阶段或公共 API，也不修改事实采信。

验收包含多跳、多父、环路、未连接实体、根不在数组首项、缺失 Token 与实测零值、
同字段多主体映射及分页筛选；浏览器验证使用隔离模拟运行，不启动真实模型。

## 非目标

不修改权威本体，不新增领域词/IRI特判，不引入云端依赖、跨文档全局身份合并、
业务事实自动提交、历史回放或旧运行转换层。模板抽取是独立执行域。

## 文档内跨章节共指（2026-09-23）

用户明确要求实现跨章节共指的最小版本并实测，以下扩展替代原先完全不做身份归并的范围。

已澄清：只判断同一次文档分析中不同原文提及是否指同一对象，不建立全局实例身份。
全文提及核验后默认执行；名称、相似属性、共同阅读或图连通都不能独立证明共指。
类型相同或具有父子关系的已确认提及进入候选比较；类型未确认及不兼容者不自动归并。
同章节候选也参与核对，以免跨章节归并间接跳过组内冲突。

- 每对输出同一、不同或未决，保留两端引用、决定性原文、依据类别及理由。
- 同一需要明确简称/别名、有效范围内确属该对象的身份编号、或唯一明确的回指；
  区分原料、产品、批次、阶段、条件和编号归属。证据不足保持未决。
- 只有组内每对都确认同一才形成一个文档内实体；存在不同、未决或缺失判定的
  传递链不归并，不用传递性绕过冲突。
- 原文提及及属性/关系证据不改写。展示合并实体及其各处提及，属性/关系继续保留
  原始提及端点、取值、极性和条件，不因归并自动产生新事实。
- 界面可查看同一/不同/未决及原文理由。刷新不调用模型，暂停后从当前进度继续。

验收：跨章节简称、相同有效编号和明确回指正例；同名异批、只有名称和相似性、
错误引用、类型不兼容、三节点矛盾链反例；归并后来源及条件保留；暂停继续；
真实模型新运行报告固定输入、逐项结果、调用成本和未完成项，不外推全文准确率。

## 本体标识引导的多实体编号识别（2026-09-23 需求纠正）

原运行将 `611/642/646车间` 登记为一个生产区域，该原文实际指三个车间。
用户明确否定将具体领域词和编号样例写入通用提示词的做法，要求调研如何利用本体 ID 标识
引导模型区分对象。上一版以 `name_parts` 和领域样例实现的方案不再作为目标设计。

- 具体类型、标识属性、适用范围与身份声明来自冻结本体，编号值和对象归属来自原文。
  不按 IRI 后缀、固定词表、数字个数或分隔符机械拆分；案例只作为验证资料。
- 区分多个对象各自的编号、一个对象的多个编号和复合键组成；独立成员须能逐项定位。
  本体缺少标识属性时保留原字段，不借用其他类型的属性或生成未声明谓词。
- 局部提及、编号属性与全局身份分开核对；不将身份标记等同全局唯一性，不因编号不同
  自动宣称对象不同，不因编号相同自动归并。
- 字段和关系分别核验，不复制集合总量，保留备选、否定与条件。旧运行不通过展示拆点修补。

调研与验收依据见
[本体身份标识引导调研](../../docs/调研/本体身份标识引导多实体编号识别调研-20260923.md)。
2026-09-23 用户进一步授权补充生产区域编号及身份注解、将身份属性/键组送入阅读卡、
验证指称与编号对应、评估工具辅助，并独立核对数量、属性与身份。
