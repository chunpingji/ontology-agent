# 文档识别模型上下文压缩

日期：2026-09-19。状态：已实现、验证并部署。承接 027/028/029 模型工具协议。

## 需求与澄清

用户要求依次优化提及工具结果、局部短引用、回答 Schema、本体卡片及重复原文读取，
并将单工具结果上限提高到 8192 tokens。默认开启，不新增历史快照、外部依赖或兼容分支。
压缩不能改变识别范围、原文内容、证据权限或成立条件。

## 验收

1. 同一物理提及共享定位和文本，各角色、类型、属性和分数无损保留。
   完整工具结果按模型视图计量，上限 8192 tokens；超限不返回半截数据或授予引用。
2. 模型使用当前请求的短引用；服务端保留完整身份，在处理回答和工具参数前还原。
   未登记引用、碰撞及跨成员借用不能获得授权；原文和新建局部编号不被误替换。
3. 回答 Schema 不重复发送；禁用输出不携带不可达定义，禁止数组仍必须为空。
4. 核验卡片保留相关冻结目标、依赖和约束；发现阶段不缩小合法候选范围。
   同 IRI 不同约束不合并；已完整提供的原文不再通过重复读取工具再次请求。
5. 调用计量、请求哈希、实际发送、暂停继续一致；已付费结果不重复执行。
6. 用当前本地分词器比较固定请求的 tokens，工程验证与真实模型验证分别报告。

## 实现边界

- `MentionData` 的权威结果不变，模型投影使用 `units[].mentions[].roles[]` 共享重复字段。
- 模型登记引用使用 `@r:<完整哈希前12位>`；当前请求内检查碰撞、未知引用和成员权限。
  映射从规范请求重建，不保存第二份身份状态。新候选 `local_id` 使用独立编号。
  模型回答的 `local_id` 仅使用字母、数字、下划线或连字符（如 `e1`、`p1`），
  避免与登记引用混淆；该生成约束不改服务端领域契约。
- 容量计量、请求哈希与实际发送共用一次投影。响应先还原再消费；非法引用的已付费
  原始响应仍落原账本，通过 `reference_error` 标记为不可消费，继续时拒绝而不重复调用。
- 核验只裁掉可确定不相关的类型/属性；实体目标保留对应类型全部约束，主体类型不明时
  不裁剪。完全相同的属性定义才共享，不把同 IRI 的不同约束合并。
- 已完整注入授权原文的模型轮次隐藏 `inspect_evidence`；服务端原文读取和证据权限不变。
- 输出 Schema 只通过 `text.format.schema` 发送；提示词保留简短字段含义，区分有原文
  依据的属性候选与未决观察，避免把格式约束误当作充分的语义指引。
