# 统一属性数量配置

2026-09-13：用户要求数据属性和对象属性统一支持未指定、单值、多值及最小/最大数量，贯通编辑保存、TTL 发布/重载与识别快照。

## 需求与澄清

- 两类属性统一提供 `multiplicity: unspecified | single | multiple`、可空非负整数 `min_cardinality`、`max_cardinality`。
- `unspecified` 表示未声明取值策略，不能当成明确多值；已有独立数字约束仍须保留并生效。
- `single` 表示最多一个值，最大数量规范化为 1；最小数量默认空，不隐含必填。显式最大数量非 1 或最小数量大于 1 拒绝。
- `multiple` 表示允许多个值，不要求至少两个；最大数量为空表示未设置上限，填写时须至少 2。最小数量可以为空、0、1 或更大；所有模式均拒绝最小数量大于最大数量。
- 空最小数量表示未声明最小约束，0 表示显式允许缺省；不得伪造缺失事实。更新遗漏字段保留原值，显式 null 清空数量限制。单值转换到其他模式时前端提交新数量配置，不能留下隐式旧上限。
- 对数字基数发布 OWL 类约束需要明确所属类；只有全局单值标记可以没有定义域。保留已有 `is_functional` API 兼容性，但不得与新策略冲突或被无关编辑清空。
- 现有 functional 标记可识别为单值；未声明 functional 不推定明确多值。支持读取类及祖先类对当前属性的简单 min/max/exactly 约束；限定类型的 qualified 约束不能误当全部值的上限。
- 本次只补数量配置和快照传播，不实施自动停止搜索、人工审核重识别或更改具体业务属性的权威定义，不部署/迁移在线数据库。

## 保存、发布与恢复契约

- 数据属性与关系 CRUD 保留现有权限、expected_version 和审计，返回以上三个字段。
- TTL 使用版本化可识别的工作台注解保存声明策略及数量；single 另发布 owl:FunctionalProperty，数量发布所属类的 owl:minCardinality/owl:maxCardinality 约束。多值不发布最小 2。
- 仅更新明确由该数量配置拥有的限制节点；删除/清空配置不得残留旧限制，也不得移除外部公理、属性链、union、SWRL 和其他类级约束。三元组 diff 必须反映实际数量公理变化。
- 新库由 TTL 播种恢复策略、数量和 functional；现有编辑草稿不能被启动播种覆盖。旧数据属性此前不存在数量字段，可以仅对迁移标记为尚未初始化的新字段从 TTL 初始化一次，不改变原有标签、类型、定义域、状态或版本；之后显式清空不得被再次播种恢复。发布后的内存本体和重新加载本体给出相同数量语义。
- 识别 `PredicateSpec` 同时冻结 `multiplicity`、`min_count`、`max_count`；继承约束合并取最严格的上下限，矛盾必须显式报告而不静默放宽。新字段参与新快照身份；不改写旧运行的已存快照。

## 验收

1. 单值可缺省、单值必填、多值无上限、多值有限上限、未指定均能保存重读、编辑和清空。
2. 两类属性的非法组合、负数、非整数、版本冲突被拒绝；无关修改不重置属性特性。
3. 元数据 → TTL diff/发布 → 新库播种 → 本体加载 → 识别快照的数量语义一致。
4. 修改/清空数量约束时保留未建模本体结构；验证类继承、外部 functional 与基数、qualified 限制的边界。
5. 定向 API、迁移、TTL/引擎/快照测试及前端类型/静态检查通过；未执行的生产迁移或真实模型评测不得报告为通过。
