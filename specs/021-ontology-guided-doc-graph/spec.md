# Feature Specification: 本体指引的文档结构与摘要关系图谱识别

**Feature Branch**: `021-ontology-guided-doc-graph`

**Created**: 2026-09-08

**Status**: 工程主体已实现并完成本地回归；发布、旧数据物理清理和正式切换仍受本规范所列门禁约束

**Input**: 用户要求基于 Spec Kit 实现 `docs/基于本体指引的文档结构和摘要元数据的关系图谱识别方案.md`。

## Clarifications

### Session 2026-09-08

- **唯一入口与直接替换**：本次范围内只有一套新的 Word 文档分析实现，不保留旧同步协议、旧 Word runner、旧断点恢复、新旧算法开关、双读、双写、灰度或软件回滚。分任务开发不等于并行上线两套实现。
- **显式根类型**：用户必须在启动前选择合法的 `root_class_iri`。选择文件不启动分析；缺失、无效或不符合根类型政策时拒绝启动，不从全文猜测或回退自动分类。用户指定根只作为运行种子，不计为抽取成功。
- **分析产物边界**：同一运行产出“分层元数据”和“关系图谱”两个且仅两个并列结果视图。系统验证通过的图仍是分析产物，不等于专家确认，不自动进入审核中心、共享候选库或业务事实库。
- **摘要权限**：标题、章节结构和摘要可以定位与排序原文，但不是事实来源，不能确认实体、身份、属性归属或关系。当前运行在识别开始前冻结元数据快照；晚到摘要只可用于新运行。
- **默认识别范围**：在线工具默认识别文档根的全部直接本体谓词并递归展开有效对象；`focus_path` 只用于隔离评测和诊断，不能成为线上漏检分支。
- **经批准的有限 CMC 本体扩展**：用户已批准在权威 CMC 本体中补充 `producesFinalProduct`、`intermediateIdentifier` 和可推导的 `hasProcessIntermediate`，并继续用 `stepOrder`/`nextStep` 表达工艺顺序。该批准只覆盖本规范 FR-087—FR-092 所列语义，不授权新增 `CMCReport→API` 直连、从共现补造关系或修改其他本体来提升评测结果。
- **旧数据语义**：旧在线 Word 识别结果、候选、断点和缓存不导入、不展示、不恢复；09 等冻结实验、报告、输入和夹具作为离线研发证据保留，新运行不得从其预测结果预种候选。
- **Constitution III 治理门禁**：当前宪章禁止物理删除或就地篡改已发布内容。因此，仅未发布且经归属核验为旧 Word 域独占的运行数据可在清理清单核准后物理删除。已确认、已提交、已发布或被其他产物引用的旧断言、快照和物化事实，必须先以追加式撤销、失效、隔离或保留墓碑的方式退出在线消费并保留历史；若仍要求物理删除，必须先完成宪章修订或正式治理决定。本门禁未满足时，不得把物理删除或正式切换标记完成。
- **既有特性覆盖关系**：
  - 复用 018 的确定性 Word IR、章节树、分页、摘要和原文定位能力；本特性明确替换 018 FR-024/025/033/034/036 中“选文件即请求”“只存页面内存”“`POST /api/document-analysis/word` 同步返回”“请求后删除源文件”“文档工具不产图”的要求。018 FR-017 的摘要“不得成为事实”边界保留，并扩展为只可参与检索规划；018 的解析、树、分页、定位和其他调用方兼容要求继续有效。
  - 复用 017 的 Word 结构、记录和声明式能力，但本特性替换“显式类型无效时回退自动分类”、旧 Word 图谱运行路径，以及 FR-019 对被替换 Word 分支的兼容要求；除 FR-087—FR-092 经用户批准的有限 CMC 权威本体扩展外，不增加文档专用 IRI 分支、不改动其他本体，也不恢复模板专用 finder。017 FR-019 对 Excel、数据库、API 和声明式其他业务的保护边界继续有效。
  - 复用 019 的 DocumentIR、精确引用、本体菜单、受控模型执行和证据类型；本工具不接 019 FR-013—FR-021 的旧作业 CandidateStore、审核、事实提交、发布快照、业务 coverage 或报告消费路径。019 的这些能力继续服务其原业务，不因本特性删除；本工具只保存独立运行级分析产物。
- **质量与发布**：工程测试、模型桩、图连通或“全部拒绝”都不能代替独立语义质量。没有冻结的独立人工标注包、经批准的质量门和真实保留集结果时，可以继续开发，但不得清理旧在线数据或开放正式新入口。

## User Scenarios & Testing

### User Story 1 - 显式启动并回看同一次文档分析 (Priority: P1)

作为文档分析人员，我希望上传 Word、明确选择本体类型并显式开始一次可持久回看的分析，以便结构元数据先可用、关系图谱随后增量出现，而刷新或离开页面不会丢失运行。

**Why this priority**: 稳定的源文件、用户确认类型和运行身份是后台识别、证据回放以及两个结果视图一致性的共同前提。

**Independent Test**: 选择文件但不启动，确认没有分析或模型活动；再选择合法类型并启动，刷新后以运行标识回到同一元数据和图谱水位。

**Acceptance Scenarios**:

1. **Given** 只选择了 Word 文件或只选择了本体类型，**When** 用户尚未点击“开始分析”，**Then** 系统不上传、不解析、不生成摘要、不调用识别模型，也不创建运行。
2. **Given** 文件和合法根类型均已选择，**When** 用户开始分析，**Then** 系统创建唯一的后台运行，冻结文件、类型和本体身份，并返回可查询的运行标识。
3. **Given** 结构解析已完成而图谱仍在运行，**When** 用户查看结果，**Then** 分层元数据立即可读，图谱显示当前完整水位和真实进度，不阻塞整个页面。
4. **Given** 一个已提交运行，**When** 用户更换文件或类型，**Then** 原运行身份不变；只有再次显式开始才创建新运行，且不会隐式取消旧运行。
5. **Given** 页面刷新、事件流重连或结果视图切换，**When** 服务端状态未变，**Then** 系统只读取既有运行，不重复解析、摘要或模型识别。

### User Story 2 - 按本体直接菜单完整而公平地识别多跳图谱 (Priority: P1)

作为分析人员，我希望系统只在当前主体的合法本体菜单内寻找实体、属性和关系，并在一条关系得到独立支持后才展开对象的下一跳，同时不会因为某章节拒绝或低路由分数而遗漏其他记录和根分支。

**Why this priority**: 该路径决定系统是在本体约束下识别真实关系，还是通过预展开类型、摘要暗示和早停制造看似连通的图。

**Independent Test**: 使用包含两个章节、一个先拒绝后支持的直接关系和一个关联对象属性的夹具，验证第二记录实际执行、第一跳通过后才出现二跳任务，并验证另一个根谓词仍被调度。

**Acceptance Scenarios**:

1. **Given** 用户指定 CMCReport 根和多跳本体，**When** 首次规划召回，**Then** 只出现根的一个谓词步骤允许的对象类型；尚未关联对象的二跳类型不进入全文召回菜单。
2. **Given** 第一阶段相关章节全部拒绝、无候选或路由为阴性，**When** 当前主体—谓词仍有范围内记录，**Then** 系统实际执行不重叠的补充阶段并保存覆盖台账。
3. **Given** `describes` 在某条记录上失败，**When** 根还有生产计划、设备或其他直接谓词，**Then** 这些分支继续轮转，失败不成为文档级否定。
4. **Given** 一条无条件肯定关系有当前版本的完整证明，**When** 对象类型也有效，**Then** 系统才把该对象加入递归前沿并编译它的直接菜单。
5. **Given** 达到任务或跳数上限，**When** 仍有未探索前沿或记录，**Then** 系统报告范围不完整及停止原因，不宣称全图穷尽。

### User Story 3 - 核验同一运行的证据、候选和覆盖 (Priority: P1)

作为需要核验结果的分析人员，我希望物理提及、局部共指、本体类型、跨文档身份及具体谓词分别判定，并在同一运行的两个结果视图中查看主体、对象或值、桥接、条件、反证、候选和覆盖，再定位回原文。

**Why this priority**: 现有实测的主要错误来自身份角色和谓词桥接混淆；只有拆分证明责任，并把来源与未完成范围一并呈现，才能同时避免错误组成关系、过度拒绝和对空图的错误解释。

**Independent Test**: 使用“API 名称 + 试验来源号 + 无组成桥接”反例和明确组成句/配方表正例，前者不得产生有效组成边，后者必须形成可回放的独立证明；再从图中跨 Tab 定位其合并表格行并核对覆盖状态。

**Acceptance Scenarios**:

1. **Given** API 表头、名称及多个试验来源编号，**When** 系统判断类型与身份，**Then** 可以支持 API 类型，但不得把试验来源号升级为 API 全局身份。
2. **Given** 主体和对象分别有证据但没有当前谓词陈述，**When** 即使模型返回支持或图中已有父路径，**Then** 证明门禁仍拒绝该肯定边。
3. **Given** 明确组成句、主体明确的配方表或可消解的跨段组成陈述，**When** 端点、角色和适用性均通过，**Then** 关系可以进入有效肯定图，并保留全部桥接步骤。
4. **Given** 实体类型可靠但没有全局唯一编号，**When** 局部指称和谓词证据充分，**Then** 系统保留文档局部实体及其合法关系/属性，不伪造全局链接。
5. **Given** `N/A`、布尔“否”、原文未提及、原文明示否定和模型拒答，**When** 记录结果，**Then** 它们分别表示占位符、有效布尔值、未提及、否定事实候选和未决/技术结果，不相互转换。
6. **Given** 后来发现竞争主体、发生归并/拆分或上游证明失效，**When** 重算依赖，**Then** 旧判断保留历史但失去当前资格；属性不复制到所有拆分节点，独立替代路径可重新计算。
7. **Given** `/analysis?tab=document` 的已提交运行，**When** 页面展示结果，**Then** 只有“分层元数据”和“关系图谱”两个同级结果 Tab；候选、筛选、详情和覆盖均收纳在关系图谱 Tab 内。
8. **Given** 章节树、重复标题、页片段、段落和表格，**When** 用户选择节点，**Then** 分层元数据保留既有层级、摘要状态、解析信息和稳定原文定位，不按标题文本猜测来源。
9. **Given** 有效、否定、条件、未归属、待定或拒绝的候选，**When** 用户切换图内筛选，**Then** 默认图只显示当前有效肯定路径，其余状态可审计但不混作已确认关系。
10. **Given** 用户选择实体、属性或边，**When** 查看详情，**Then** 系统展示端点角色、谓词桥接、适用条件、反证、版本、判定和独立审阅状态，并能定位到本运行的原文记录或物理单元格。
11. **Given** 图为空或仍在运行，**When** 用户查看覆盖，**Then** 页面区分正在处理、技术未完成、语义未决和范围内处理完成但无有效关系，不断言全文客观无关系。

### User Story 4 - 安全控制、恢复和删除运行 (Priority: P1)

作为运行所有者，我希望后台任务在浏览器断开和服务进程重启后仍可安全继续，并能暂停、恢复、取消或删除；任何陈旧执行者、越权用户或迟到响应都不能改写或读取该运行。

**Why this priority**: 长时间模型任务和受保护原文需要持久队列、唯一执行权、精确授权及明确的终态，而不是依赖浏览器或请求线程。

**Independent Test**: 在一个运行中注入进程重启、租约丢失、暂停、恢复、取消、删除和跨用户请求，验证只从持久水位继续、无重复逻辑任务、无陈旧写入和无越权来源访问。

**Acceptance Scenarios**:

1. **Given** 一个正在执行的运行，**When** worker 租约过期或旧执行者迟到返回，**Then** 只有当前执行令牌持有者可以追加结果，旧结果被拒绝且不改变水位。
2. **Given** 用户请求暂停，**When** 当前安全批次提交完成，**Then** 运行才进入 paused；有效期内恢复时更换执行令牌并从最后持久水位继续。
3. **Given** 用户取消运行，**When** 取消生效，**Then** 执行权限立即撤销，已提交产物保留为取消快照，运行不可恢复；继续分析必须新建运行。
4. **Given** 用户删除或运行到期，**When** 清理开始，**Then** 系统先阻止领取、恢复和识别写入，再删除仅由该运行拥有的内容并保留防止迟到复写的最小墓碑。
5. **Given** 其他用户、伪造来源路径或越界文件请求，**When** 访问状态、事件、原文、控制或删除接口，**Then** 所有入口按同一授权边界拒绝，内容哈希相同也不授予跨用户访问。

### User Story 5 - 在质量与治理门禁后完成单次替换 (Priority: P2)

作为发布与合规负责人，我希望能够先盘点旧 Word 域及共享依赖，在独立质量、机制、权限和清理核验全部通过后一次性启用唯一新实现，使旧结果不可在线消费，同时不破坏其他抽取业务、共享来源、已发布历史或离线评测证据。

**Why this priority**: 直接替换和不可恢复清理具有高风险，必须以精确清单、依赖闭包、宪章治理和真实质量证据为前提。

**Independent Test**: 在含 Word、Excel、声明式、模板默认源、共享原文、已发布事实和全局审计的数据集中运行只读盘点及隔离切换演练，验证目标旧入口不可达、目标在线结果不再消费、保护对象不变且治理受限记录没有被物理删除。

**Acceptance Scenarios**:

1. **Given** 尚无独立金标、批准质量门、完整清理清单或宪章治理结论，**When** 请求正式切换，**Then** 系统保持维护前状态，不执行破坏性清理或开放新入口。
2. **Given** 目标旧数据与共享对象混合存在，**When** 生成清理清单，**Then** 每个对象都有精确身份、归属、引用、动作和切后核验；来源不明确的对象不删除。
3. **Given** 旧内容已确认、提交、发布或仍被其他产物引用，**When** 当前宪章仍有效，**Then** 系统通过追加撤销/失效和消费隔离处理，不物理删除历史。
4. **Given** 全部门禁通过并进入维护窗口，**When** 完成切换，**Then** 旧入口、旧 runner 和旧恢复器不可达，新系统不导入旧候选/断点/审核状态，其他业务与离线证据保持不变。
5. **Given** 切换中途或上线后发现严重语义、版本或权限问题，**When** 停止接单并暂停受影响运行，**Then** 修复唯一新实现并保留原始审计，不恢复旧实现、不篡改原提议，也不把取消或失败标成完成。

### Edge Cases

- 文件为空、伪装扩展名、损坏、转换失败、超大小或解压资源上限时，在模型调用前失败，并保留可理解的阶段错误。
- 合法标签相同但 IRI 不同，或同一 IRI 有继承、并列 range、显式 union、未支持表达式时，按完整 IRI 和正式约束处理；无法解析的约束保守待定而非放宽。
- 标题、目录、摘要或低置信提示提到实体，但正文没有当前谓词桥接时，只能影响检索顺序。
- 同一合并物理单元格被多个逻辑行观察时，只保留一个物理提及和多个观察引用；不按行数创建已确认实体。
- 表头与名称能定位表格但不能唯一定位行，或增加来源格只能定位某行时，定位结果不得升级为身份或关系证明。
- 同名、同项目、不同制剂/批次/试验来源号及第三个模糊节点不能通过传递闭包洗成同一实体。
- 属性值与属性词同时出现但 owner、制剂/API 层级或适用条件不明时，保留观察与待定/拒绝理由，不强挂到当前主体。
- 同一提议前置检查明确不支持时，后续检查标 `not_checked`；兄弟提议、后续记录和其他谓词继续。
- 模型拒答、非法结构、引用错误、超时、token 超限和服务不可用不记录为原文否定；有界重试耗尽后仍保留真实未完成状态。
- 大记录无法在不丢失表头、竞争主体、条件和反证的前提下装入上下文时，记录预算超限并继续其他任务，不静默截断后声称已检查。
- SSE 断线、旧游标、快速切换运行和迟到响应不得重启任务或把旧运行结果覆盖到当前页面。
- 暂停请求尚未到安全边界、取消/删除已请求、租约过期、fingerprint 不匹配或旧协议 checkpoint 存在时，允许操作由服务端状态决定，前端不能自行推定成功。
- 无条件肯定、否定、条件、模型拒绝和人工审核拒绝保持不同状态；只有当前有效的无条件肯定路径驱动肯定递归。
- 缺少全局身份不阻断局部事实；缺少局部类型或谓词证明则不能用全局同名键补过。
- 共享缓存命中不得跨用户泄露；共享产物删除采用引用检查，不能因单个运行删除而损坏其他运行。
- 未批准质量 SLO、保留集不足或目标 CMCReport 本身没有组成证据时，如实报告未决；不得修改原文、评分参考或超出 FR-087—FR-092 批准范围的本体来凑出成功链路，已批准的本体公理本身也不得替代原文事实证明。

## Requirements

### Functional Requirements

#### 输入、运行身份与产物边界

- **FR-001**: 系统 MUST 在 `/analysis?tab=document` 提供一个 `.doc`/`.docx` 文件、本体类型选择和显式“开始分析”；选择或拖入文件 MUST NOT 自动启动任何服务端分析。
- **FR-002**: 启动前 MUST 同时校验文件、实际文档内容、完整根类型 IRI 及根类型政策；无效输入 MUST 在任何摘要或识别模型调用前以 4xx 拒绝。
- **FR-003**: 根类型 MUST 来自用户本次明确选择并在运行内冻结；系统 MUST NOT 从全文猜测、替换或回退自动分类。
- **FR-004**: 用户指定的文档根 MUST 标明“用户指定”，只作为合法启动种子；它 MUST NOT 计入抽取真阳性或模型识别结果。
- **FR-005**: 每次显式启动 MUST 创建独立的分析运行，并分别绑定源文档身份、解析身份、元数据快照身份和识别运行身份；这些身份 MUST NOT 混用。
- **FR-006**: 创建运行 MUST 支持按所有者隔离的幂等键：同键同文件和类型返回同一运行，同键不同输入返回冲突；仅文件哈希相同 MUST NOT 吞掉用户明确的新运行。
- **FR-007**: 已提交运行的文件、根类型、本体快照和执行配置 MUST 不可编辑；更换输入 MUST 创建新草稿并在再次显式提交后产生新运行。
- **FR-008**: 同一运行 MUST 产出共享同一原文、IR 和冻结元数据快照的分层元数据与关系图谱；元数据可先就绪，图谱可按完整水位增量就绪。
- **FR-009**: 文档分析候选、证明和图 MUST 仅为运行级分析产物；系统 MUST NOT 自动审核、自动确认、自动提交共享业务事实或向中央事实库写入。
- **FR-010**: 在线运行范围 MUST 默认为 `document_graph`；`focus_path` 只可用于明确标记的评测或诊断，并将其他谓词标为范围外。

#### 结构、摘要与本体菜单

- **FR-011**: 系统 MUST 一次构建可版本化的 Word IR、章节树、物理来源和逻辑记录索引，并保留段落、表格、合并单元格、表头、行列和原文区间的可回放身份。
- **FR-012**: 系统 MUST 形成版本化 MetadataSnapshot，绑定文档/结构哈希、摘要来源与模型身份、原始节点/记录及全部依赖；摘要或回退内容不得获得事实来源身份。
- **FR-013**: 元数据准备 MUST 明确区分有效缓存摘要、新生成摘要和仅结构三种模式；实际模式及版本 MUST 进入运行身份和进度。
- **FR-014**: 识别开始前 MUST 冻结 MetadataSnapshot；晚到或重新生成的摘要 MUST NOT 改变当前运行的排序、缓存、候选、覆盖或完成度。
- **FR-015**: 摘要失败时 MUST 如实显示失败、摘录回退或 structure-only；已完成的确定性结构仍可查看，切换 Tab 或 GET MUST NOT 隐式重试摘要。
- **FR-016**: OntologySnapshot MUST 保留正式 domain/range、声明来源、继承路径、同 IRI 多项约束、定义哈希和无法解析的约束，不能用扁平投影静默放宽本体。
- **FR-017**: 系统 MUST 按当前已通过类型的主体编译一个谓词步骤的 LocalMenu，包含合法继承属性/关系和正式对象 range/子类批次；模型不得新增 IRI、修改 domain/range 或扩展允许输出类型。
- **FR-018**: 多跳类型 MUST NOT 在父关系成立前预展开到全文召回；只有具体对象经当前有效肯定边到达后，才可编译该对象的直接菜单。
- **FR-019**: domain、range、标题、摘要、提示分数和现有图路径 MUST 只用于约束或检索，不得单独作为实体存在、属性归属或关系成立的证据。
- **FR-020**: 无法解释的本体约束 MUST 产生明确诊断并使受影响提议保守待定；其他独立谓词 MUST 继续。

#### 检索、调度与覆盖

- **FR-021**: 每个范围内主体—谓词 MUST 有版本化 RetrievalPlan 和 RecallLedger，计划键必须覆盖主体版本、本体、原文/元数据和检索政策身份。
- **FR-022**: 每个计划 MUST 具有不重叠的优先阶段和补充阶段，其并集等于该运行范围内的全部目标非标题记录；低分、路由阴性、零匹配和首次拒绝不得永久移除记录。标题和表头可以作为受限上下文或验证来源，但除非另有明确的标题事实政策，不得作为独立实体召回目标。
- **FR-023**: 第一阶段无肯定输出 MUST 进入补充阶段；验收必须看到后续不同记录的真实任务/调用事件，不能以“队列中仍有项目”代替执行。
- **FR-024**: 根的全部直接谓词、关系与属性、根分支与子分支 MUST 有公平且有界的轮转；任一提议、记录或关系失败 MUST NOT 阻断其他独立工作。
- **FR-025**: 可选 mention 召回器只能在当前小菜单内提出回到原文 span 的线索；缺失、关闭或未命中时 MUST 保留通用主召回路径，且不得判定身份、属性 owner 或关系。
- **FR-026**: 检索范围、绑定范围和已授权断言范围 MUST 分开；授权必须绑定精确主体、谓词、角色、证据和版本，不能跨谓词或整个文档泛化。
- **FR-027**: 上下文 MUST 保留目标、完整逻辑记录、物理表头/合并映射、端点来源、连续字段块、竞争主体、条件、否定和反证；不得为了预算静默删除这些内容。
- **FR-028**: 无法在预算内保留必要证据闭包时 MUST 记录 `context_budget_exceeded`、保持该记录未完成并继续其他任务；不得把拆碎的小格冒充完整原记录已验证。
- **FR-029**: RecallLedger MUST 满足 `planned = unattempted + attempted_incomplete + examined` 且三类互斥；排队、运行和重试状态属于执行维度，不能重复计入覆盖。
- **FR-030**: 空召回只表示未观察到候选；技术失败、协议失败、拒答或缺失必要判定 MUST 为 attempted_incomplete，不得提升为 examined 或“没有事实”。相同输入的 semantic unsupported 不得重复采样刷成通过；undetermined 只可在有实质新证据或显式上下文扩展时补验，默认每个稳定断言 lineage 最多两次补验。纯 alias、revision 或计划重建不得重置额度；lineage 归并须合并已用额度，拆分须继承额度。技术重试须独立计数，重验不得饿死未尝试记录；显式追加额度必须记录授权操作者和理由。

#### 提及、实体、身份与语义证明

- **FR-031**: 系统 MUST 分离物理 SourceMention、文档 LocalReferent、本体 EntityInterpretation 和跨文档 IdentityClaim，并分别保存精确来源、版本、证明和竞争解释。
- **FR-032**: 同一物理来源在多个逻辑视图出现时 MUST 去重物理提及并增加观察引用；物理去重 MUST NOT 自动创建、拆分或合并业务实体。
- **FR-033**: 类型、局部共指、标识字段角色、局部对应、唯一性范围和全局身份 MUST 分别判断；缺少全局唯一键 MUST NOT 否定已由原文支持的局部实体。
- **FR-034**: 每次验证 MUST 绑定程序构造且不可由模型替换的目标，至少固定检查种类、运行/文档上下文、主体、谓词、对象或值、极性、适用性、来源范围以及所有相关版本。
- **FR-035**: 语义判定 MUST 区分 `supported`、`unsupported`、`undetermined`、`not_checked`；技术失败和模型拒答另记执行事件，MUST NOT 伪装为 unsupported。
- **FR-036**: 支持、拒绝和不确定判定 MUST 保存理由代码、理由、实际查看范围、支持与反证引用、验证器/模型身份和尝试身份；重验追加新版本，不覆盖旧答复。
- **FR-037**: 每条属性或关系 MUST 有针对当前精确谓词的 PredicateEvidence，分别包含主体角色、对象/值角色、谓词桥接、适用性、反证和依赖；仅端点共现、同文档、同名、邻近或父路径不得通过证明门禁。
- **FR-038**: 可接受桥接限于原文明示断言、owner 明确的字段组、角色映射表、已消解引用链或受限文档主题描述；桥接类别自身还 MUST 通过独立语义核验，模型声明类别不能自动放行。
- **FR-039**: 文档描述、实体数据属性和组成关系 MUST 使用按精确谓词版本化的政策；文档主题描述授权 MUST NOT 用于证明产品组成或任意子属性。
- **FR-040**: 无全局身份时，充分的局部类型、指称和谓词证明仍可产生运行内实体与关系；没有通过类型或谓词证明时，不得为了探索下游而保存假肯定边。
- **FR-041**: ValueObservation MUST 区分 present、placeholder 和 not_mentioned；placeholder 至少区分 unknown、not_applicable、unspecified。无上下文的 `N/A` 不得成为事实值，“否”不得被缺失过滤。
- **FR-042**: 断言极性 MUST 区分 affirmed、negated、conditional 和 uncertain；模型未支持不等于原文否定，只有当前有效、无条件、肯定且未被审核拒绝的边可以驱动肯定递归。
- **FR-043**: 当前提议前置检查明确失败时，后续阶段 MUST 标记 not_checked 并停止该提议；同记录其他提议、下一记录、其他谓词和独立路径 MUST 继续。
- **FR-044**: 原文引用 MUST 使用运行内授权 ID 和精确子串回放；坐标由程序唯一定位，权限、定位回放和语义支持 MUST 分别校验，重复子串不得任选第一处。
- **FR-045**: 无法映射到当前本体的真实观察 MUST 作为 unmodelled observation 保留，不得偷偷映射到相近但错误的类或属性。

#### 归并、依赖、版本与图投影

- **FR-046**: 同名、同项目、邻近或不同试验来源号都不得单独决定实体数量或归并；可靠键归并必须同时满足角色、namespace/scope、类型/限定兼容和冲突检查。
- **FR-047**: 每次归并或拆分 MUST 形成追加式 ResolutionEvent，记录输入精确版本、依据、规范选择、别名、旧/新版本及受影响断言；拆分不得把旧属性复制给所有新实体。
- **FR-048**: DependencyIndex MUST 覆盖类型解释、局部共指、身份、谓词证明、范围、路径、审核、原文/元数据版本及竞争 owner 订阅；晚到竞争证据必须使相关旧资格失效并按需重验。
- **FR-049**: 一个证明的必要依赖 MUST 按 AND 处理，同一断言的独立替代证明按 OR 处理；上游失效后只有完整独立替代路径可恢复可达性。
- **FR-050**: 文档根是唯一无入边启动例外；普通实体必须由当前有效肯定路径到达。未经专家审阅可继续分析探索但必须标为 unreviewed，且不获得业务事实提交资格。
- **FR-051**: 候选、证明、事件和图投影 MUST 使用运行内真实 `id@revision`，不得把首次观察的 revision 重置为 1、静默升级引用或创建第二套公共映射。
- **FR-052**: 图快照 MUST 来自同一已持久事件水位，包含根、实体、属性、关系、精确证明、元数据快照、覆盖和未决统计；失效/删除也必须显式表达，前端不得拼接不同水位。

#### 持久运行、状态、恢复与保留

- **FR-053**: 运行级原始提议、判定、证明、归并、失效和覆盖事件在保留期内 MUST 追加式不可变；当前 head 和投影必须可从权威事件重建。
- **FR-054**: 运行状态 MUST 分离 execution、stage、coverage、semantic、artifact、control 和 deletion 维度，并能表达 queued/running/paused/finished/failed/cancelled、ingest/parse/metadata/recognition/finalize、partial/exhausted_in_scope、unreviewed/unresolved/reviewed 以及各产物的 pending/building/ready/partial/failed；正常语义拒绝不得使整个执行 failed，队列耗尽不得表示语义正确。
- **FR-055**: `in_scope_complete` 只可在必要计划已执行且没有技术未完成或上限截断前沿时返回；语义未决数和执行完成度 MUST 同时展示。
- **FR-056**: 完整运行 fingerprint MUST 在图谱识别前冻结，并覆盖文档/结构、根类型、本体/菜单、元数据、模型/tokenizer、协议、验证/归并/检索政策、scope、预算及重试设置。
- **FR-057**: 新协议恢复只允许同一运行且 fingerprint/schema 一致；旧 runner checkpoint 或不匹配的新 checkpoint MUST 明确拒绝，不尝试转换或降级到旧实现。
- **FR-058**: 后台工作 MUST 来自持久可领取状态并由唯一租约和执行令牌保护；模型调用前、返回后和每次持久批次均必须检查所有权，失去令牌的 worker 不得写入。
- **FR-059**: checkpoint MUST 保存持久水位、前沿、覆盖、候选/证明 head、依赖、重试、调度轮次和进度；中断记录保持 attempted_incomplete，恢复不得重做已完整提交的逻辑任务。
- **FR-060**: pause、resume、cancel 和 delete 必须校验预期控制版本并由服务端返回当前合法操作。pause 必须在安全提交边界生效且可在有效期内 resume；cancel 必须撤销执行权、保留取消水位且不可恢复；delete 必须先阻止领取/恢复/写入，再进入明确删除状态。
- **FR-061**: 运行中默认不因保留期自动删除；终态从结束时间、paused 从暂停时间起默认保留 7 天，并向用户返回实际 `expires_at`。具体可配置值、大小和资源限制必须进入部署配置及边界测试。
- **FR-062**: 到期或用户删除只能清理该运行独占的源文件、产物、缓存和记录；共享产物必须做引用检查，并保留足以阻止迟到 worker 复写的最小删除墓碑。
- **FR-063**: 缓存复用 MUST 覆盖内容、全部语义依赖、版本和权限域；相同哈希不得授权跨用户读取，Tab 切换、刷新和事件重连不得隐式重算。

#### API、页面、安全与可观测性

- **FR-064**: 系统 MUST 以 `/api/document-analysis/runs` 为唯一新 API 前缀，提供创建、状态、metadata、graph、source、events，以及 pause、resume、cancel、delete 能力，并在响应中声明契约版本。
- **FR-065**: 创建接口 MUST 接收 Word 文件、完整根类型 IRI 和所有者隔离的请求幂等键，验证后返回 202 与运行查询地址，不同步等待图谱完成。
- **FR-066**: 所有 GET 和事件订阅 MUST 只读取已存在运行；pending、partial、failed、deleted/expired 和旧游标均有明确响应，不得创建任务、生成摘要、识别候选或审核结果。
- **FR-067**: 事件订阅 MUST 支持按最后事件 ID 续读；无法续读时客户端必须通过只读 GET 获取完整当前水位，不得重启分析。
- **FR-068**: 状态、元数据、图、原文、事件、控制和删除接口 MUST 使用同一登录、所有者/授权检查；source 不得接受任意服务器路径或未授权 URL。原文、证明和模型上下文必须受相同权限保护，完整 prompt、业务片段和标识不得写入通用遥测。
- **FR-069**: 文档分析面板 MUST 提供恰好两个并列结果 Tab：“分层元数据”和“关系图谱”；前者完整收纳章节树、原文、节点摘要与结构信息，后者收纳图、筛选、详情、证据及覆盖。
- **FR-070**: 图谱默认显示当前证明门通过的肯定根图；图内必须可查看全部候选及未归属、否定、条件、待定、拒绝状态，但不能把它们展示成已确认肯定边。
- **FR-071**: SourceSelection MUST 同时包含运行、解析、记录/单元格及 span 身份；从图证据到原文和章节的定位、跨 Tab 切换及重复标题场景均必须保持稳定。
- **FR-072**: 页面 MUST 显示文件名、类型标签及完整 IRI、运行阶段、状态、合法控制、保留期限和真实 RunProgress；进度至少分别报告任务尝试、模型调用、记录计划/已检/未完成/未尝试、分期计数、supported/unsupported/undetermined、待展开前沿、停止原因和契约版本。无可靠总数时不得制造百分比，计划记录数不得作为模型调用分母。
- **FR-073**: URL 可使用 `documentRun=<recognition_run_id>` 恢复当前运行；前端必须按运行 ID 和单调水位隔离请求，旧运行迟到响应不得覆盖当前选择。
- **FR-074**: 页面文案 MUST 说明分析会生成分层元数据与关系图谱、结果不会自动提交业务事实、关闭页面不取消运行且数据按保留策略清理；旧“即时、临时、不识别图谱”文案必须移除。

#### 退役、清理、评测与发布

- **FR-075**: 旧 `POST /api/document-analysis/word`、旧客户端、被替换的 Word 图谱入口、旧格式适配、旧 runner 恢复器和新旧选择开关 MUST 从生产可达路径移除。
- **FR-076**: Excel、数据库、声明式抽取、模板默认源及其他业务入口所需的共享解析/模型设施 MUST 保留并回归；系统不得按 Word 扩展名、目录或粗粒度 source_type 清空共享数据。
- **FR-077**: 清理前 MUST 生成并复核只读 manifest，逐项列出精确对象、来源模式、归属、文件绝对路径及哈希、所有引用、动作和切后核验；未知归属项不得删除。
- **FR-078**: 旧候选、断点、审核状态和缓存 MUST NOT 导入新运行；冻结实验、历史报告、评测输入和夹具 MUST 作为离线证据保留且不进入线上运行数据。
- **FR-079**: 在现行 Constitution III 下，未发布且独占的旧运行数据方可按 manifest 物理删除；已确认、已提交、已发布或被引用内容 MUST 追加撤销/失效并保留历史。其物理删除必须以前置宪章修订或正式治理批准为条件。
- **FR-080**: 任何破坏性清理 MUST 等到旧写入和租约已撤销、迟到结果无法写入、机制/权限/质量门通过并进入维护窗口；清理过程必须幂等记录数量、文件、保留/失效对象和失败项。
- **FR-081**: 线上与评测 MUST 使用同一识别核心和版本化政策；评分参考、人工金标或评分器不得作为识别输入，冻结历史 runtime 不得挂入在线服务。
- **FR-082**: 独立标注包 MUST 覆盖 mention、类型、局部共指、身份角色/范围、owner/层级、谓词方向/桥接、极性/条件及等价来源；开发文档及近重复不得充当保留集。
- **FR-083**: 评测 MUST 至少包含明确组成正例、同文档同名但无组成桥接反例、原料/制剂/批次/试验编号混合难例，并对关键正反例进行至少三个独立新运行，不挑选最好一次。
- **FR-084**: 发布 MUST 分开报告机制、语义、覆盖、运行完整性和成本；成本至少区分首个有效结果、排队、摘要、模型/非模型时长、tokens 和调用数。本轮不以相对历史耗时的提速倍数作为硬门。未决、未评分、技术未完成和范围外内容须单列，图连通、旧银标命中或全部拒绝不得当作质量成功。
- **FR-085**: T01—T31 对应的确定性、数据库/API、前端、本体和清理契约以及独立真实质量门全部通过后方可正式切换；没有批准的质量 SLO 或保留集结果时不得开放线上入口或执行旧数据清理。
- **FR-086**: 切换后若发现摘要事实泄漏、错误身份/组成、版本错配、跨用户访问或未授权事实提交，系统 MUST 停止接单、暂停受影响运行、保留审计并修复唯一新实现；不得恢复旧实现或改写原始判断历史。

#### 经批准的有限 CMC 权威本体扩展

- **FR-087**: 权威 CMC 本体 MUST 新增 `producesFinalProduct` 对象属性，其 domain MUST 为 `SynthesisRoute ⊔ SynthesisStep`，range MUST 为 `DrugProduct ⊔ ActivePharmaceuticalIngredient`；该属性表示路线或最终步骤的最终产品/API，MUST NOT 用于 `ProcessIntermediate`。
- **FR-088**: 权威 CMC 本体 MUST 新增 `intermediateIdentifier` 数据属性，domain 为 `ProcessIntermediate`、range 为 `xsd:string`，用于保存 `SM5592-A14`、`SM5592-A15` 等原文明示标识。除非另有经验证且进入运行身份的项目/路线唯一性范围，裸标识 MUST NOT 被声明或解释为全局 `identityKey`。
- **FR-089**: 权威 CMC 本体 MUST 新增可多值的 `hasProcessIntermediate` 对象属性，domain 为 `DrugProduct ⊔ ActivePharmaceuticalIngredient`、range 为 `ProcessIntermediate`，且 MUST NOT 声明为 functional 或施加最大基数；其值是无序的产品/API 级中间体视图。
- **FR-090**: `hasProcessIntermediate` MUST 具有两条正式属性链：路线级链 `inverse(producesFinalProduct) / hasStep / producesIntermediate`，以及仅有最终步骤关系时恢复所属路线的链 `inverse(producesFinalProduct) / inverse(hasStep) / hasStep / producesIntermediate`。属性链只表达已明确最终产品路径上的蕴涵；同一 `CMCReport` 同时提及产品与路线、同名或邻近 MUST NOT 触发该关系。
- **FR-091**: 中间体的工艺顺序 MUST 由现有 `SynthesisStep.stepOrder` 或 `SynthesisStep.nextStep` 表达；RDF 多值断言、API 数组或 UI 展示的元素位置 MUST NOT 被解释为规范顺序。
- **FR-092**: `owl:propertyChainAxiom` 的存在只保证正式本体语义，不保证当前运行时 reasoner、SPARQL、实体 API 或图投影自动物化 `hasProcessIntermediate`。在没有版本化推导器或显式已审核断言时，系统 MUST 只展示基础边和“可推导”定义，不得把未物化关系宣称为已存储事实；若未来运行时推导，结果 MUST 绑定两条基础路径中的实际依赖和来源版本。匿名 union、属性链及其 RDF list MUST 在加载、schema 投影和权威 TTL 往返中保持完整。

### Key Entities

- **Document Analysis Run**: 用户一次显式分析的稳定身份，绑定所有者、文件、根类型、本体、执行配置、状态、控制、保留期限和产物水位。
- **Document IR / Record Index**: 同一源文件的确定性结构与物理/逻辑记录视图，保存章节、段落、表格、单元格、表头、合并映射和可回放坐标。
- **Metadata Snapshot / Retrieval Hint**: 冻结的章节树、摘要及结构提示；只具有检索权限，不具有事实权限。
- **Ontology Snapshot / Local Menu**: 可追溯的正式本体约束及当前主体一个谓词步骤的合法属性、关系和对象类型菜单。
- **Source Mention / Local Referent / Entity Interpretation / Identity Claim**: 从物理原文区间到局部指称、本体类型解释和跨文档身份的四个独立层次。
- **Field Role Claim / Value Observation**: 原文区间在当前记录中的身份、名称、属性值、条件等抽取角色，以及值的存在/占位/未提及状态。
- **Verification Target / Semantic Decision / Predicate Evidence**: 冻结的验证对象、分阶段语义判定和针对精确谓词的端点/桥接/反证/依赖证明。
- **Retrieval Plan / Recall Ledger**: 某主体—谓词的分期记录计划、实际尝试、判定和覆盖守恒台账。
- **Resolution Event / Dependency Index**: 局部归并、全局关联、拆分与失效的追加历史，以及所有证明、范围、路径、审核和竞争解释依赖。
- **Run Fingerprint / Checkpoint**: 完整执行身份和可恢复水位，防止跨版本、跨协议或多 worker 陈旧写入。
- **Graph Snapshot / Source Selection**: 同一事件水位的完整图投影及跨两个结果视图定位原文所需的稳定引用。
- **Cleanup Manifest**: 旧域目标、独占/共享归属、引用闭包、允许动作、计数与保护对象的审计清单。

## Assumptions

- 复用现有登录身份、授权角色、Word IR、章节树、原文预览、本地模型/tokenizer 与本体查询能力；后续 plan 必须重新核对当前代码而不能把历史实验视作生产实现。
- 默认在 air-gap 环境运行，运行期不依赖公网。可选本地模型关闭是正常配置；结构仍可查看，依赖模型的图谱工作如实保持未完成，不回退旧规则。
- 首期默认终态/暂停保留 7 天；上传大小、解压资源、模型预算和调度上限由部署配置给出并纳入 fingerprint、状态展示和边界测试，而不是在规范中虚构生产容量。

- 当前 CMCReport 及近重复文档是开发回归输入，不是未见保留集；真实质量阈值需业务与技术在独立标注规模明确后预注册。
