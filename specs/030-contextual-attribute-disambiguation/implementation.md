# 030 实施说明

日期：2026-09-19。对应用户授权的四项需求；沿 Spec Kit 的 spec、澄清、plan、tasks 实施。

## 输入与执行顺序

原始 Word → 保留完整 IR/预览并标记确定目录 → 正文记录与真实标题上下文 → 有界阅读组与物理字段识别及去重 → 组内普通实体属性发现 → 对应字段消歧 → 独立核验 → 已登记实体间关系。

1. `docx_structure.py`、`document_ir.py` 标记确定的目录标题/条目，解析版本升为 7。`records.py` 与 `word_tree_summarizer.py` 排除这些导航材料，目录后的无标题正文仍保留。旧 IR 未携带角色字段时保持原序列化和哈希。
2. `reading_groups.py` 只依据本体字段结构或明确续文，在相同父节及主体/条件边界内组成阅读组。默认单节 240 字、组 1200 字、最多 8 条记录；字数是容量上限，不证明语义连续。标题、祖先和旁读记录只提供绑定上下文；每个事实仍使用明确授权的原记录。
3. `attribute_disambiguation.py` 从标签和值的精确物理锚点建字段。支持短字段、表格表头、字段标题和值，以及有明确 split_field_value 依据的前后分段。相同物理字段跨类卡只产生一个 lineage；同值不同位置不会合并。
4. `executor.py` 在记录 × 类卡展开前分流纯编号/密级字段；混合记录继续识别实体和其他属性。`contextual-discovery-v2` 先执行阅读组的普通发现，再执行对应字段；前置纯字段延后到下一普通组，全文无普通组时直接执行。已分流字段的值不能从普通 properties 分支重复入图。合法主体/属性对统一比较，不按分数截成“唯一候选”。缺值、本体缺口、主体缺失或容量超限保留原因且不发消歧请求。
5. `record_model_adapter.py` 的属性任务禁止工具探索、新实体和其他字段，最多输出一个授权组合及精确原值；正常发现和独立核验共享既有总预算。多解或证据不足保留未决，不生成属性事实。存在唯一候选也必须验证归属。
6. 当前字段状态复用 `work:record_discovery`；没有新表、历史快照或第二套账本。相关候选/修订/来源变化才唤醒，字段首轮后最多再试一次。技术失败的已付尝试也计数，零调用前置缺口不计实际尝试；暂停继续复用已经确认的响应。

## 本体与展示

权威 TTL 仅增加 `slpra-doc:documentNumber` 和 `slpra-doc:confidentialityLevel`，domain 为 CMCReport，range 为字符串。增量 +12/-0；原有 3470 条三元组保留。不增加必填、唯一键、基数、密级枚举或访问控制含义。详见 [增量契约](contracts/ontology-diff.ttl)。

隔离加载发现既有快照导出丢失跨模块父类；`ontology_plan.py` 合并类详情中的已加载父类后，真实 CMCReport 卡保留 6 个既有属性和 2 个新增属性。该修复作用于新建快照，不改写旧冻结快照。

Harness 通过只读 GET 展示当前字段、原值、候选数、尝试次数和原因，区分属性消歧与属性归属核验。未准备的候选数显示“尚未准备”；运行中的 active 行结合运行状态展示执行中或已暂停。已解决、未决、技术错误和否定事实不会合并成一种结果。

## 生效与边界

- 新普通文档运行默认冻结 `contextual-discovery-v2`；已存在的 `contextual-discovery-v1` 运行继续使用字段优先的原游标顺序，原请求和已付响应不改写。
- 已验证别名可用于候选及原文上下文，不自动继承为属性证明；仍走独立归属核验。
- 只有短、邻近或摘要相似的章节不会合并；无明确字段标签的孤立代码不猜归属。
- 分段标签和值完成字段路由后，纯标签记录可能仍有普通发现开销；关系识别保留自己的必要核验，不能把“字段零调用”宣称为“整份文档零调用”。
- 未调用真实模型做质量评测，不据受控测试宣称准确率、tokens 或耗时改善。T32 的真实模型质量验收仍独立待办。
- 首次实现交付后，按用户后续授权完成前后端重启，启动时从权威 TTL 重建 World 并补种两个新增属性；没有发布混合其他草稿的工作台批次。在线生效及旧草稿保持核验见 [deployment.md](deployment.md)。
