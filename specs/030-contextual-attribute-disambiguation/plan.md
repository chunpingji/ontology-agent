# 030 实现计划

当前字段校准阶段由 [032](../032-attribute-calibration/spec.md) 补充：首次消歧保留未决原字段，后到相关实体/关系的变化在常规识别收尾时合并为一次有界校准，继续使用原 lineage 与总调用预算。

流程：specify → clarify（见 spec 的默认判断）→ plan → tasks → implement；保留工作区既有 028/029 改动，不切分支，不自动提交。

## 宪章检查（设计前/后）

范围限用户明确的四项需求；无新依赖、服务、消息队列或历史快照。原文证据/主体/条件和独立核验不放宽。本体写入先展示 12 条新增三元组预览，外科式添加，并在隔离环境验证元数据和 World；不操作业务库草稿。当前状态与模型账本复用已有边界。设计前与契约确定后均通过。

## 实现边界

1. 目录：解析器逐段标记 `navigation_role`（toc_heading/toc_entry），IR 保留；RecordIndex 与摘要材料排除这些单元。新 parser version；旧 IR 缺失角色字段不改变旧结构哈希。
2. 阅读组：独立纯函数基于冻结 IR、真实标题锚点、本体字段标签及明确续文构造有界组。保留原记录，记录发现任务携带 `source_record_ids`，聚合授权原文但不推导实体同一性。组容量默认短节 240 字、总量 1200 字、最多 8 条记录；这些是容量限制而非语义证明。
3. 字段消歧：在普通类卡准入前识别独立字段观察，按原文位置建立唯一字段任务。执行时按阅读组先跑普通实体发现，再跑该组字段；此前没有普通来源的纯字段延后到下一普通组，全文无普通组时直接执行。复用 RecordDiscoveryTask/记录模型闭环，显式 `purpose=property_disambiguation`，禁止发明实体，只允许授权候选对的属性提案；独立核验复用原路径。混合记录保留一般发现。
4. 同字段的合法候选属性卡一次确定，字段工作与当前记录工作同分区保存；不新建数据库表。相关实体修订/来源及允许属性形成无序依赖签名；重开复用原 lineage、预算、协议和原子发布，不重写已发送输入。
5. 冻结 `contextual-discovery-v2`，与 [031](../031-semantic-record-discovery/plan.md) 的有限语义候选共同调度，相关普通发现后释放字段；不保留 v1 字段优先游标执行分支。Harness/契约显示属性消歧和最新字段结果；GET 不触发模型。
6. 本体：`slpra-doc:documentNumber`、`slpra-doc:confidentialityLevel`，domain CMCReport，range string；无基数、hasKey 或枚举。三元组 diff 与隔离同步测试见 contracts 和 tests。

## 验证策略

目录与分组用合成 DOCX 及原文锚点反例；字段准入/候选/重复输入、后到主体、恢复和原子发布用受控模型集成测试；在线策略、Harness 和类型做定向验证。仅当触及 PostgreSQL 并发契约时运行专用可销毁库。结果记录于 quickstart，不复用 029 历史测试数字作为本次结果。
