# 实现计划

流程：specify → clarify（spec 中的默认检索参数与边界）→ plan → tasks → implement。

宪章检查：复用现有离线语义服务、当前状态和调用账本；无新依赖、组件、原文权限扩张或本体修改。新策略替换普通记录发现，不增加旧运行兼容分支。

1. 冻结候选上限、相似度阈值；独立模块负责检索视图、有限候选和选取/消费。
2. 复用 RankingService 的模型、预算、向量缓存与持久化边界，批量编码两侧文本。
3. Executor 保存每组最新候选状态，按相关性准入并消费；RecordDiscoveryTask 及核验不变。进度只统计实际工作，附检索范围与未入选计数。
4. 回归覆盖排序、收缩、失败/暂停、冷继续与字段/关系联动；用已有诊断输入核对调度规模，不启动原运行或新生成模型评测。

小候选池减少生成调用，但可能损失召回；低分组合保留检索未覆盖语义，真实阈值需固定输入、本体、模型的质量对照后调整。

实施后宪章复核：保持以上组件和证据边界；新增原文指代线索只用于有界补识别，不建立实体同一性。前端明确未入选组合未经识别；原任务、原文权限与独立核验继续复用。无本体、数据库结构或运行期外网依赖变更。

## 2026-09-19 调用效率修正

按 [补充需求与验收](recognition-efficiency.md) 先明确范围，再实现：复用表格阅读组容纳有界连续行；关系端点未就绪时保留当前待处理状态并推动对应发现，端点变化后唤醒；补齐发现提示与有预算的输出纠正；在现有候选分区内调度补缺及不同章节/类型。沿用原文权限、独立核验、当前状态及调用账本，不新增存储、模型或服务。通过受控多实体/多属性、跨行反例、后到端点、冷继续和预算用例验证，真实模型结果及部署另行记录。
