# 031 实现记录

日期：2026-09-19；工程验证完成，未部署或重新识别真实文档。

## 最终算法

1. 复用 030 阅读组和唯一字段观察。普通 Schema Card 仍按容量编译，每卡默认最多 4 个类。
2. 分别编码卡片的标签/描述/属性标签/本体词项及阅读组的标题/原文。复用本地语义模型、精排缓存与预算，批量编码成本随阅读组数与卡片数之和增长；余弦比较不调用生成模型。
3. 每组保留达到 0.25 的最多 2 张卡。优先从未处理阅读组选择，再按相似度和原文位置排序；不存在全组合任务或扫描游标。
4. 准入后从候选待办移除，原任务保存执行结果。明确缺口可每组补选最多 1 张相关卡，已执行任务可按原证据反馈与原调用预算有界重开；同类实体在其他记录中的候选不被全局删除。
5. 语义排序可能使指代段先于其先行词。原文明示指代但尚无绑定时保留来源线索，相关实体出现后定向补识别；原文、身份和独立核验权限保持。
6. 字段仍只生成一份任务，在相关普通发现后释放。候选/任务状态复用当前工作分区，向量与请求成本使用独立精排分区；冷继续加载已保存结果。

假定仍有 151 个普通阅读组和 67 个字段，首轮发现上限为 `151 × 2 + 67 = 369`，原计划为 `151 × 35 + 67 = 5352`。这不是实际调用数或耗时：联合阅读/阈值可能进一步减少首轮任务，核验、关系与有界反馈另计。没有用受控向量测试证明真实召回率。

## 文件与契约

- `record_search.py`：有限候选、相似度选取、消费与有界补选。
- `record_discovery.py`：冻结 `record-discovery-v2` 及参数；仅保留当前 contextual v2。
- `semantic_reranker.py`：发现向量编码复用已付费缓存、请求额度、总/槽 token 预算、暂停/取消与模型 deadline；失败不回退穷举。
- `executor.py`：以 `work:record_searches` 替换笛卡尔游标，消费后准入任务；保持同 lineage 已证明且仍有效的关系覆盖。
- `reference_context.py`：复用原有明确指代线索判定。
- `retrieval_diagnostics.py`、`document_analysis/application.py`、前端 API 类型：传播筛选组数、剩余/准入/未入选组合数。图谱面板明确未入选组合未经识别。
- `quality_guided_variant.py`：评测输出增加候选筛选计数；不将候选耗尽当成全文事实穷尽。
