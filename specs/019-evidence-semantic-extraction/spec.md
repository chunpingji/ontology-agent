# Feature Specification: 统一文档证据与通用语义抽取

**Feature Branch**: `019-evidence-semantic-extraction`
**Created**: 2026-09-05
**Status**: Ready for planning
**Input**: 用户要求基于 Spec Kit 实现已评审的《文档结构解析能力增强报告模板的关系图谱识别和 NER 能力》，包括复审 P2 的否定/条件断言澄清。

## Clarifications

### Session 2026-09-05

本轮沿用已完成的两轮评审及用户补充，未重新询问已明确需求。

- 否定断言有充分证据时可以验证、审核、提交；只阻断对应正向事实的物化。条件断言也可持久化，不直接作为无条件正向事实。
- 最终消除范围包括自有生产处理链的正则与硬编码业务 finder，涵盖结构、分词、配置、来源、报告及前端；第三方内部实现单独审计，不宣称全栈零正则。
- 模型关闭是离线正常态，结构预览和模板草稿仍可用；依赖模型的任务如实显示未完成，不回退旧规则。
- 真实人工金标、性能和最终退役验收是发布门禁，不能以桩模型或旧输出代替。未具备实测证据时不标记发布就绪。

## User Scenarios & Testing

### 指定业务验收场景（2026-09-05 用户补充）

以 `/settings/ast-templates/dea037a2-f4b5-478a-8e0e-d5471fc45cbc` 的风险评估文档模板为业务验收基准：输入 `CMCReport`，使用模板关联的默认源文档，输出可预览、可下载且逐值可溯源的风险评估报告。模板样例只控制结构/行文，不作为事实来源；审核、提交、覆盖和报告必须使用真实发布快照。缺失项、否定项及待人工签署项如实呈现，不为跑通而伪造“可接受”、人员签名或来源数据。模板原版本和历史报告保持可回放，声明修订须记录前后差异。

该场景是用户指定的业务“金标”（端到端验收用例），不等同于独立人工标注的模型质量数据集。总体特性范围不缩减；质量统计和性能发布门禁仍需实际证据。

### User Story 1 - 一份文档、统一结构和可定位模板 (Priority: P1)

分析人员上传 Word 后，在分析、模板设计和抽取中看到一致的章节与表格，并能从插槽或证据直接定位原文。

**Why this priority**: 来源坐标和结构是所有后续事实判断的基础。
**Independent Test**: 上传含重复标题、分页、合并及多层嵌套表的文档，三个入口结构一致；关闭语义模型仍能创建结构草稿。

**Acceptance Scenarios**:

1. **Given** 相同文件及解析版本，**When** 分别分析、导入模板与抽取，**Then** 结构身份及证据坐标相同。
2. **Given** 嵌套表、合并单元格和非基本平面字符，**When** 查看抽取来源，**Then** 精确回到原文，不把合成表头或分隔符当作值。
3. **Given** 模板样例被替换，**When** 点击旧插槽来源，**Then** 显示来源失效，不跳到同名文本。

### User Story 2 - 正确归属的实体、属性和关系候选 (Priority: P1)

分析人员得到由本体定义驱动的候选；主体在标题、值在正文及同段多个主体时仍明确归属，缺少证据时拒答。

**Why this priority**: 错主体和仅凭共现建立关系会污染风险事实。
**Independent Test**: 标题主体/正文数值、A 规格 250mg/B 规格 500mg、否定/条件关系及未见类型样本完成候选生成与来源验证。

**Acceptance Scenarios**:

1. **Given** 标题药品 A，正文只有规格数值，**When** 抽取，**Then** 可生成 A 的规格候选，不要求正文再次提及 A。
2. **Given** 同段多个主体和值，**When** 抽取属性，**Then** 每个值有独立主体及绑定证据，不能复制到所有主体。
3. **Given** 两实体共现但没有关系，**When** 判定关系，**Then** 不生成肯定关系；无法唯一绑定时明确拒答。
4. **Given** 可信否定或条件表达，**When** 验证，**Then** 断言本身可通过，保留极性和条件。
5. **Given** 新增此前未支持的类和关系描述，**When** 抽取，**Then** 无需增加专用抽取算法即可提出有证据候选。

### User Story 3 - 可审核、可恢复的事实提交 (Priority: P1)

审核人员看到独立节点、逐值属性、关系及真实来源，确认后提交，并可查询实际持久化事实及完整历史。

**Why this priority**: 确认、实际入图和来源回放必须一致。
**Independent Test**: 多值候选审核、过期编辑冲突、重复提交、写入失败恢复及否定/条件断言回放。

**Acceptance Scenarios**:

1. **Given** 多值和冲突候选，**When** 审核或编辑，**Then** 不丢弃逐值来源，旧版本可回放，过期版本更新被拒绝。
2. **Given** 已确认候选，**When** 提交失败，**Then** 不报成功、不对报告发布，恢复后重试不重复事实。
3. **Given** 已确认否定/条件断言，**When** 提交，**Then** 断言本身可查询，不产生无条件正向事实，也不因没有正向边误判失败。
4. **Given** 外部档案属性，**When** 回放来源，**Then** 显示档案记录和字段版本，文档编号只证明身份匹配。
5. **Given** 实体归并，**When** 提交关联事实，**Then** 属性和边使用同一规范实体，历史版本保留。

### User Story 4 - 按实例计算缺口并受控补抽 (Priority: P1)

报告作者看到具体主体、完整关系路径和对象的缺口；补抽只针对缺口，报告使用同一已提交事实集合。

**Why this priority**: A 的完整数据不能掩盖 B 的缺口。
**Independent Test**: 错谓词、错主体、对象属性不全、开放对象集合、否定不存在和补抽无进展场景。

**Acceptance Scenarios**:

1. **Given** A 完整而 B 仅在另一关系下有设备，**When** 验证覆盖，**Then** B 的目标关系仍缺失。
2. **Given** 要求所有相关对象满足，**When** 对象发现未完成，**Then** 返回未完成，不以空集或少数对象判满足。
3. **Given** 已提交且范围匹配的否定断言，**When** 计算覆盖，**Then** 可确认相应范围不存在，但不扩大为所有对象不存在。
4. **Given** 模型不可用或补抽无进展，**When** 达到停止条件，**Then** 有界结束并保留真实缺口。

### User Story 5 - 离线运行与旧规则退役 (Priority: P1)

管理员能确认生产链路不再依赖正则、业务 finder 或隐藏兜底；关闭模型时仍有正确的服务行为。

**Why this priority**: 是已批准的最终机制替代目标。
**Independent Test**: 全链审计、旧入口禁用后的运行、未知版式与模型关闭验证。

**Acceptance Scenarios**:

1. **Given** 最终生产产物，**When** 审计代码、配置、动态入口和故障路径，**Then** 无自有可执行正则、专用 finder 或业务类算法分派。
2. **Given** 所有模型关闭，**When** 上传文档，**Then** 提供结构/预览/草稿，抽取任务显示未完成且不调用旧规则。
3. **Given** 第三方实现未审计，**When** 查看验收报告，**Then** 明确边界和残留，不宣称全栈零正则。

### User Story 6 - 可复现实测与发布门禁 (Priority: P2)

评审人员能够追踪需求、任务、测试、人工金标及性能记录，判断哪些能力已经验证。

**Why this priority**: 可运行不等于真实抽取质量已达标。
**Independent Test**: 固定数据/模型版本生成评测结果，缺少真实金标时发布门禁不通过。

**Acceptance Scenarios**:

1. **Given** 独立人工金标，**When** 比较不同上下文策略，**Then** 按类型、主体数及版式分别报告准确率、召回、拒答与成本。
2. **Given** 只有桩模型测试，**When** 检查发布资格，**Then** 不把测试通过解释为真实质量提升。

### Edge Cases

- 无主体、歧义主体、缺来源、失效坐标、跨记录值和伪造引用不得成为已验证事实。
- 同主体相反极性或互斥值、条件/时间不匹配须保留冲突或未完成状态。
- 单一对象的否定不能推广为整个对象集合不存在。
- 极性、来源、身份或范围变更使旧审核和依赖失效。
- 图部分写入、进程重启、数据库确认失败不暴露未发布事实。
- 示例报告、摘要、模板示例值不得作为生产事实。
- 历史来源无法恢复时显式标记未验证，不补造证据。
- 长文档窗口、预算、循环关系、重复补抽和外部版本变化有明确停止或恢复行为。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 在分析、模板和抽取间共享可版本化的文档结构与证据身份。
- **FR-002**: 系统 MUST 保留标题层次、分页可信度、合并及嵌套表真实坐标和原文偏移。
- **FR-003**: 模板 MUST 从已有结构生成草稿并保存每个元素的来源；替换样例使旧来源显式失效。
- **FR-004**: 模板示例、输出报告和摘要 MUST NOT 作为生产事实来源。
- **FR-005**: 系统 MUST 先形成有证据的主体，再独立驱动属性和关系任务；正文无需存在实体提及。
- **FR-006**: 系统 MUST 使用本体语义驱动通用候选召回，不因模板覆盖声明丢弃其他实体。
- **FR-007**: 属性和关系 MUST 带显式主体、竞争主体、允许范围及独立绑定证据。
- **FR-008**: 数值、单位、范围、比较符、多值及适用条件 MUST 独立保留和验证。
- **FR-009**: 可信否定和条件断言 MUST 可验证、审核和持久化；MUST NOT 直接物化为无条件正向事实。
- **FR-010**: 多跳 MUST 使用真实父实例及路径，范围扩展有依据和版本，循环及预算有界。
- **FR-011**: 缓存及恢复身份 MUST 覆盖主体/竞争主体版本、范围、分类、预算、分词器、任务和模型策略全部有效依赖。
- **FR-012**: 系统 MUST 区分文档、外部、人工和推导来源，分离身份匹配与属性值来源。
- **FR-013**: 候选 MUST 持久化独立节点、逐值属性、关系、冲突、来源及稳定版本，不能由同名文本直接合并。
- **FR-014**: 审核 MUST 使用乐观并发与追加历史；验证、审核和提交状态独立。
- **FR-015**: 提交 MUST 写入真实实例、断言与合格正向关系，支持幂等、失败恢复及来源回读。
- **FR-016**: 未成功提交的事实 MUST NOT 被默认事实查询、覆盖或报告消费。
- **FR-017**: 实体归并 MUST 更新关联主体及端点并重验冲突，保留历史快照。
- **FR-018**: 覆盖 MUST 按主体、完整关系路径、对象实例及属性归属计算，并定义存在/全部、基数和集合完备性。
- **FR-019**: 覆盖 MUST 区分满足、缺失、不存在、不适用、待审核、冲突和未完成；不存在仅由范围匹配的已发布否定支持。
- **FR-020**: 补抽 MUST 使用同一通用抽取能力，有去重、轮次、范围和资源预算，不因缺口虚构值。
- **FR-021**: 报告和覆盖 MUST 使用相同已发布事实快照和筛选规则，冻结来源和模板版本。
- **FR-022**: 最终自有生产链 MUST 删除全部可执行正则、业务 finder、业务类算法分派与隐式回退，含结构、分词、配置、前端和报告。
- **FR-023**: 系统 MUST 提供逐职责替代与残留审计；第三方内部未审计项明确披露。
- **FR-024**: 模型关闭 MUST 保持离线正常态和结构预览；依赖任务如实未完成，不调用旧规则。
- **FR-025**: 系统 MUST 沿用现有权限、离线、审计和本体保真要求，未经启用不访问云端。
- **FR-026**: 系统 MUST 提供独立人工金标、上下文消融、未见类型/版式及性能的可复现评测与发布门禁。
- **FR-027**: 历史数据 MUST 保留可读性，无法恢复来源的记录标为历史未验证，不能自动作为新契约事实。
- **FR-028**: 全部关键契约 MUST 有自动化测试和可执行端到端验证步骤。

### Key Entities

- **文档证据**：文件身份、章节与单元格、原文范围、角色、版本及诊断。
- **抽取任务**：目标语义、主体及竞争主体、上下文、允许范围、预算和依赖。
- **候选与断言**：实体、属性、关系及其值、极性、条件、绑定和来源。
- **审核与提交**：候选版本、审核历史、规范身份、幂等批次及恢复状态。
- **事实快照与覆盖任务**：已发布断言集合、主体/对象发现状态、完整路径、缺口及报告版本。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 同文档三个入口的结构及坐标一致；关键嵌套表、重复标题和字符定位案例全部通过。
- **SC-002**: 标题主体/正文值、同段多主体、否定/条件和多值关键案例零错绑、零无来源入图。
- **SC-003**: 可信否定/条件完成审核提交并可回放，不产生无条件正向事实。
- **SC-004**: 重复或并发提交不重复事实，故障恢复不误报成功，未发布事实对正式查询不可见。
- **SC-005**: 错主体、错谓词、错对象及开放集合的关键覆盖案例零错误满足。
- **SC-006**: 新发布事实来源完整率为 100%，各类真实来源可回放。
- **SC-007**: 补抽最多两轮、每轮至多一次范围扩展；模型不可用或无进展时停止并显示原因。
- **SC-008**: 自有生产代码、配置及最终产物审计不存在可执行正则、硬编码业务 finder 或隐式回退。
- **SC-009**: 仅添加本体语义即可支持未见类和关系，在隔离版式样本上满足已冻结质量门禁。
- **SC-010**: 各上线文档类型的实体、属性、关系准确率和召回达到独立金标的不回归门禁；多主体绑定改善。
- **SC-011**: 同文档桶的 95 分位处理时间不超过基线 1.2 倍且满足生产服务目标，内存不超过部署预算。
- **SC-012**: 缺少真实金标、固定模型或生产性能证据时，不得标记发布验收通过。

## Assumptions

- 以用户指定设计及本轮 P2 补充作为已授权功能边界；实施计划负责技术映射，不缩减为仅 IR 或仅原型。
- 复用现有分析、模板、抽取、审核、报告用户界面及权限角色。
- 默认离线，显式开启的本地模型作为通用语义能力；关闭模型是正常配置，任务完成状态与服务降级状态分开。
- 人工金标及真实性能结果只能由实际标注和测量产生；工程工作可以先完成工具与契约，发布门禁保持严格。
- 历史行为可用于回归比较，已确认错误行为不构成需要永久保留的能力。
