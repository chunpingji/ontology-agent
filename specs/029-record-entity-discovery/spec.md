## 1. 目标与范围

### 2026-09-19 手工测试反馈澄清

- 修正模型输入和 Harness 中重复的章节元数据、本体/主体信息；仅精简模型输入视图，不改变事实权限、声明身份、核验内容或当前状态。
- 同一章节的标题和摘要只需表达一次，记录仍各自保留定位和授权。共享可见性不构成其他任务的事实授权。
- Harness 按任务、授权原文/摘要、本体卡拆分单任务、批次及记录任务；发现阶段不再显示为核验目标，实际原始请求仍可查看。
- Word 目录跳过、短章节与相邻章节联合分析、CMCReport 编号和密级属性在本次单独评估；本次不据评估自动变更解析、调度或权威本体。
- 验收：同节多记录的标题摘要只出现一份；不同证据、角色、事实权限和核验目标保持；已保存请求不重写；原始与结构化展示对应同一次实际请求。

### 1.1 用户明确目标

1. 在一次识别中发现文档记录内的多个实体及其属性，减少逐主体、逐谓词重复读取原文。
2. 候选实体生成或补充后，推动后续关系识别。
3. 关系识别使用已发现的实体及原文证据，继续受本体约束。

实体可以先于关系被发现和核验；某条入边未证明不应阻止该实体自身的独立属性被识别。实体存在、属性归属和关系断言仍分别需要原文支持。

### 1.2 设计澄清与采用的默认判断

以下为本方案的设计选择，不冒充用户逐项确认；实施中若改变这些范围，应先回写规范和计划。

| 问题 | 本方案选择 |
|---|---|
| 识别哪些实体？ | 限于选定文档类型及本次分析目标对应的本体类型范围；不自动扩展为整个本体或任意命名实体。 |
| 批量单位是什么？ | 首期为一个完整文档记录中的多个实体和多个属性；表格保留行、表头、注释及归属上下文。 |
| 是否等全文完成才识别关系？ | 不设置全文屏障。每批可用候选形成后推进相关关系任务，与后续记录发现交错执行。 |
| “候选”是否代表事实提交？ | 原始提案待核验；通过系统核验的候选可进入本次运行图谱，仍不等于人工确认或业务事实提交。 |
| 候选事件何时生效？ | 新实体通过类型/指称核验，或已有实体增加可用证据后，推动关系调度。未经核验的模型提案不直接成为关系端点。 |
| 关系缺少端点怎么办？ | 允许对具体原文范围进行有限补发现，防止首轮遗漏永久阻断关系；不进行无界全局补扫。 |
| 旧运行如何处理？ | 当前按 031 使用新建运行验证；不迁移或重写旧制品，不为旧穷举游标保留执行分支。 |

### 1.3 不在本期范围

不增加本体类型/谓词、跨文档身份合并、任意既存实体合并、全实体两两穷举、自动业务事实提交、消息中间件、事件溯源、历史回放、历史快照、诊断平台、新模型服务或并行推理框架。暂停与继续沿用当前运行入口。

## 2. 使用场景与验收

### US-1 同一记录批量发现多个实体及属性（P1）

同一段落或表格记录描述两个不同对象，各自具有名称、编号或数值属性。一次发现提出多个实体及其属性；逐项核验后分别保留正确归属和原文。

验收：无需先证明两个对象的入边；甲的值不挂到乙，记录组成对象不被字段值冒充，属性缺证不丢弃已成立的实体。

### US-2 候选变化推动关系识别（P1）

前一批发现制剂，后一批发现活性成分及组成描述。后到候选使相关关系获得处理机会，最终根据组成原文建立有向关系。

验收：前一批缺对象时的空结果不永久关闭后续机会；单纯同文档或类型匹配不生成关系；已完成且输入无变化的工作不重复执行。

### US-3 实体成立、关系不成立（P1）

文档明确描述两个实体及其属性，但没有证据证明二者的指定关系。

验收：核验通过的实体和属性保留，关系保持未决或拒绝；不为连通图补造文档根关系。条件、否定和选择组保持原有语义。

### US-4 首轮遗漏、跨记录指称与属性补充（P1）

属性记录使用代词或省略主体；相关实体稍后才被识别。关系核验还可能发现首轮遗漏的合法端点。

验收：在对应记录和证据范围内补充识别/绑定；同名不同位置不直接合并，模糊归属保持未决，已识别实体无需因每个关系再次创建。

### US-5 暂停继续与部分完成（P1）

发现响应已保存、实体已提交或关系任务已安排时暂停，再继续。

验收：保存的有效响应不重复调用模型；候选和待办一致；逐项保留成功、技术失败、缺证及未尝试结果；未知请求结局不被当成成功或退款。

## 3. 功能需求

| ID | 要求 | 验收口径 |
|---|---|---|
| RFR-01 | 在冻结的本体和分析范围内发现实体 | 合法继承、既有类型限制及范围保留；未声明 IRI 不获授权。 |
| RFR-02 | 一次发现支持多个实体及各自多个属性 | 每项属性绑定明确主体及该类型适用属性，不能共享一份无主体区分的属性菜单。 |
| RFR-03 | 保留原文权限与记录结构 | 表头/摘要/相邻上下文不自动变成事实来源，表格合并单元与逻辑行不混同。 |
| RFR-04 | 实体可在无已证明入边时被核验与使用 | 只要求本身有效的类型、指称与适用范围证明；不继承其他实体的根身份权限。 |
| RFR-05 | 属性逐项核验归属、字段、值、单位与限定 | 一个属性失败不抹去独立成立的实体或其他属性。 |
| RFR-06 | 候选变化安排受影响的后续工作 | 新增实体和新增有效证据均能推动相关任务；重复通知不反复生成相同工作。 |
| RFR-07 | 关系候选筛选与事实证明分离 | 类型匹配、共现及相似度只提供线索；每条边独立证明端点、谓词、方向及限定。 |
| RFR-08 | 后到候选和定向补发现不被首轮结果永久阻塞 | 只重开受影响工作，保留原额度，不无限循环。 |
| RFR-09 | 原文提及、文档局部身份和关系证明分离 | 同物理提及按既有规则复用；跨位置同指独立核验；不新增跨文档身份。 |
| RFR-10 | 发现、核验和完成度逐项表达 | 未尝试、漏答、技术失败、未决和否定不混同；空候选不等于全文无实体。 |
| RFR-11 | 复用当前状态完成暂停继续 | 候选、证明和后续待办在同一提交边界生效；不靠事件回放恢复。 |
| RFR-12 | 保留真实调用成本与预算 | 物理请求计一次；拆分、重组、事件触发或继续不重置已消耗额度。 |
| RFR-13 | 保留图谱和读操作契约 | 已核验孤立节点可见；条件/否定/选择组保真；GET、刷新和切换展示不启动识别。 |
| RFR-14 | 固定条件下验证质量与效率 | 分别报告实体、属性、关系质量，覆盖、未完成率、调用、tokens 和耗时。 |

1. US-1 至 US-5 的正例及错主体、错类型、错单位、错方向、条件丢失等反例通过。
