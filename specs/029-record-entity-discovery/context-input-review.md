## 2. 是否跳过目录内容

**建议跳过已确定的 Word 目录条目的识别与摘要调用；保留来源索引和文档预览。**

必须区分：

- Word 目录是导航文本，通常为章节标题和页码，不提供独立业务事实。
- `source_catalog` 是当前任务的授权来源索引，负责把记录、证据和章节元数据关联起来。本次已去重，不能整块删除来实现 Word 目录跳过。
- Harness 展示的是实际调用。仅在 Harness 隐藏目录不会减少模型调用，也不能阻止目录被当成事实目标；应从解析角色、摘要和任务准入处理，再由 Harness 如实展示结果。

当前 [docx_structure.py](../../backend/app/services/extraction/docx_structure.py:447) 识别目录域、目录标题、样式及页码，但只修正标题层级/归节，没有把“已确认目录条目”角色持久传递给 IR。[records.py](../../backend/app/services/extraction/ontology_guided/records.py:140) 随后仍将这些段落生成记录；摘要入口也没有排除它们。

当前解析器对本地样本文档的确定性统计为 166 条记录，其中目录占 20 条（约 12%）。这是本地样本的新解析结果，不是用户当前冻结运行的覆盖数，也不等于能节省 12% tokens。

最小后续方案：

1. 持久传递已确认目录条目的块/证据角色，保留原文和定位。
2. 从实体/属性/关系发现目标、事实证据及模型摘要材料中排除这些条目。覆盖分母按可识别正文计算，不记成“模型检查后未发现事实”。
3. 不按整节标题“目录”直接过滤。合成反例已确认：目录结束后、下一标题前的正常正文可能仍归在该 section，必须保留。
4. 目录仍可参与文档导航；正文采用 TOC 样式、数字或页码类似表达时，不凭单一格式误删。

验收：有标题/无标题目录、Word 域、普通正文误用 TOC 样式、目录后的无标题正文均覆盖；目录不触发模型识别/摘要调用，正文覆盖和证据锚点不丢失。

## 3. 短 section 是否与前后段合并分析

**值得优化，但字数只应作为候选条件；先补完整阅读上下文，再判断与前段或后段的连续性。**

同一本地样本有 21 个叶 section，直接内容不超过 100 字的有 6 个、不超过 200 字的有 15 个，其中有 1 个空叶节。这些数字是描述性统计，未将阈值作为实施规则。

更明确的现有问题：合成“名称 → 物料甲”“分子式 → C10H12O2”时，两条记录的发现输入分别只有值，缺少对应标题锚点和字段绑定。直接增加字数或合并章节树并不能保证属性归属正确。当前调度按记录 × 本体类卡组进行，仅减少 section 数也不自动减少模型调用。

建议采用以下判据：

| 情况 | 建议处理 |
|---|---|
| 仅有标题或字段标签，下一段给值/内容 | 与后续正文联合阅读；标题/祖先标签作为可定位绑定上下文。 |
| 短段为前段的续句、明确指代或补充条件，且范围一致 | 可与前段联合阅读，同时保留指代/归属需要独立证明的要求。 |
| 同父级、连续字段，明确属于同一对象或表格记录 | 可形成一次多字段阅读任务；各字段仍保留原章节和原文锚点。 |
| 物料、批次、样品、阶段、条件或否定范围改变 | 保持独立；长度短不构成合并理由。 |
| 前后均可能承接、只有摘要相似或无法确定归属 | 暂不合并，不额外调用模型只为决定每个短节的归组。 |

优先顺序：补齐标题/祖先标签绑定 → 在原树和原文不变的前提下形成有边界的阅读组 → 如需减少调用，再让组成为发现任务的输入单位。此项会改变当前 029 的“单记录发现”准入与覆盖口径，应在后续明确需求后修订 spec/plan/tasks，不能当作 Harness 展示修复附带上线。

不因为联合阅读而合并实体、转移属性或扩大原来的事实权限。验收应同时看标题和值的正确归属、相邻不同主体的反例、否定/条件保持、调用数和完整覆盖，不能只比较 section 数。

## 4. CMCReport 编号与密级

**应补充这两个属性。当前权威 TTL 没有文档编号和密级。**

[CMCReport](../../ontology/slpra/slpra-drug-development.ttl:438) 继承 [RegulatoryDocument](../../ontology/slpra/slpra-document.ttl:21)。当前内存本体快照编译的类型卡有 6 个数据属性：`documentName`、`documentVersion`、`approvalStatus`、`sourceSystem`、`contentHash`、`ctdModuleNumber`。其中 CTD 模块编号表示 `3.2.S` 等章节位置，不能用作报告编号。

本次建议的最小范围限定 CMCReport：

| 属性 | 建议 IRI | domain | range |
|---|---|---|---|
| 文档编号 | `slpra-doc:documentNumber` | `slpra-dev:CMCReport` | `xsd:string` |
| 密级 | `slpra-doc:confidentialityLevel` | `slpra-dev:CMCReport` | `xsd:string` |

沿用文档元数据命名空间；不建立同义的报告编号第二套属性。如果后续明确所有法规文档都需要这两个属性，可以将 domain 定义在 `RegulatoryDocument` 供子类继承；这会扩大适用本体类型，不作为本次自动实施范围。

编号保留前导零、连接符和原文格式，不从文件名、CTD 章节号或哈希补造，不声明全局唯一，不自动作为实体身份合并键。密级保留原文，不预设企业密级枚举、排序或访问控制。当前未确认必填/单值要求，不增加最小/最大基数或 FunctionalProperty。

拟议三元组增量为新增 12 条、删除 0 条，以下仅预览，未写入 TTL 或业务库：

```turtle
slpra-doc:documentNumber a owl:DatatypeProperty ;
    rdfs:domain slpra-dev:CMCReport ;
    rdfs:range xsd:string ;
    rdfs:label "document number"@en ;
    rdfs:label "文档编号"@zh ;
    rdfs:comment "原文明确标注的文档管理编号；按字符串保留，不声明全局唯一。"@zh .

slpra-doc:confidentialityLevel a owl:DatatypeProperty ;
    rdfs:domain slpra-dev:CMCReport ;
    rdfs:range xsd:string ;
    rdfs:label "confidentiality level"@en ;
    rdfs:label "密级"@zh ;
    rdfs:comment "原文明确标注的文档保密级别；不预设枚举、排序或访问控制含义。"@zh .
```

既有类型卡编译支持本类和祖先的数据属性，无须为这两个字段增加识别器专用分支。实施应沿用已有草稿、diff、批次发布和双存储流程；发布会汇总现有草稿，需确保实际 diff 不夹带无关修改。启动播种仅补缺失项，不能以改 TTL 后重启替代双存储核验。旧文档运行冻结本体快照，新增属性应由发布后的新运行验收。

## 6. 编号短文本的属性歧义处理（追加方案，未实施）

问题：同一个编号短文本可能对应文档、设备、批次等多个主体和不同属性。继续按每个本体类型卡反复推断，既重复付费，又容易因为某种编号格式相似而错挂事实。

建议分离“字段值识别”和“主体/谓词绑定”：字段及原文先保留，归属不确定时标记歧义；只有证据支持后才生成正常属性声明并独立核验。只为确实存在歧义的字段增加定向消歧任务，复用现有模型调用、预算及当前工作状态，不新增模型服务或通用工作流平台。

### 6.1 当前可复用能力与缺口

- [ObservationProposal](../../backend/app/services/extraction/ontology_guided/claim_protocol.py:166) 已允许 `ambiguous`、`unbound`，且主体和谓词可为空，可以保留未定归属的原文观察。
- 正常 `PropertyProposal` 必须具有主体和属性 IRI；不应为了通过这个契约而猜选主体，也不把待消歧值直接塞入图谱属性。
- [observe_record_gaps](../../backend/app/services/extraction/ontology_guided/executor.py:3141) 记录的是原文缺口锚点。候选更新可通过 `discovery_feedback` 重开原记录/类卡的完整发现；当前不是字段级的专门消歧。
- 记录任务仍按记录与类卡组组合准入，lineage 包含类卡 ID，因此同一字段跨卡的调用额度也是分开的。这部分首轮重复不属于失败重试。仅让模型输出歧义标记，未在准入和跨卡去重上处理，不能消除其他类卡对同一短文本的重复尝试。
- 人工属性修复要求一个已被拒绝的现存候选；未定主体的字段不满足该入口，不宜复用其业务语义。

### 6.2 建议处理顺序

1. **补齐并识别完整字段**：尽量一次取得字段标签、值、表头/标题、所属记录以及明确主体提及。例如“文档编号：CMC-001”应作为带标签的字段读取，不能只向模型提供“CMC-001”。只有“文档编号”标签而没有值时属于缺值观察，不建立虚构属性值的消歧任务。长度和编号格式只用于候选路由，不能证明归属。
2. **在类卡扩散之前分流**：有明确主体证据的字段进入普通属性识别；存在值但缺主体/属性区分依据的字段形成一个待消歧项，不为每个“带编号”的类型各建一份同义待办。复杂记录中其他有依据的实体/属性仍正常识别。
3. **按物理字段去重**：键由本运行的文档和字段标签/值锚点确定，不含类卡或被猜测的主体。不同原文位置即使编号相同也不能合并。跨类卡观察引用同一待办，保存各自的合法候选线索。
4. **构造有界候选对**：候选为 `(已登记主体引用及修订, 合法属性 IRI)`，依据明确标签、表格/章节归属和授权上下文筛选。本体 domain/range 用来排除不合法组合，不证明某个组合成立；文档根也是候选之一，但不能默认拥有文档内所有编号。
5. **定向消歧**：将同一字段的候选对和最小充分原文放在一次比较任务中；无需分别请求每个候选。回答允许“有证据的归属”“仍有歧义”“没有合格候选”。候选过多时先补上下文/缩小范围，不能按分数任意截掉候选后宣称唯一。
6. **复用正常独立核验**：消歧成功只是产生带证据的属性提案。主体绑定、字段标签与值、属性合法性、否定/条件及范围仍经现有核验；未决值不入事实图谱，也不参与关系推导或身份合并。

例如，只有“编号：001”时应保留值及其位置并标记归属待定。后续发现该字段属于当前报告的封面元数据，且原文有报告名称/编号归属支持后，才提出文档编号属性。若原文实际是附件设备表，编号应归于有证据的设备；同处一个报告不构成归文档根的理由。

### 6.3 资源上限与唤醒条件

- 同一字段及相同相关输入，只消歧一次；换类卡、排序、提示措辞或 Harness 展示不构成新证据。
- 相关输入包括字段/上下文锚点、候选主体修订、允许属性及有效归属证明。只有这些内容的实质变化才可唤醒，不因任意新实体或候选列表重排而重试。
- 建议首轮一次定向消歧、补充相关证据后至多一次自动再试；明确沿用已有总请求预算，不以重开待办领取新额度。成功后的独立核验调用另行计入预算，不混称为“只调用一次模型”。
- 原文读取、候选检索及确定性校验优先于 LLM；必要模型调用使用有界回答和输出预算。仍无依据则保留未决及所缺信息，文档其余工作继续。
- 在既有当前工作状态中只保留这一个字段待办、相关输入签名、尝试额度和最新结果引用；原文及模型结果继续沿用原有制品，不建立第二套历史存储。

### 6.4 本体缺口必须与歧义区分

当前 CMCReport 缺少文档编号属性。如果原文明示文档编号，而允许本体没有对应属性，应标记为“本体缺少可用属性”，不能不断尝试设备编号、批号等其他 IRI。补充本体定义是此例的前提之一；新本体版本应由新运行使用，旧冻结运行不能静默改用新本体。

Harness 建议单独显示“待消歧属性”：原文字段与值、候选归属、歧义原因、所缺上下文、处理结果。未决需与错误、否定事实和已验证属性分开统计。

### 6.5 验收条件

- 同一编号字段出现在多类卡的分析范围内，只产生一个消歧待办；无新相关证据时不重复调用。
- 文档编号、批号、设备编号具有相同格式甚至相同值，仍按实际主体分别归属。
- 两个同样合理候选、标签缺失、仅凭相邻或同文档时保持未决，不靠最高分强选。
- 有效标题/表头/主体证明补齐后可定向处理，无关实体变化不触发。
- 本体缺属性时明确报告缺口，不转用其他编号属性；编号不自动成为全局身份键。
- 对照同时统计调用数、输入/输出 tokens、耗时、错误归属率、已解决与未决字段数；不能把未决排除后宣称准确率提升。

本节是针对用户问题的设计建议，没有实施新的消歧任务、修改识别调度或启动模型。若进入实施，应先将字段级输入、当前状态、预算及验收契约补入 spec/plan/tasks。
