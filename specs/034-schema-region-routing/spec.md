## 问题与目标

当前记录发现先把根类型四跳内的全部类型按 IRI 分成完整执行卡，再对每个阅读组选择执行卡。
运行 `87219d4b-f49e-4e80-8737-3f258eb7cbfa` 中，137 个类型形成 35 张卡，
107 个阅读组形成 214 个待生成组合；开始约 29 分钟后仍有 209 个组合待处理。

MVP 从根类型的一跳关系生成轻量 Routing Schema Card，先用冻结的章节标题、路径和摘要定位区域，
再在命中区域内选择完整 Execution Card。目标是减少语义编码对象、发现组合和生成调用，同时保持
物理原文、证据权限、合法本体范围和独立核验不变。

首版只减少候选，没有减少同一区域内的模型执行次数。运行
`09a85be4-d109-4339-beb9-b107550fc7a7` 在 2026-09-20 03:47 UTC 的快照为：运行中、
识别阶段，已尝试 28 个任务，已发生 35 次模型调用且另有 1 次在途；计划 263、已检查 6、
未完成 22、未尝试 235。47 个 routed group 全部选中 2 张卡，仍形成 94 个普通任务，另有
64 个属性字段任务。发现平均约 91 秒、核验平均约 169 秒，排队平均约 0.03 秒；已保存响应中
reasoning JSON 约 638 KB，占响应项体积约 82.6%。因此性能 v2 必须减少模型调用及单次输出，
不能把继续收紧 embedding 或排名当作主优化方向。

## 用户场景与验收

1. 新文档分析运行从根类型的正式关系构造路由卡。每张卡包含关系标签、定义、方向、正式 range
   类型、该分支可达类型标签及冻结词汇；下游类型只用于元数据区域检索，根层实体发现的
   Execution Card 只包含该关系的直接 range，完整属性、基数、单位和身份约束仍在执行卡中。
2. 路由卡只与 `MetadataSnapshot` 的标题、路径和摘要匹配。命中结构节点没有直接记录时，确定性地
   解析其后代记录；空叶节点可解析最近的同父相邻事实节点。元数据命中不授予事实，也不证明关系。
3. 普通正文在同一 section 内按连续物理顺序合批。新冻结运行最多 8 条记录、1200 字符；合批
   不跨 section、不跨表格或被表格打断，每条物理记录和 evidence anchor 原样保留。首版曾改为
   4 条/800 字，但 `09a...` 中阅读组由 52 增至 60，任务数量反而增加，因此恢复原分组。
4. 表格继续每批最多 4 个连续数据行。已被首个表格批次吸收的明确表前说明不再生成普通发现任务。
5. 命中区域只执行对应根关系的直接 range Execution Card；每张源卡仍受类型数和实际输入
   token 上限约束。多直接 range 可按 class IRI 合并为一张确定性区域执行卡，同类定义冲突时
   拒绝合并；模型每个区域只执行一个根层发现单元。发现实体后，再从该实体的局部菜单遍历下游
   关系，不把下游类型提前混入根层类型判断。
6. 路由结果、候选执行卡和范围哈希进入当前工作状态；暂停继续不得重新付费或改变已冻结范围。
7. 未命中区域记为 `unrouted` / `unattempted`，不得解释为无事实。明确的下游类型缺口仍可通过现有
   有界反馈机制补入一张遗漏的 Execution Card。
8. 用运行 `87219d4b-f49e-4e80-8737-3f258eb7cbfa` 的 214 个普通候选组合作基线，并用运行
   `8d1cdc6f-e349-435e-a3fa-9b4ffdc39d12` 验证新路由、真实模型调用、暂停继续和公开 API。
9. 核验回答中每个 facet 的 `reason` 最多 160 字，依据仍由逐字 `support` 提供，避免解释文字
   挤占结构化回答预算。该限制不减少必需 facet、证据引用或独立核验目标。
10. 确定性定位的属性字段随所属区域一起提交，模型只判断主体归属和合法谓词，值解析继续由
    服务端完成；新运行不再为这些字段另建 64 个 `attribute_disambiguation` 任务。
11. 新运行默认 `reasoning.effort=none` 且 `chat_template_kwargs.enable_thinking=false`，
    发现阶段最多输出 8192 token，核验阶段按 2026-09-21 用户要求提高到 16384 token，
    总上限仍作为保护。核验 JSON 截断时先保存
    已付费响应，再按 target/member 拆分，
    不重新执行发现阶段。
12. 每条 lineage 最多 6 次模型调用；一次已完成任务最多因下游缺口重新打开 1 次。恢复继续沿用
    冻结计数，不因拆分、重启或换卡重置额度。
13. `record-entity-first-v1` 管线不向模型提供 `propose_mentions`。Schema 区域请求已经携带授权原文，
    实体及记录组成由生成模型直接提出逐字引用；GLiNER 边界工具只保留给非 record 路径。工具
    `no_match` 不得解释为区域无实体或全文否定。新运行不冻结或初始化 `gliner2`，Harness 也不再
    显示不适用于当前管线的 GLiNER 启用状态。record 适配器初始化时拒绝注入任何
    `mention_extractor`；record 工具分派器即使收到错误配置，也必须拒绝 `propose_mentions`。
14. 记录实体发现首轮不提供工具，直接返回结构化实体、属性和逐字引文；关系阶段
    仍可使用已授权的锚点、共指和图验证工具。
15. 执行卡的直接类型数超过 `max_classes_per_card` 时，首轮仅识别实体，输出 Schema 限制
    `properties.maxItems=0`；实体核验通过后再由局部菜单调度属性和关系。未通过阶段 Schema
    的回答不重放进纠错上下文。
16. 区域发现并核验通过的实体和属性可以先进入当前工作状态；孤立实体仍编译局部属性菜单，供明确的
    人工属性修复使用。在一条精确入边成立前，不为该实体自动调度下游关系，避免子实体关系抢在
    `CMCReport` 根关系之前读取相同原文。
17. record 关系若被事实来源、端点 range、桥接证据或确定性图校验拒绝，直接保留为
    `incomplete` / `undetermined` 并推进下一原文或端点页，不以 evidence recovery 或
    reproposal 再次发送同一原文。JSON 和外层 Schema 无法解析时仍允许一次结构纠正。
18. 核验拆批状态是当前权威工作状态的一部分。每批独立保存 target 集合、尝试次数和结果引用；
    单次只允许一个合法状态转换。非法回退、改写 target 或未引用结果由 `HeadConflict` 拒绝。
19. record 关系输出 Schema 的 `object_ids` 只枚举当前主体之外的已登记端点。当前主体不得作为
    自己的对象；没有端点时 `relations.maxItems=0`。`predicate_support` 至少包含一条
    `fact_eligible=true` 的完整关系句，可与 `bridge_support` 复用，辅助标题不能单独充当谓词证据。
20. record 关系的 `relations.maxItems` 不超过当前登记对象数。同一主体、谓词、对象集合、选择和
    限定条件只允许一条候选；不得按 evidence 单元复制同一关系。
21. 每个批成员最多使用一次回答结构纠正。纠正后仍不满足 JSON/Schema 契约时结束该成员；模型
    输出截断后的成员/target 拆批继续使用其独立的持久批次状态。
22. entity-only 区域发现得到的实体，只有在一条精确入边通过完整证明门后，才自动调度其尚缺的
    局部属性；已存在有效属性不得重复调度，也不必等待其他无关根关系全部完成。

## MVP 边界

- 复用 `RankingService.discovery_embeddings`、现有本地权重、当前状态和完整发现/核验执行器；
  不新增模型、数据库表、HTTP 接口、历史快照或外网依赖。
- 根文档自身属性保留在封面/制品元数据责任域，不把文件名或摘要当作属性事实。
- 实体及其属性可在根入边尚未成立时保留；关系仍需独立、可定位的原文证明。
- 相似度、章节命中、相邻和共现只提供检索准入，不能证明实体合并、关系方向或主体归属。
- 本期不修改 SLPRA TTL。`CMCReport describes` 当前正式 range 只允许 `DrugProduct`，因此原料药
  文档的 CMCReport→API 根边可能无法成立；实现必须报告该本体限制，不能暗中扩大 range。
- 本期保持单运行一个活动识别单元。`recognition_inflight=1` 与单一 `active_unit_ref` 仍是实际
  执行契约；双并发须同时改造预留、检查点、暂停取消和恢复，不能只修改配置值。

## 成功口径

- 定向测试证明关系分支范围、空结构节点解析、区域准入、同节合批、表前说明去重和恢复一致性。
- 固定影子计划的普通发现组合少于当前 214，且没有把未路由区域标成已检查或否定。
- 每个实际模型请求继续使用现有完整 `RecordDiscoverySchemaCard`，Routing Card 不进入事实核验。
- 超过4个竞争类型的记录首轮请求不生成属性；不超过阈值的卡仍可合并实体与属性。
- 根关系路由卡保留下游类型用于区域匹配，但根层执行卡完整覆盖全部直接 range 且不含更深类型。
- 同一区域多张源 Execution Card 只形成一个执行单元，属性字段不再形成独立模型任务。
- record 管线的模型工具列表不含 `propose_mentions`，适配器不接受边界提取器，工具分派器也不能
  绕过工具列表调用该工具。
- 请求冻结值为 8 条/1200 字、reasoning none、thinking false、发现 8192/核验 16384、
  lineage 6、反馈重开 1。
- record 关系的服务端语义拒绝不产生第二次 discovery；解析失败的结构纠正仍受预算约束。
- record 关系 Schema 不向 `object_ids` 暴露当前主体，且无登记端点时禁止输出关系。
- record 关系不能按证据单元复制同一端点关系，结构纠正最多一次。
- 未证明入边的实体不产生下游关系计划，但保留已核验属性及人工属性修复菜单。
- entity-only 实体的精确入边成立后可生成缺失属性，已有属性不重复执行。
- Ruff、受影响 pytest 和 `git diff --check` 通过；工程验证、影子计划和真实模型质量评测分别报告。
- 另建新运行测量调用数和墙钟时间；`09a...` 只作为首版失败基线，不用代码推算冒充性能提升。

## 文档驱动候选发现增补（2026-09-21）

本节承接[基础方案第 7.5 节](../../docs/基于本体指引的文档结构和摘要元数据的关系图谱识别方案.md)，
沿用本体限定范围、原文证据和已登记关系端点；实施与实证状态见任务清单，不变更历史验收结果。

- D1：同一原文区域可服务多个合法识别目标。先批量发现实体和属性、核验并登记端点，再基于
  同区域原文批量提出合法关系；不以每一条虚拟关系分别启动重复实体发现。
- D2：实体、属性和关系逐项判定，保留各自的原文、主体归属、范围、极性和条件；一个成员通过
  不意味着整个区域通过。未核验的新端点不能直接参与关系事实，孤立实体不提前展开下游关系。
- D3：同源已有结果可复用；缺项只驱动必要补查。未路由、未检查、技术失败、合法空结果和
  语义否定分别展示；原文相邻、共现、摘要或相似度不得直接使关系成立。
- D4：虚拟目标清单包含未找到候选的项，关系/属性完整度与执行覆盖分开；多值项只找到部分
  成员不能算完成。没有新来源、端点或证据时，不为同一缺项重复发送发现请求。
- D5：实施后在用户指定的 CMCReport 文档 `upload-a255fd30-192c-4f81-92df-5f76a56b8383`
  新建运行，报告实线证据、虚线原因、漏识别与未评分项，以及发现/核验调用数和耗时；不把
  工程测试、图谱非空或处理结束当作质量与完整度达标。

本规范负责区域执行侧，`/analysis` 外层“图谱分析”入口及实虚线展示由基础方案第 13.4 节定义，
不在此重复建立一套运行或存储。复用当前模型和管线，不增加 Semantica 运行依赖或自动本体修改。

## 实证问题修复与主服务验收（2026-09-21）

用户确认按以下优先级修复后部署主服务；所有新增规则必须依据通用证据协议和冻结本体，
不得新增报告类型、药物类别或特定字段 IRI 的分支，不修改权威本体以迎合文档结果。

1. 派生执行卡只登记实际采用的投影。未选投影不影响冻结卡集合，已消费投影仍保留必要的
   重建配方；来源、类型、卡 ID 和范围哈希继续严格核对，缺失/篡改必须拒绝。
2. 发现和核验明确区分事实授权单元与仅供定位的上下文。引用必须非空，完整字段的缺失标记
   保留为缺失观察，不能当作实值。传递并核验本体类型定义、字段角色和身份约束；名称或
   项目归属不自动证明唯一身份，同名不自动合并不同类型/层级的实例。
3. 每个新确认且已持久化的模型回答更新执行进展时间，包括拆分核验的中间回答；心跳、
   预约和重复回执不更新。执行进展不增加事实完整度。停滞导致的模型取消必须如实分类。
4. 主服务启用新图谱分析入口和修复，并在新运行核对实体登记、关系、实线及属性原文。
   真实多谓词合批、全文范围和完整度增长分别验收；未经实际完成，不报告质量或速度改善。

新主运行的实证追加验收：类型核验不得由属性 domain、属性菜单或共有字段反推类型，
必须核对冻结定义的关键限定；缺证保持未决，不能改写本体定义扩大类型。全文表格范围
不能默认排除所有首行：显式表头优先，具有明确数据行结构的首行参与事实识别；不确定
表保留保守范围，不通过放宽上下文事实权限补救。规则不得依赖报告名、表序号或领域词。

## 第二阶段：Schema 对齐与原文采信（2026-09-21，用户批准实施）

新文档运行默认启用 `evidence_review`。按区域/候选先发现再独立核验，无需等待全文第一阶段完成；
保留实体独立展开合法下层的能力，未采信上层关系不得阻断下层识别。候选阶段既有运行不修改冻结策略。

- 先从原文识别并登记实体，再围绕已登记主体的冻结 Schema 菜单发现关系和属性候选。
  属性不再由缺失字段清单驱动全表补造；没有合适谓词的观察保留为待对齐，不编造 IRI。
- 核验使用本次冻结本体的定义、主体/对象范围、方向、属性语义、原文值、否定与条件。
  逐项结论分为采信、待定、未采信；技术未完成与证据不足不能当作否定事实。
- 高可信判断以源证据与语义对齐为依据，不采用未经校准的模型自报概率阈值。
- SHACL、数值格式/表示及换算诊断独立保存，不是原文属性采信的硬门。原文值、原文单位
  与规范化值、规范化单位分开；只有规范化成功才有可用规范值。缺单位、范围值或格式问题
  不丢弃已明确归属和字段语义的原文值，不取范围端点冒充标量。N/A 保持缺失标记。
- 非空、真实、授权的原文引用、合法本体 IRI、当前实体引用/版本、主体归属仍是采信边界。

  现有发现/问题记录，不制造可用图节点、关系或来源引用。
- 图谱采信关系为实线，待定为虚线；未采信默认隐藏，可切换并查看理由。隐藏只影响展示，
  不缩小本体目标分母。否定、条件、备选组不得显示成无条件肯定事实。
- 复用现有当前工作状态、模型回执、候选身份与原文选择器，不添加回放状态或数据副本。
  新阶段默认启用，暂停继续不重发已确认发现；GET/刷新/筛选不触发模型任务。
- 工程验收覆盖：原文范围值+decimal Schema仍保留采信原值，SHACL失败不改变源结论，
  N/A/错源/错主体不采信，未采信理由保留，单位换算显示不混配，孤立实体下层与属性可探索，
  单/批次持久恢复不重复调用。主服务新运行区分真实阶段结果、工程测试和全文质量评测。

## 联合候选与组合证据（2026-09-21，用户批准）

本节覆盖第二阶段先登记实体再发现关系/属性的顺序限制；默认阶段仍为 evidence_review。

- 同一授权区域共同发现实体、属性和关系；关系可引用本轮实体或已登记实体，属性候选
  不以 SHACL/规范化通过为前提。端点身份失败仍阻止关系采信。
- 结合两端属性原文、谓词标签/定义、表头行列及主体归属联合判断，输出谓词必须来自当前
