# 实现计划与内部契约

宪章核查：不改权威 TTL、数据库结构、业务事实接纳、证据授权或公共 HTTP 契约。复用一份当前
工作状态和现有排名缓存，不增加历史回放状态。运行时不出网。

## 数据流

1. `compile_schema_region_routing` 从根类型的正式一跳关系开始，在既有 hop / focus-path 范围内计算
   每个根关系分支的可达类型。它产生轻量 `RoutingSchemaCard` 和 `route -> class scope`。
2. 每个分支的可达类型仅扩充路由文本；根层执行范围取正式关系的全部直接 range，并按现有类型数
   和输入 token 门槛编译成完整 `RecordDiscoverySchemaCard`。相同直接 range 集合只保存一张
   执行卡；路由卡只引用这些执行卡 ID。发现直接 range 实体后，下游关系从该实体局部菜单继续。
3. `build_section_paragraph_groups` 合并同 section 连续段落；新冻结路由策略将普通组限制为 8 条、
   1200 字。表格 lead-in 在普通段落合批前排除，再由首个表格批次拥有。
4. `RecordSearch.prepare` 一次编码 Routing Card、Metadata Node、Execution Card 和阅读组文本。
   先选每条关系的前 N 个元数据区域，再把区域解析为物理记录集合，最后只在该区域获准的执行卡中
   使用该根关系的直接 range 卡。确定性模式执行相同的两阶段词项匹配；多直接 range 源卡合并
   为一张确定性区域执行卡，不再对下游类型分片做组内 Top-K。
5. `RecordSearch.rows` 持久化已选择区域、准入原因、剩余执行卡和未路由状态；`scope_hash` 覆盖
   路由卡、元数据 dependency hash、阅读组、执行卡和策略。恢复时对同一哈希严格校验。
6. 执行器只把合并后的完整执行卡传给模型，并把所属区域的确定性属性字段放入
   `property_fields`；发现、独立核验、关系发现和有界反馈继续使用现有证明门。
7. record 管线直接使用请求中已提供的授权原文，不暴露 `propose_mentions`；非 record 路径继续按
   既有能力使用边界模型。服务端同时在工具清单和分派权限处拒绝 record 管线的该工具调用；新
   record 运行的冻结策略删除 `gliner2`，因此也不构造词表或边界模型实例。

## 性能 v2 实施顺序

1. **区域级批量发现。** 保留最多两张源卡的路由选择，但按 class IRI 合并为一个执行卡；搜索
   状态保存 `source_card_ids` 和 `execution_card_id`，冷恢复重建并核对确定性 ID。
2. **属性字段并入区域调用。** 字段卡附着到所属阅读组，不再从普通区域删除 exclusive field，
   新运行不生成独立字段 slot；旧冻结运行仍按其已保存模式恢复。
3. **恢复 1200 字/8 条。** 撤销 800 字/4 条的新默认，避免把同一区域切成更多阅读组。
4. **关闭 thinking 并分阶段限制输出。** 冻结 `reasoning={"effort":"none"}` 与
   `chat_template_kwargs={"enable_thinking":false}`；发现为 8192、核验为 16384 token，且不超过
   总输出上限。容量估算和实际 Responses 请求使用同一阶段上限。
5. **限制重复修复。** lineage 上限 6 次，反馈重开上限 1 次；截断核验按 target/member 拆分，
   已完成发现不重做。
6. **最后评估双并发。** 前五项通过新运行计时后再决定。当前执行器同步等待单个调用，只有一个
   `active_unit_ref`；实施双并发需要一起修改预留、协议检查点、暂停取消和恢复。

## 关键选择

- 区域匹配以 metadata node 为单位，事实请求以物理 record 为单位，避免把摘要变成证据。
- 空节点先取全部有记录后代；无后代时只取最近的同父事实兄弟，距离并列时按文档顺序。
- 普通段落只在同一 section 的连续 run 内合批；容量超限切批，单条超限保留独立任务。
- 路由卡列出冻结本体词汇，但执行范围以 IRI 集合为准，标签冲突不影响准入。
- 路由召回范围与根层类型判断范围分离：前者包含可达类型，后者只含正式直接 range。
- 路由阈值与每关系区域数、每阅读组执行卡数分别冻结；不设置失败时全量扫描的隐式回退。
- 核验 JSON Schema 将 facet `reason` 限制为 160 字；逐字证据继续放在 support 字段，减少大组
  回答被解释文字挤占后截断的概率。
- 标准 `reasoning.effort=none` 不会自动关闭当前 Qwen/llama.cpp 模板的 thinking；非标准模板参数
  作为冻结请求的一部分进入容量计数、请求哈希和恢复校验。
- 类型选择数超过既有每卡4类阈值时，先做实体-only NER；这避免在主体尚未成立时生成
  大量属性。通过核验的实体沿用现有局部菜单继续属性和关系识别。
- 阶段回答解析失败时，已付费回答仍持久化；纠错请求从原始授权输入和简短错误重建，
  不携带无效的大段助手正文。
- 阶段输出上限用于控制延迟和截断面，不裁掉 Schema 必填字段；超过核验上限时通过确定性拆分
  完成各 target，不把不完整 JSON 送入事实门。

## 兼容与启用

`SchemaRegionRoutingPolicy` 作为 `RecordDiscoveryPolicy` 的可选冻结字段。旧冻结策略缺少执行模式时
沿用 `per_card` / `separate`；新文档运行由 `freeze_tool_engine_policy` 写入
`region_batch` / `region_batch`。恢复只读取运行自身冻结值，不静默升级在途运行。

- 执行器：表前说明不重复、物理来源不丢、暂停继续不重复模型调用。
- 区域执行：多张源卡合并一次发现；属性字段随区域请求；截断核验拆分且不重复发现。
- 类型范围：父类与多个下游类同属一个路由分支时，根层请求保留全部直接 range，且不会因分片
  Top-K 丢失父类；record 请求的工具列表没有 `propose_mentions`。
- 预算：实际 transport 收到发现 8192/核验 16384、reasoning none 和 thinking false，后两者与
  反馈上限一起进入冻结策略。
- 真实运行：将 `8d1...` 迁移到新策略，对照 `87219...` 的 214 个普通候选组合，验证路由统计、
  模型调用、证据拒绝、覆盖守恒、暂停继续和公开 API。
- 性能复验：必须新建运行使用 v2 冻结策略，记录模型调用、阶段耗时、首结果及覆盖；不修改
  `09a...` 的冻结状态，也不把单元测试通过当作真实提速结论。

   合批必须同时核对来源角色和各目标授权，不能简单取权限并集。

   关系缺证据时也不无条件重发同一原文；新增证据后的补查遵守既有预算与事实来源契约。
5. 将目标满足状态、成员实证数量及范围核对状态提供给现有展示投影，计算规则以基础方案

上述顺序保留当前端点登记门和根入边顺序。批量候选提出只是执行组织变化，语义拒绝不会因
其他同批成员成立而放行；原文证据门、暂停继续和跨运行隔离仍使用现有契约。
