# Feature Specification: 报告输出语义化

**Feature Branch**: `020-report-output-semantics`
**Created**: 2026-09-06
**Status**: Implementation
**Input**: 实现[报告模板特性的输出语义化重构](../../docs/报告模板特性的输出语义化重构.md)，包括 OS-01～OS-13、AC-01～AC-40 和 R01～R04。

## Clarifications

### Session 2026-09-06

依据需求 §21 已决策事项完成歧义扫描，无需重复提问。章节/分组保留；绑定定位数据，输入提供类型契约，输出只消费授权输入；正文冻结与后续签署分离。旧语义不能证明等价时产生待处理问题，不能自动批准迁移。真实来源、规则/声明审核、独立模型质量和部署性能是需实测的发布条件，不能由 fixture 代替；缺数据不阻止协议、诊断与布局实现。

## User Scenarios & Testing

### User Story 1 - 编写有明确数据契约的模板 (Priority: P1)

作者在保留章节/分组的前提下，分别编辑输出的数据绑定、输入项和呈现，共享输入可复用。

**Independent Test**: 用合法新业务类配置对象描述和记录表，检查类型、路径、共享引用和依赖循环。

**Acceptance Scenarios**:

1. **Given** 固定本体定义，**When** 配置未知属性、错误方向/定义域或把关系当字符串，**Then** 定位并阻止发布。
2. **Given** 多处共享输入，**When** 改名或移动输出，**Then** 稳定引用和取值不变；被引用定义不能静默删除。
3. **Given** 循环或多主体，**When** 检查模板，**Then** 报出循环路径或要求明确范围，不取第一项。

### User Story 2 - 冻结证据并生成可追溯内容 (Priority: P1)

分析人员选择来源和主体，查看同次运行的输入、缺口、正文及下载，每个记录/单元格可追到证据。

**Independent Test**: 用已发布证据生成运行后改变模板/来源，再访问旧运行，内容与来源保持不变。

**Acceptance Scenarios**:

1. **Given** 同名不同设备及多个计划，**When** 投影，**Then** 仅按明确身份与关系连接，保持记录键和缺失格。
2. **Given** 规格冲突而编号有效，**When** 只引用编号或显示整表，**Then** 编号可用，表格保留冲突格且阻止正式用途。
3. **Given** 候选、开放集合、0、false、明确不存在，**When** 校验，**Then** 区分各状态，部分数据不满足全量要求。
4. **Given** 模型关闭或输出错误，**When** 行文，**Then** 确定性单元仍可用，辅助单元失败或使用已声明备用，材料状态不被篡改。

### User Story 3 - 验证条件与逐声明前提 (Priority: P1)

审核人核对条件定义、断言关联、参数范围及每条规则输出的成立证据；计划不会成为已实施，未触发不会成为低风险。

**Independent Test**: 检查 TRUE/FALSE/UNKNOWN、错主体/时间、只有计划和缺确认记录的反例。

**Acceptance Scenarios**:

1. **Given** 条件证据缺关联或求值证明，**When** 消费，**Then** 保持未完成；只有范围一致的 TRUE 可受限投影。
2. **Given** 共线数据但缺设备确认记录，**When** 执行 R-RA2，**Then** 不输出“均有效”；未发布/禁用/未审规则和非法等级不进入合格决定。
3. **Given** 条件依赖自身激活关系，**When** 发布，**Then** 拒绝自证循环。

### User Story 4 - 固定正文审核与独立签署 (Priority: P2)

审核绑定确切正文，签署人重认证后对固定内容签名；签署形成新封装而不改正文或输入。

**Independent Test**: 固定内容、审核、并发签署、重复请求、封装失败恢复及撤销，检查历史和各层 hash。

**Acceptance Scenarios**:

1. **Given** 角色位置，**When** 签署，**Then** 身份来自服务端，名册或客户端布尔声明不能充当认证。
2. **Given** 并发或幂等键冲突，**When** 追加，**Then** 拒绝覆盖；同请求重放原记录。
3. **Given** finalizing/sealed 会话，**When** 追加或恢复封装，**Then** 拒绝追加，恢复复用冻结签署；改变正文创建新版本和新会话。

### User Story 5 - 迁移并退役隐式执行 (Priority: P2)

作者审阅原模板/规则与目标草稿差异，每个旧字段有映射或问题；历史报告可读，新执行不依赖标签/finder/正则或回退。

**Independent Test**: 基准 32 项全登记，3 节 6 组及 origin 保留，七风险列进入同一记录表，未知占位符保持问题。

**Acceptance Scenarios**:

1. **Given** v18 和旧规则，**When** 迁移，**Then** 原 hash 不变，未解决语义不发布，启动 seed 不原位改规则。
2. **Given** V2 或未知协议，**When** 旧客户端保存，**Then** 拒绝而非丢字段。
3. **Given** 未见类/编码/布局，**When** 加合法声明，**Then** 通用执行无需新业务算法。

### Edge Cases

多来源版本冲突、重复项身份错误、未知守卫与未选分支、条件自证、预算超限、样式替换、排队后修改来源、原子工件中断、默认来源缺快照、名单未签署、样例肯定句、工作流不可用及并发修改已发布定义。

## Requirements

### Functional Requirements

- **FR-001**: 保留组织身份/顺序/origin，每个输出一次；注册表和稳定引用是唯一规范定义。
- **FR-002**: facts/context/workflow/derived 均有已注册语义、类型、版本、范围及完整依赖；拒绝未知 provider、循环和任意业务载荷。
- **FR-003**: 完整有向路径、规范身份、适用范围、发现完整性和来源版本共同决定取值；标签仅展示，正式值必须已发布。
- **FR-004**: 支持精确小数、日期/年月、枚举、数量、范围、实体、记录与列表；逐值保持类型、状态、来源。
- **FR-005**: 按需求 §7.5 保留全部 issues、字段/祖先约束、UseResolution 和报告阻断集合；显示策略不能豁免必需材料。
- **FR-006**: Coverage 合并必需输入、规则/条件参数、有效消费和独立完整性；未知分支不免除要求，未选分支不误阻断。
- **FR-007**: 条件定义/审核关联/三值求值独立冻结，只有同范围完整证明可受限投影，不改 positive_eligible。
- **FR-008**: 冻结精确发布启用且审核过的规则修订，逐声明验证前提；FALSE/UNKNOWN/计划不推出低风险、已实施或可接受。
- **FR-009**: 通用派生使用有限结构化操作，按稳定键连接且保留 lineage；拒绝脚本、SQL、回调、正则。
- **FR-010**: 支持 composed/assisted、table/form/list/static；关键值和合格声明用稳定引用，辅助行文验证授权与引用并保留审核门禁。
- **FR-011**: compile→bind→freeze sources→resolve→validate→freeze inputs→render→assemble 形成唯一运行；预览和下载固定相同 AST，重放不生成。
- **FR-012**: revision/hash 乐观并发、幂等、权限、审计和原子工件登记；快照、已完成结果及已发布定义不可变。
- **FR-013**: 正文执行/材料/审核三轴独立；正式用途同时满足材料、审核、签署及工件条件。
- **FR-014**: 正文固定后独立会话/CAS/签名/事件/快照/封装，按服务端身份逐账户重认证，撤销追加、历史不变。
- **FR-015**: 32 项及逐规则/声明迁移全登记，原 schema/hash 保留，无法证明等价的业务语义不得静默转成完成。
- **FR-016**: 编辑器提供绑定/输入/输出、共享影响、合法属性、状态/证据、三类预览、固定内容签署；未知协议拒绝保存。
- **FR-017**: 老报告/覆盖/预览入口转统一服务；读详情不创建来源；V2 无旧链回退，历史只读保存工件。
- **FR-018**: 按需求 §18 完成全自有生产、配置、动态故障及最终包退役审计；第三方内部单独登记。

### Key Entities

模板家族/修订、Binding、Input/ResolvedInput、OutputUnit、SourceBundle、ReportInputSnapshot、条件定义/关联/证明、规则修订/ClaimEligibility、输出结果/AST/工件、正文版本/审核、签署会话/签名/事件/快照/封装、迁移台账。

## Success Criteria

- **SC-001**: AC-01～AC-40 全有执行证据或明确未满足的发布条件，固定验收中错主体/路径、无来源值、伪签名/日期和无依据结论为零。
- **SC-002**: 关键引用/逐值来源及 32 项迁移登记覆盖率 100%；原版本可回放。
- **SC-003**: 同一正文/封装预览和下载业务内容、顺序、引用一致，重复下载不调用模型。
- **SC-004**: 独立行文样本及短/中/长、多来源、记录/重复预算按需求 §20.3 实测；p95 不超过同配置基线 1.2 倍。
- **SC-005**: 全部自有生产及打包入口旧机制计数为零后才宣称完全退役。

## Assumptions

复用现有角色、离线部署、证据审核/提交和本体发布。真实业务语义由授权审核人确认，自动迁移只生成可审阅草稿。保留用户需求与评审稿改动。代码验证、真实数据、人工语义审核、部署发布验收分开记录。
