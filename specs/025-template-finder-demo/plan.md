# 实施计划

技术依据：[实施方案](../../docs/模板级Finder图谱演示实施方案-20260914.md)。

1. 固定契约和空绑定，移植隔离 Profile/Finder、来源及只读本体适配。
2. 复用 ExtractionJob / AnnotationExecution，独立 worker、缓存及 API 门禁。
3. 共享 Finder 前端容器，接入模板页和报告中心。
4. 定向测试、静态和类型检查；目标材料就绪后执行实际绑定与验收。

宪章：无新表/第三方依赖/本体修改，无候选/事实/报告写入。旧算法例外仅指定模板展示域，普通退役门禁保留。用户已有改动不覆盖。

页面切换扩展：在现有模板表增加两个可空字符串字段存储显式引擎和 Finder profile（迁移 0041）；空值保留原文件绑定行为。独立 GET/PATCH 配置接口复用角色、审计和条件更新；配置不进入 schema_json / schema_hash。模板详情页共用选择组件，保存后刷新模板及报告识别上下文，编辑中的报告结构保持原样。定向验证双向切换、非法配置、权限、并发、缓存和无隐式执行。

## 报告兼容实施计划

用户已批准补充方案。先固定[报告兼容契约](report-compatibility.md)，再完成 Finder 只读选择/投影与 Mock 记录加载、Slot 语义分析与编辑、共享预览与输出，最后执行定向测试及指定模板真实验证。报告数据只进入既有输入包；识别 worker 和正式事实流程保持原域。

宪章复核：复用 V2 编译/类型值/渲染、当前 Finder 授权与最新结果，不扩展历史回放；契约增量用默认缺省序列化保留旧模板 hash；演示来源不伪造事实/审核。无新增依赖与数据库迁移。

## Section 行文恢复

按 [Section 行文契约](section-narrative.md) 实现可选 Section.narrative 作者配置，编译展开为普通 V2 行文输出。2026-09-15 按用户指定的 b6f9bd4 使用方式修正：自动读取模板样例生成 `{{字段名}}` Prompt 并直接填入文本框；请求期间的新手工编辑保留为优先，迟到响应不覆盖切换后的上下文。

章节试生成恢复专用 `preview-section-narrative`，使用当前用户、模板、原件与所选引擎的已有结果，不创建 ReportRun，不保存模板修订。V2 本节字段复用纯编译和输入解析，按字段处理配置缺口；Mock 仍执行显式来源和筛选条件。部分集合、缺失子字段允许生成待补充草稿，保持材料状态及原有严格行文策略。完整报告继续由 V2 执行与导出，保留正式报告/签署门禁。验证实际失败集合、占位符、源与用户隔离、临时预览无报告副作用，再执行真实模型和页面验收；无新表、依赖或业务事实写入。
