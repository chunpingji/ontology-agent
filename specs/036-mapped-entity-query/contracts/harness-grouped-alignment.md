# 正式 Harness 分组接线

用户于 2026-09-28 授权部署。沿用当前运行、模型调用账本、暂停继续与只读查询服务；不导入评测模块，不增加数据库表或更改本体。

类型对齐后，对当前原文中带身份属性的同类型提及核对编号表达及竞争分组。当前模型消息协议为 `document-harness-v3`；公开图谱的实体、属性及关系结构沿用既有契约，不提供旧编号消息转换。每个表达必须选择程序提供的原文片段 ID 和当前类型的合法身份属性；每种分组覆盖全部最小表达，成员之间编号片段不重叠。查询缺失不否定指称，来源候选身份始终为 `not_checked`。

在提出分组前，每个可查询映射最多读取 50 条记录，只把身份键在当前来源中的逐字出现及完整键组定义注入 `key_candidates`。这是有界召回，保留来源 complete/truncated 状态和 boundary_status=not_checked；子串命中不证明完整编号。分组提出后再对所有原文编号表达逐项精确查询。

程序从本组可见来源、已定位提及/字段和 `key_occurrences` 建立 `evidence_spans`。每项 ID 绑定文档哈希、原文单元与字符起止位置，同字串的不同出现使用不同 ID；相同物理范围只登记一次。文本由程序从原文切片，模型不填写片段文本或组 anchor。目录保留 `boundary_status=not_checked`，上下文或键子串出现在目录中不代表它是完整编号。

目录区分编号候选与上下文用途：已定位原字段值及来源键逐字出现的片段标记 `identifier_candidate=true`；名称和整句片段初始只用于上下文证据。这样无 Mock 时仍可使用发现阶段保存的原字段值。expression.span_id 的动态枚举只包含编号候选，不能直接把上下文中的“644车间”名称片段当作编号。需要将上下文中的真实完整编号纳入候选时，也走一次 `new_spans` 定位申请；复用相同物理片段 ID，不复制原文。原字段可能是其他属性，编号候选资格只允许参与核对，不代表字段语义、完整边界或身份已确认。

`referent_candidates` 输出 `new_spans`、`expressions` 和 `partitions`。每个 expression 为 `{id, property_iri, span_id}`，其中 span_id 被动态 Schema 限制为当前目录 ID，程序再次核验；不得输出旧 quote 字段。完整组与成员的竞争解释必须分别引用真实存在的片段，不能拼出原文不存在的表达。编号值、精确查询值和后续绑定均从已选择的片段还原。

目录缺少必要片段时，模型可在 `new_spans` 一次提出全部缺项，使用 `{source_id,text,occurrence}` 严格定位；本轮 expressions/partitions 为空。程序逐字校验、检查本组范围并拒绝重复项，全部通过后才分配 ID，返回扩充目录重问一次分组；第二次 `new_spans` 必须为空。无 Mock 命中的编号走同一入口，不按标点拆分或自动决定对象数。非法引文仍失败，不模糊匹配，不自动删错项或用部分目录冒充补充成功。

扩充机会每组最多一次，复用当前 `referent_work` 的目录、扩充标记和最新回答，以及独立的模型调用账本。暂停继续不重置机会、不重复已保存回答；失败回答也保留，继续时仍校验失败。目录及补充调用计入既有输入和运行预算，超限不得截断原文或放宽核验。本机制替代旧的候选重抄引文及 `quote_correction`，默认启用，无额外开关。

模型选择一个完整分组或保留未决，与后续关系是否选择一个地点无关。`referent_selection` 的证据使用 `evidence_span_ids`，只选当前目录 ID；程序检查证据覆盖全部成员。所选成员的 anchor、表达片段 ID 和来源候选构成同一绑定；编号从原文片段派生，后续属性映射不得改写或交换。类型/指称仍需独立核验。未选分组不得采信成员或其属性。

成员仅输出 expression_ids；程序从这些已经校验的编号引用派生成员的连续 anchor。模型不再重复生成成员 anchor，以免正确的成员编号引用与误抄的整体 anchor 冲突。程序不改变表达原值、成员归属或所选分组。

`referent_selection` 必须返回 `verdict=supported|unresolved`。supported 表示原文语义结合可核验键匹配支持一个完整文内分组，须给出非空分组 ID、决定性原文片段及理由。共享称谓、完整编号边界以及对应类型/编号属性的不同来源记录精确命中可构成联合支持；无实际反证时，不要求额外并列词或逐一反证所有理论可能。菜单列出的竞争解释不自带证据，仅设想可能是复合编号不能自动否定这种联合支持。

有据的复合编号、改号/别名、对象层级冲突须纳入判断，不能由来源命中覆盖；数字子串匹配不能证明完整边界。有据竞争仍无法消解或关键依据不足时必须 unresolved 且分组 ID 为 null，说明具体冲突或缺口。分隔符、查询命中、记录数或缺记录均不能单独决定对象数；complete 只表示查询完成，不声明权威全集。无来源命中仍可凭明确原文分组。reason 说明原文语义、实际使用的键匹配及有据竞争解释的处理。confidence 保留在原始回答和当前工作状态中，仅为辅助信息，不参与登记决策。局部分组不确认全局身份、生产参与方式或并行时间。

只有 supported 且原文片段合法、分组完整、成员不重叠、证据覆盖全部成员，才登记候选成员。supported 与 null、unresolved 与非空 ID 等矛盾消息直接拒绝；证据覆盖不足保留未决并记录具体原因，高分不能绕过约束。低分不能单独推翻有据的 supported 判定。模型判定语义、程序核验结构和定位，两者均不等于全局身份确认。该改动限定指称分组阶段，其他阶段的采信规则独立；不将旧消息补写 verdict 后作为新协议结果。

属性对齐和证据核验只判断原文中该对象的编号值、完整边界及归属。身份键标记表示该属性可参与身份核对，不要求仅为保存文内编号就证明全局唯一；缺命名空间或业务范围不自动使编号属性未决。编号可由原字段或称谓上下文表达，不要求原文复述本体属性标签。仍须核对其确为编号而非名称中的任意数字、数量或其他层级对象的编号。identity_binding 保持成员归属与原值一致，不替代语义证据；有反证应拒绝，无足够依据应未决。属性定义若实质要求特定体系、认证状态等限定，不得以本规则豁免。采信编号不修改来源 identity_status，不确认来源记录、跨文档同一性或合并对象。

关系组使用本体合法谓词与当前已提供的端点，包含 `object_ids`、`participation=options|all|unknown`、`selection=exactly_one|unspecified`、`timing=parallel|sequential|unspecified`、极性与条件。选择和时间分别受参与方式约束；选项组不能展开肯定边。关系参与和时间分项核验。来源记录不能证明文档关系。

公开图谱增加 `relation_groups`，保留参与状态、时间状态、成员和原文证据；页面关联关系中展示。指称竞争解释通过当前观察展示，编号绑定传入模型上下文。所有新运行默认启用。验收使用当前代码新建运行，不重写旧实测产物。
