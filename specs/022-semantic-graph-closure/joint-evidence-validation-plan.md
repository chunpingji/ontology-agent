# HRS-5592 跨记录互补证据定向验证预登记

日期：2026-09-10。用户授权沿“保留未决断言、补充跨记录证据、联合重验、有效父关系后展开属性”方向实证验证。

## 范围与实验因素

这是因果定位实验，不是全文识别性能验收。复用当前正式 `assemble_context`、
`LocalModelRecognitionAdapter` 的独立发现/验证、`ProofGate` 和有效图投影；
新脚本仅冻结输入、指定诊断任务及证据干预、记录结果。线上核心、提示、权威 TTL、
原件及 r1 历史结果均不改变。没有实现生产用自动证据聚合、持久重验或实体合并。
直接适配器实验不运行生产执行器的冲突订阅、失效和重验；图采用当前证明门结果的
有效投影作观察。相互冲突的候选必须另列，不能以该投影冒充生产执行器最终裁决。

每个原文目标分别执行 current（现有上下文装配）和 joint（现有上下文加预登记原文）两组。
current 已含表头、字段组和局部绑定，不能称为“孤立段落”。joint 新片段保持
`fact_eligible=false`，只提供类型、归属、关系、条件等支持；新对象/值仍只能来自 target。
两组均不注入候选答案或旧图谱。源位置选择是人工诊断干预，不能视为自动检索召回效果。

保持同一主体、谓词、原文目标及 claim lineage；证据变化生成新 task/context/target 身份，
单独保留旧结果；相同证据不重复执行。显式重验是试验驱动器行为，不能报告为当前内核
已有自动未决重验。两组都执行用于控制选择偏差，顺序按 case 交错；不是重试直到通过。

## 限额、测量与验收

- 新目录、新 run；最多 32 个任务、48 次主模型请求、1200 秒识别软截止、主请求在途 1。
- 不启用语义排序，目标和证据已预选；因而不能报告 H0/H2、生产数据库或全文提速倍数。
- 两次模型调用共享请求限额；每次真实请求前持久记录预扣。截止后不再派发，在途尾部另计。
- 保留精确请求/原始响应、完整上下文、任务/断言身份、图、证明、决策、调度用量和环境。
- 分列装配、发现、核验、证明/投影、父关系通过、属性开始/完成、单任务及总耗时；
  模型技术失败、无候选、未决、否定、预算未执行分开。
- 用源引用及冻结本体做识别外核对；没有专家金标，不报告正式 precision/recall。
- 工程正反例必须覆盖 A 与 B 单独不足、同主体 A+B 成立、辅助证据不授予新端点权限、
  跨文档/超预算、竞争主体及否定/条件、上下文身份变化、有效父边后属性可达。

若 joint 使原先未决的正确同一断言通过，并保留反例拒绝，支持证据聚合方向；若仅增加
上下文而仍无正确属性，明确报告未达成及判定失败位置。单次定向结果不证明全面提速、
自动召回可用、全文关系/属性完整或已部署。
