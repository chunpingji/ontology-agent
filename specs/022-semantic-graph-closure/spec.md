# Feature Specification: 主体感知语义精排与关系图谱闭环

**Feature Branch**: `022-semantic-graph-closure`
**Created**: 2026-09-08
**Status**: CPU and CUDA 12 engineering implemented and validated; independent real-model quality gate pending
**Input**: 实施[语义精排方案](../../docs/支持语义相似度精排的关系图谱识别精度提升方案.md)，承接 [021](../021-ontology-guided-doc-graph/spec.md)，补齐整个关系图谱能力的闭环。

## Clarifications

### Session 2026-09-08

- 范围：同一文档分析运行从显式上传、完整原文、当前直接本体菜单、主体感知排序、独立证明到有效多跳图、覆盖及原文回放；不以单个打分模块代替整体交付。
- 首期实施方案 P0–P4 的工程能力；P5 明确标为后续的补充精排，不阻塞必要上下文及迟到反证闭环。工程先交付必要来源装配与失效传播，不能依赖 P5 才安全。
- 模型能力可选：正式运行冻结确定性或语义排序模式；语义排序失败按预先冻结的整池降级/暂停政策处理；主验证模型失败仍为未完成。
- 验收分层：可控模型工程验证不替代专家标注和三次真实新运行。缺少独立材料、模型制品或专用并发测试环境的外部门如实待验，不编造质量提升。
- 授权：实施、隔离测试与可逆配置；不涉及本体修改、旧域数据清理、部署或业务事实提交。

### Session 2026-09-09 — CUDA 12 增量（初始约定）

- 保留现有 CPU 路径及默认 `cpu/float32`，另建隔离 GPU 依赖环境；候选为 PyTorch
  `2.7.1` / CUDA `12.6`（`cu126`），本机驱动、卡型与实际 wheel/runtime 兼容性必须实测。
- GPU 仅支持显式单卡 `cuda:N`，本轮目标精度为 `float16`；设备和精度在运行前冻结，
  不按可用性自动选择设备，不将 GPU 失败静默切换为 CPU 推理。
- CUDA 不可用、卡号越界、内存不足及非有限输出属于技术失败，沿用整池暂停或确定性
  降级政策；取消、超时和所有权丢失清理私有 worker，不能留下后台 GPU 任务继续占槽。
- CPU/GPU 对照使用同一冻结文档、查询、完整记录视图及模型制品。记录实际数值环境、
  输入与原始分数差异、成本及恢复行为；性能实测不替代 T017 的专家质量与成本协议。

### Session 2026-09-09 — 默认引擎改为 GPU

- 按用户后续指令，应用及基础 Compose 的默认设备/精度改为 `cuda:0/float16`，固定
  CUDA 12.6；默认 batch 4、超时 1200 秒、文档并发 1、失败 pause。覆盖上述 CPU 默认约定。
- CPU 的独立环境、锁和 Dockerfile 保留，新增 `docker-compose.cpu.yml` 显式使用
  `cpu/float32` 及 runc；不将 GPU 配置错误或资源不足静默处理为 CPU 成功。
- 物理 GPU 由部署配置指定，未指定不暴露显卡；排序能力开关及完整制品要求保留。
  当前共享服务切换须避开持有效租约的识别运行，不重写已有冻结身份。

### Session 2026-09-09 — 显式开启线上排序

- 用户授权打开本机 `SEMANTIC_RANKING_ENABLED=true`，配置完整模型并切换 backend，
  使 embedding 召回与 reranker 精排参与新建线上识别运行。保留通用安装的显式启用门。
- 切换前核对活动运行/租约及迁移状态，保护旧冻结制品；切换后核验真实环境与共享
  factory 的双模型请求，不将环境验收替代 T017 或将旧运行重标为新 GPU 运行。

## User Scenarios & Testing

### Session 2026-09-09 — 模板图谱切换共享新内核

- 用户要求将模板关系图谱正式迁移到 `OntologyGuidedExecutor`，包括运行控制、引用、
  实体属性及分支状态；不再把旧抽取域临时修复当作迁移完成。
- 工程契约、实施与真实模板验收见 [kernel-panel-migration.md](kernel-panel-migration.md)。
  继续保留历史运行、独立验证、原文权限与业务事实提交边界。
- 后续指令明确性能为全局堵点，本轮先收尾编码，以相关 TDD/回归测试通过交付；
  暂停真实模型实验，完整关系及属性的金标准留待性能工作后验收。

### User Story 1 - 原文记录获得主体与角色感知的优先顺序 (Priority: P1)

分析人员显式提交文档后，系统针对当前已到达主体的直接关系和属性优先读取相关原文，包括否定及条件；同名、试验来源编号与摘要不会成为可信身份。

**Independent Test**: 用空名称文档根、局部产品、含 API/试验来源表头及低匹配组成原文运行排序，检查全部来源保留、隔离字段排除以及角色上下文完整。

**Acceptance Scenarios**:

1. 高相似度共现无组成证明时不产生有效组成边；低分原文仍能被真正读取。
2. 同一池分批乱序返回后得到统一名次；缺项、重复、非有限分值及超长视图不导致候选丢失或局部混排。
3. 记录评分成功不增加已检查原文计数；每个意图对完整池评分，成本包含所有输入对。
4. 全部剩余记录无法完整精排时，仍按确定性顺序获得实际原文探索机会；观察明确 not_rerankable，没有伪造的精排分数。取消和所有权丢失直接中止，不触发技术降级。
5. 相同完整输入在显式 CPU 和默认 CUDA 12 GPU 上均返回完整、有限的逐对原始 logit
   与 L2 向量；不增加 sigmoid/softmax、不截断原文。FP16 的数值与排名差异如实报告。
6. GPU 不可用或请求失败时，没有隐藏 CPU embedding/精排调用；部分 GPU 分数不能与
   确定性顺序混成成功语义池，失败和已预扣费用仍保留。

### User Story 2 - 全部关系与属性公平执行且证明闭合 (Priority: P1)

分析人员在预算内获得各主体、谓词、阶段的实际执行，新增关系继续按合法菜单扩展；验证时能看到当前主体已证明的原文、必要角色、条件与反证。迟到冲突使旧肯定路径暂停使用。

**Independent Test**: 从文档根发现产品再发现真实 API 组成，穿插高相似度假桥接、多个谓词和低分第二阶段原文，随后出现同范围反证；核对源引用、真实调用日志、图失效和未决覆盖。

**Acceptance Scenarios**:

1. 槽位两阶段均有记录时前两次新记录机会分别执行第一、第二阶段，此后按冻结配额执行；根/子主体、关系/属性、谓词、章节轮转均无饥饿。
2. 已知必要原文超过普通保留名额仍全部装配；缺失或预算不足不得显示完整验证。
3. 纯排名变化不重做语义任务；主体或证明变化不继承无效已检状态，重验额度保守继承。
4. 同范围迟到反证暂停相关断言及依赖路径；其他批次/条件不直接判为矛盾。
5. 候选发现与证明验证使用两次独立模型请求；验证响应必须逐项匹配冻结 candidate/target，独立判断桥接类别。第二阶段缺项、重复、目标漂移或预算不足不能生成有效事实。
6. 文档根身份由冻结文档、显式根类型及根版本程序绑定，不要求模型伪造根的物理提及；根 ID 和类名不能作为原文引用。局部主体仍须证明原文归属，所有独立语义判定必须显式返回，字段遗漏按协议失败处理。

### User Story 3 - 同一运行可恢复、可解释且展示真实覆盖 (Priority: P1)

用户暂停恢复、刷新、切换两个结果 Tab 或查看排序详情时，已提交顺序和证明可重放，页面分开说明计划、实际执行、未完成与排序降级。

**Independent Test**: 在排序已提交和记录执行后恢复同一运行；更换模型/政策、旧查询响应、跨用户访问及删除后响应均不能污染结果，所有读取不启动模型。

**Acceptance Scenarios**:

1. 已提交排序和轮转计数恢复稳定，无漏项/重复；评分产物未持久化时不能推进原文执行。
   相同本体声明仅因引擎枚举顺序变化时，冻结语义身份必须保持一致；真实声明变化仍使身份失效。
2. 模型与排序配置变化要求新运行；有效租约也不能允许旧主体/查询响应写入新计划。
3. 图中证据可定位主体、对象/值、谓词、条件和反证；检索分数不显示为事实正确概率。任务预算用完与记录技术未完成分别说明，未尝试记录不能被标成已尝试失败。
4. 每次模型请求前先持久化预扣；进程在两阶段之间退出后，恢复保留已预扣额度。请求持久化失败不能派发，软暂停不能丢弃已完成验证。
5. CPU/GPU、CUDA runtime、dtype 或影响推理的数值环境变化使恢复身份失效；同环境
   恢复已提交排序不再调用模型。取消/超时后的 GPU worker 已退出才释放调度槽。
6. 排序请求预扣后等待持久化超过期限，但本进程确定尚未派发时，记录可追溯回执。
   同一输入恢复只能复用该笔预留一次，累计费用和既有上限不降低；无法确认是否派发的
   崩溃、旧记录仍保守占用额度。运行中的覆盖快照不显示停止原因，暂停原因来自当前
   运行状态，不改写旧图谱或覆盖计数；界面分别说明超时、预算耗尽和原文技术未完成。

### User Story 4 - 独立检验精度、召回、路径和成本 (Priority: P2)

评测者使用与识别输入隔离的参考，对固定池与动态前沿分别计分，并核验共同基线、消融因素和预算，避免空图、漏评分或无效引用制造提升。

**Independent Test**: 重复窗口、等价证据、全拒绝、未到达主体、未裁决预测和零相关查询都产生明确分母、未定义值和门禁结果；消融非注册因素变化被拒绝。

### Edge Cases

全负分/零命中、缺少模型、超时/预算耗尽、表格尾部反证、同 hash 不同用户、取消/删除后晚到评分、计划和台账同时遗漏记录、未确认编号、空根名、局部无全局编号实体、任务重试及候选失效均保持来源权限与覆盖守恒。

## Requirements

### Functional Requirements

- **FR-001**：查询仅采用当前主体有效原文及直接本体谓词，输出已用/排除来源，隔离假设与未验证身份。
- **FR-002**：检索视图保留原文、结构、表头、单位与遗漏状态；摘要、相似度和排名始终仅用于检索。
- **FR-003**：多路候选按记录去重、配额补位并保留完整目标；结构零命中不伪装为命中。
- **FR-004**：同一冻结池的各意图完成全部逐对评分后才产生统一排名；技术异常按整池政策终结，不能部分分数混排。
- **FR-005**：根/主体/谓词/阶段/章节公平性由实际启动机会计数，重试不能长期阻塞新记录，低排位等待任务有探索机会。
- **FR-006**：完整目标须直接与冻结原文记录全集核对；完成、未尝试和技术未完成独立守恒。
- **FR-007**：排序依赖与证明依赖分离；排序更新不得授予证明权限、改变语义任务身份或刷新重验额度。
- **FR-008**：当前主体证据和全部已知必要上下文进入独立的第二次验证请求；冻结候选和精确目标，桥接类别须独立语义核验。缺失、截断、未知条件和归属竞争不得包装成完整肯定证明。
- **FR-009**：原文否定和条件独立保留；同范围新增潜在冲突使旧断言及其递归依赖暂停，保留审计和未决义务。
- **FR-010**：排序模式、模型不可变身份、输入/窗口/归一化、融合/配额/公平/失败政策及预算数值限额在运行前冻结，恢复拒绝漂移；预算是否启用遵循 FR-017 的独立运行控制。
- **FR-011**：排序提交、预算启用时的逐请求预扣、原文调度、覆盖与图水位可持久重放；取消和所有权丢失直接中止，软暂停保留完整结果。读取不触发模型，所有制品继承运行所有权和删除门禁。
- **FR-012**：用户可区分计划数和实际阶段执行数、排序模式/降级与语义未决，查看记录排序原因及独立原文证明。
- **FR-013**：评测分别报告检索、完整断言、身份/路径、引用、覆盖和全部成本；重复、未裁决、未到达和范围外项目显式计账。
- **FR-014**：精度收益须由预注册独立质量协议及至少三个真实新运行验证；工程通过不能自动触发发布/清理或声称质量提升。
- **FR-015**：默认使用单卡 CUDA 12.6/float16，显式 CPU/float32 保持兼容；本地
  推理配置，独立环境与完整制品校验。GPU 不可用不静默回退 CPU；失败、取消、超时及
  owner 丢失遵守既有整池政策、调度清理和费用保全契约。
- **FR-016**：设备、dtype、实际 CUDA/驱动/卡型及推理数值政策纳入不可变身份与结果
  记录；CPU/GPU 比较保持文档、模型制品、完整查询/视图/记录池及预算可比，分别报告
  冷/热耗时、资源、原始分数及排名差异；不能将设备差异伪装为原 A–D 唯一因素。
- **FR-017**：运行暂停或可恢复失败时，所有者的写入角色可显式启用/禁用排序预算，
  操作具有版本冲突检测、幂等回执和变更审计，不自动启动模型。缺省启用。
  禁用期间不执行累计调用数及 tokens 限额检查，不预扣、不累计预算统计；历史账目保留，
  再次启用从关闭前的累计量继续。排序模型仍可运行，单次输入完整性/长度、超时、
  每次自动技术重试上限和取消保持有效。数值限额、语义身份、已提交图谱和排序结果仍冻结；
  预算开关作为独立运行控制生效，允许原预算暂停在禁用后恢复同一运行。未记账不表示实际成本为零。

### Key Entities

- 主体槽位查询：有效主体解释、直接谓词、检索意图与受权限过滤的来源。
- 检索视图：可回放原文与结构副本、完整性和遗漏声明。
- 排序轮次与观察：同一候选集合和输入身份下的分项评分、统一名次、降级及成本。
- 证明依赖与执行台账：事实成立的必要来源、失效闭包、实际执行和续执行义务。
- 质量协议与报告：独立参考、预注册比较、预算、指标和未验收门。

## Success Criteria

### Measurable Outcomes

- **SC-001**：方案 SR01–SR26 逐项有工程证据或明确外部待验，零静默遗漏；P5 扩展组明确单列。
- **SC-002**：固定夹具的真实组成多跳原文可回放，高相似度无桥接反例零有效边；低分记录实际被检查。
- **SC-003**：完整目标零丢失、已提交任务零无因重做；阶段计划与真实执行可核对，暂停恢复保持一致。
- **SC-004**：迟到同范围冲突在下一可见水位前阻断旧肯定路径；必要来源不受精排候选配额影响。
- **SC-005**：每个质量结论能追溯独立参考和完整成本；没有真实质量证据时结果明确为研发待验。
- **SC-006**：GPU 默认及显式 CPU 回归、GPU 成功/不可用/失败/取消/漂移边界均有工程证据；新增
  同输入 CPU/GPU 实测保留实际制品和未完成项。GPU 工程与环境结果独立于 T017 裁决。

## Assumptions

- 继承 021 的唯一新运行域、鉴权、两个结果 Tab、原文协议和业务提交边界。
- 默认内网离线运行，沿用已安装依赖及完整校验的本地制品；本轮 CPU 排序环境已经补齐，专家标注仍不得由合成金标冒充。
- 不选择未经标注规模支持的 95%/99% SLO；正式精度主张的阈值由独立质量协议冻结。
- CUDA 12.6 wheel 已在官方历史安装页列出，不据此假定本机可用；GPU 验收状态与
  环境资料另记 [gpu-ranking.md](gpu-ranking.md)，旧 CPU 实验制品不重写。
