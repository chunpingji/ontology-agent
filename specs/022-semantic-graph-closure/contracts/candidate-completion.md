# 定向候选、覆盖台账与完成状态契约

日期：2026-09-13。依据：用户授权修复关系图谱生产运行长期无法结束的问题。
需求对应 021 FR-022/023/029/072、SC-004 和 022 FR-006/AR-005/PF-009。
本次工程、迁移和未完成验收项见[验证记录](../candidate-completion-validation.md)。

## 搜索与任务

- 每份冻结原文只有一个共享搜索域。只有用户绑定的根或经有效肯定证明可达的主体，
  才能针对其本体合法直接关系/属性检索；不能预展开未到达对象的多跳菜单。
- 新运行冻结 `performance.candidate_planning=sparse-candidates-v1`，参与运行指纹和
  检查点一致性校验。搜索计划保留来源、主体/谓词/依赖、阶段和有界游标；不将全文
  record IDs 逐槽位展开为计划机会、覆盖条目或 RecognitionTask。
- 只有通过现有准入屏障的候选进入台账。同一原文在不同主体或谓词可对应不同任务；
  同一逻辑候选重复召回或恢复不能重复首次任务。已准入未实例化者仍属于待处理任务。
- `planned = examined + incomplete + unattempted` 在实际准入候选上守恒。搜索评分、
  上下文读取、未入选、软剪枝均不能计为 examined、技术失败或否定事实。
  搜索域和未入选处置只作独立诊断，不要求清空全文才能结束本轮策略。
- 必要来源、反证、明确多值清单缺口、有效重激活和未决补证沿既有证明契约处理；
  不能用裁剪候选分母逃避已经产生的实际义务。

## 完成与失败

`completion=policy_complete` 要求当前合法搜索阶段已结束、没有待应用/在途结果、
实际候选无未尝试或技术未完成、没有未执行的必要补验、预算暂停或待展开前沿。
同时写 `stop_reason=candidate_search_exhausted`，运行进入 `finished`。
本轮没有入选候选也须完成合法搜索步骤，不能以空队列或空图直接达标。

`policy_complete` 表示冻结策略已执行完，**不表示全文事实已穷尽或全文没有关系**。
不支持某个候选只影响其精确证据范围。模型失败、协议失败、未知调用支出、预算不足、
用户暂停继续沿各自失败/暂停/未完成原因呈现，不转换为完成。
语义未决、否定、条件和相互冲突是独立结果维度；若必要核验与有界补证策略均已执行，
仍可 policy_complete，但必须保留并显示这些结果及证据，不能提升为有效肯定事实。

搜索无新候选必须消费结果、推进阶段或明确停止；不能在同一槽位、游标和结果上空转。
存储与心跳慢于租约时旧执行者不得继续提交；续期须保留 fencing，不能借延长租约
或健康心跳掩盖业务无进展。自动恢复须有持久的有限次数；耗尽后明确可恢复失败，
保留最后完整图谱、原文、检查点、费用和诊断，而不是永久 queued/running 重领。

## 公共 API 与展示

沿用 `document-analysis-runs-v1`；新增可选字段：

| 载荷 | 字段 | 含义 |
| --- | --- | --- |
| `progress`、图谱 `coverage` 及适用槽位覆盖 | `candidate_policy: "sparse-candidates-v1"` | `records_*` 计实际主体—谓词候选任务，不是独立原文数 |
| 新策略 `progress` | `completion: "incomplete" \| "policy_complete"` | 独立呈现策略完成判据 |
| `progress`、`coverage` | `stop_reason: "candidate_search_exhausted"` | 本轮搜索和候选核验已结束；运行中仍为 null |

旧载荷缺少新字段时沿用旧记录覆盖解释，不补写新策略默认值。检索诊断中的
soft_pruned/待处置等计数不参与候选守恒式，同一原文跨槽位的搜索机会可重复计数。
前端显示“本轮识别完成”和“候选任务”，明确未入选原文尚未核验；失败、暂停、
预算不足和未决仍可见。所有读取、刷新和切换仍为零额外模型调用。

## 旧运行与迁移

已有冻结运行（包括 v1–v4）保留原策略、预算累计、指纹、任务身份、台账及完成定义；
旧 `in_scope_complete` 的全文校验不放宽。部署不原地改旧运行，也不重置恢复次数和费用。
采用稀疏候选策略须显式创建新运行，原件可以复用，识别运行身份必须不同。
无进展的旧运行在有限恢复后报告失败并保留制品；恢复旧运行仍按原冻结策略，
不能把“恢复”隐式变为新策略运行。历史冻结评测目录保持原样。

运行活性通过 `0037_doc_analysis_liveness` 为 execution 增加持久进展水位、连续恢复
次数和最后进展时间。默认 `document_analysis_no_progress_timeout_seconds=900`、
`document_analysis_max_recovery_attempts_without_progress=3`；自动重领不重置进展时间，
排队后的首次领取和显式恢复分别开启新的执行窗口。触发限制时报告 `ANALYSIS_STALLED`。
状态发布默认 `document_analysis_publish_timeout_seconds=30`，实际取该值与半个租期
的较小者；超时整体回滚并报告 `PUBLICATION_TIMEOUT`。心跳续期在拿锁后检查当前时间，
不能复活过期所有者；解析、差分、哈希与显示投影准备在发布写锁之外执行。

## 必须验证的反例与验收

1. 大全文、多可达槽位但每槽只准入少量候选：计划任务与台账随实际候选增长，不能出现
   主体×谓词×全文的任务或覆盖条目；共享全文仍可检索。
2. 搜索阶段全部合法结束且候选全部核验：有限步进入 `policy_complete/finished`；
   未入选原文保留未核验诊断，不计 unattempted、不宣称全文否定。
3. 零候选、全拒、无新增语义池：推进真实搜索阶段后有限步结束，不等待永远不会出现的结果。
4. 已准入未派发、任务技术失败、必要重验未执行、跳数或预算截断：分别阻止完成并
   保存真实原因，不通过删台账或改分母获得完成。已完成核验的语义未决/冲突可随策略
   结束而保留，必须可见，不能因需要全部肯定而让真实冲突文档永久运行。
5. 重复准入、检查点恢复、同一记录跨槽位：首次任务幂等，独立槽位正常计数，费用不重置。
6. 慢检查点、失租迟到结果、续期与提交竞争：保持 fencing、没有陈旧写入；有限恢复
   耗尽后明确失败，最后完整制品仍可读。SQLite 不能替代专用 PostgreSQL 并发验收。
7. 旧快照恢复后原指纹/预算/计数/完成判据不变；新策略需新运行 ID，未知策略版本拒绝。
8. API 与前端同时覆盖运行中、策略完成、暂停、失败和旧载荷；实际候选计数、搜索范围、
   语义未决各自显示。工程测试、真实模型质量、生产部署分别登记，不互相替代。
