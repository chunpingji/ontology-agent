# 证据聚合与证明协议修复契约

2026-09-10 用户授权实施。新运行采用 `evidence-repair-v1`，历史运行保留冻结协议。
依据：[优化方案8.14–8.19](../../../docs/关系谱图识别新内核的性能优化方案.md)。

## 事实及证明

每任务仍为单主体、精确谓词、单事实记录；辅助来源只能补证。由IR计算真实列头、
值、合并格、owner及范围映射；值须属于所选映射，相邻/同名不证明归属。
关系与属性的发现/验证schema分开，属性实际请求没有对象类型字段。
ProofMenu、请求枚举、返回校验和ProofGate同源。属性必需field_role、predicate_entailment、
bridge_entailment、applicability，非根加local_coreference；关系另加type，每项需要独立原文证明。
同物理提及的相容类型不拆实体；无唯一可证明主类型则未决。类型否定不是describes否定。
明确的分类/状态/否定句不能作为实体名称，即使模型全supported仍标记
entity_reference_not_specific并可重新提议；保守形态检查不替代独立语义核验。

实际传输结构分别为 `PropertyDiscovery/PropertyReview` 与
`RelationshipDiscovery/RelationshipReview`。属性值使用
`value_quote: {evidence_id, text, context_text}`：短值重复时，`context_text` 从本任务可提取
原文的完整句/逐字分句枚举中选取；服务端在同一来源内唯一定位上下文及值，不接受模型坐标。
表格字段以任务局部 `B1/B2` 别名选择真实映射，持久化仍使用完整来源与映射身份。
核验中的 `subject_binding: {verdict, support, local_support}` 对非根 supported 强制两侧非空引用：
support 的来源枚举仅含已确认主体，local_support 仅含当前记录。根身份由程序冻结，两者必须空。
引用合并后仍核对原始主体来源及当前owner，不能只引用另一段同名叙述。role supported 分支同样强制非空 field_role_support，
返回规范化后仍须通过 ProofGate，JSON schema 合法不是事实通过。
发现阶段使用 `scope_qualifiers: [{dimension, condition_quote: {evidence_id, text}}]`，
dimension仅接受product/material/batch/step/equipment/site/time；无范围返回空数组。
condition_quote须是当前授权来源中的逐字限制条件，不是对象名称或本体IRI；同维度重复声明
明确拒绝，不能静默覆盖。服务端保留引用，将逐字条件映射为内部applicability维度值并纳入
condition_support，独立核验其真实条件角色。不能仅凭引用存在自动通过，也不得删除真实条件。
新增`source-quoted-scope-v1`冻结到新运行、模型身份、请求及阶段缓存；旧范围政策不能静默复用。
整数值另冻结`source-integer-quotes-v2`：只为单一已解决的整数类型、无未注册单位换算的
属性，从当前事实来源枚举逐字整数候选；每个来源、数值及定位短语组合先经过唯一引用回放，
再编码为完整对象的oneOf分支，三个字段不能任意交叉组合。重复数字必须绑定可唯一定位的
原文短语，只有数值本已唯一时才允许null定位。支持原文全角数字，不在服务端剥离单位改写原值。
模型直接引用原文数字子串，整句仍用于证明单位与角色。来源无整数时不能生成整数候选；
类型union/未解决约束不据此收窄。词面候选不证明字段归属；服务端保留原值、类型及角色检查。
datatype_mismatch可触发一次新提议与独立核验，不复用旧目标、不凭检索补造值。

## 阶段与恢复

归属门另冻结 `owner_binding=source-owned-binding-v2`。保留原始主体引用与局部主体引用
各自的来源，不能在合并引用后丢失角色。表格值须对应已确认主体的同一物理行/单元格owner；
字段组须包含原主体的精确来源。两个同名来源或备注列不能单独证明身份；跨记录表格主体
需要显式装配并独立核验的指代链，缺少时保持 `owner_identity_unproven`。
正文中明确指名主体的完整主谓句保留独立语义归属检查，不据此建立全局同名身份。
归属政策进入配置模型身份和新运行政策；旧归属版本的冻结结果不得静默复用，须新建运行。

首次发现与验证是两次独立请求；持久冻结候选后才预扣验证请求。只增加辅助证据且
断言不变时复用发现、重新验证全部维度；改变端点/类型/极性/条件/范围/bridge须重新提议。
无proposal只保存真实来源线索，只有路径缺口时保存槽位定位状态，不逐空记录建工单。
内容hash包含物理来源、权限、字段映射及精确依赖，排除任务ID/别名/排序。
相同证据不重验。每次补证最多4逻辑记录，每槽位4活动工单，必要闭包不裁剪；正向补验1次，
反证2次，原lineage主请求8次，类型分支与技术重试共享额度。
`evidence-work-v2`分别保留一次正向补验和一次重新提议的累计额度；完成其中一种且仍缺证据
时，可执行尚未用过的另一种。补证仍须有新增来源，顺序不刷新额度；无新来源或两种额度
均耗尽时停留未决。切换时保存原任务、来源及累计计数，旧工单版本不能静默按新规则恢复。
协调器唯一写入，阶段制品经确认持久化；保存的发现/响应恢复不重复调用，未知费用不退款。
旧运行、跨运行及指纹漂移不自动升级。新候选策略的共享搜索域与实际准入台账分开，
旧冻结运行保留原全集覆盖；两种台账均守恒，重验不增加examined；
新证据待核验仍为未完成。父关系无效不展开属性，反证按依赖及适用范围传播。

实现边界：每次实际核验最多两个类型假设，未核类型保留为 deferred 并阻止相关资格；
目前没有遍历全部停放类型的后续游标。迟到反证订阅覆盖已有来源的否定/条件候选，
尚未全面覆盖仅检索到、但未形成候选的疑似反证。datatype 采用保守规则，未注册单位换算
和未解决约束返回未决；一般多值基数的完整检查不在此次新增实现中。

### 来源单位修复（2026-09-13）

数量属性采用 [来源单位核验契约](source-bound-units.md)。新运行冻结
`source-bound-units-v1:si-subset-v3-unit-aliases`，同单位及登记别名不再一律未决；
登记的同维度精确换算可规范化。单位必须由独立核验引用原文及其与数值的绑定，
不得用属性名推断。单位/数据类型失败与字段角色判定分开保存，公开原因明确指出实际门禁。
旧运行不原地重算或静默升级，旧单位政策的恢复必须新建运行。

## 检索及验收

启发式先定位，按缺口补搜，再按需语义及剩余范围探索。阶段结束但全文未检查保持
可恢复暂停，继续不刷新预算/指纹；恢复包括检索状态、工单、证据、依赖及费用。
H1支持单个中文本体标签的受约束词片组合（至少2个且覆盖40%），不以单词片激活全文。
非根主体的精确已证明来源可作为属性H1种子，不能用其他同名位置替代；语义关闭时直接推进
后续搜索。小页普通任务与惰性任务使用同一模板优先/普通轮转策略，优先不构成事实证明。
工程验收涵盖互补A+B、重复证据、错列/owner/条件、类型否定、缺必需facet、非法枚举、
发现/核验阶段崩溃、预扣失败、迟到worker、跨用户及旧运行恢复。
真实验收以HRS-5592原件、冻结CMCReport本体及同一本机模型至少3独立新运行，
记录正确关系/属性首达、覆盖、调用/token、补搜/发现/核验/保存/等待及总耗时。
设备编号/规格、计划日期/批数及错误日期反例须实际执行；未展开不能计通过。
质量未达不宣称提速或完整识别达标，不改写r1/r2原件及输出，不自动部署。

## 新运行与状态存储

`DOCUMENT_ANALYSIS_EVIDENCE_REPAIR_ENABLED` 默认 false。仅新运行显式启用时冻结
evidence-repair-v1、heuristic-first-v2、proof-menu-v1、physical-mention-v1、每 lineage 8 次
主请求和 checkpoint-v2；旧运行继续其冻结协议。工单、阶段响应与预扣由协调器确认写入，
新协议同时冻结模板公平策略，普通准入任务与惰性任务均保留2次优先/1次普通轮转及恢复游标。
完成响应可以在剩余预算为零时恢复应用，不能借恢复追加未付费请求。
现有不可变块存储增加批量读及精确已提交 head 缓存，未改存储版本；全量编码 CPU 和
历史 inventory 遍历仍存在。第4.4节的完整增量事件/周期基线目标不能以本次 SQL 优化替代。
