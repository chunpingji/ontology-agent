# S0：本体原生词汇语义检索契约

日期：2026-09-13。需求来源：[spec.md 的 OL-001～OL-008](../spec.md)。
本契约限定本次已授权 S0；独立词表的编译、审核、发布、人工扩词及管理页面不在范围内。

## 1. 来源与权限

本体引擎只读当前本体快照范围内类、对象属性、数据属性的两种注释：

| 注释谓词 | IRI | 用途 |
| --- | --- | --- |
| `rdfs:label` | `http://www.w3.org/2000/01/rdf-schema#label` | 正式名称及语言变体 |
| `skos:altLabel` | `http://www.w3.org/2004/02/skos/core#altLabel` | 本体已声明的替代表达 |

两种来源独立有效；只有 altLabel 时也纳入检索。读取全部有效非空字面量和语言标签，
忽略非字面量与空白值，不只取中文、英文或第一条。按概念 IRI 保留注释；同词多 IRI 不合并概念。
没有注释与读取失败是不同结果，后者不得被容错吞成空词表。
原有 comment/description 仅保留查询背景，不生成别名；不从原文、模型、
专家金标或 `_ALIASES` 补造原生注释。本次不写 TTL，不改变公理、角色或事实权限。

快照的既有展示 label 只在确有 `rdfs:label` 时进行确定性多值选择；只有
`skos:altLabel` 时保留既有展示回退，不把 altLabel 提升为快照单标签。
altLabel-only 由后述 v2 的选词及查询展示字段进入语义检索，避免从快照单标签
绕路进入 H0/H1。rdfs 多值展示的确定性选择可能改变新运行的展示及既有词面输入，
这一影响须与语义接入效果分开记录。

## 2. 冻结载荷与兼容

`OntologySnapshot` 新增可选 `lexical_context`。新载荷对应
`ontology-guided-snapshot-v2`；词汇载荷自身版本为 `v1`，按 IRI 保存 `annotations`，
每项保留 `text`、`language`、`predicate_iri`，并有可核验的 `context_hash`。
完整注释冻结在本体快照中，查询预算只影响采用，不裁掉源载荷。

1. 对 IRI、注释来源、语言及文本进行确定性排序和精确去重。同一文字具有不同
   来源或语言时保留各来源；RDF 枚举重排不改变 `context_hash`。
2. 有新载荷的 `ontology_hash` 覆盖逻辑投影和完整 `lexical_context`。仅修改词汇、
   来源或语言也改变本体冻结身份，不能只 hash 旧单标签投影。
3. 旧快照未包含载荷时，序列化省略新增字段，保持旧 hash 输入和存储形状。
   不在恢复时重新向当前本体补词；旧查询继续 `subject-slot-query-v1`。
4. 新载荷启用 `subject-slot-query-v2`，包括有读取能力但注释集合为空的快照。
   无注释时展示标签回退 IRI，保留定义背景，不宣称存在新词汇。
5. 恢复前核验载荷结构和内容身份；篡改、缺失的已绑定内容及不支持的形状明确
   拒绝，不切换当前本体或旧硬编码。v1 原本不支持恢复的限制不变。

新增字段不构成独立词表制品或发布版本。本次复用分析运行已有本体快照、
权限与制品保留机制，不新增数据库结构或 HTTP 端点。

## 3. 查询输入与选词

`build_subject_queries(..., ontology: OntologySnapshot | None = None)` 接收冻结
本体。运行适配器向首次准备、后续检索及提交回放传入同一冻结快照，不在 worker
中查询本体 live 状态。查询身份由载荷存在性决定，不能静默重新定义 v1。

角色范围及优先顺序为：

1. 当前待检索的直接谓词 IRI；
2. 当前主体类 IRI；
3. 当前直接谓词允许的目标类型 IRI，按确定性顺序处理。

不因共享 domain、父类或文本相似度收集无关概念。边的合法目标沿用冻结菜单，
不将多值 range 无条件解释为 union，不在查询层放宽不可解析的范围。
数据属性不把 datatype 作为实体实例，类型词始终位于本体语境。

初版选词规则为 `ontology-label-selection-v1`，固定在 v2 查询：每概念最多 **8** 个去重词，每词最多 **80** 字符，
一条查询采用的词汇文本合计最多 **640** 字符。规范化只服务匹配及去重，
原始文字、语言和来源仍能从冻结注释回放。不通过截短超长词制造新术语；
词数、单词长度或总预算超限时跳过并记录原因。

同一概念先采用 label，再采用仅有 altLabel 的词，各组按文本排序；去除首尾空白
后相同的词合并采用，原注释文字仍保持。查询的 `lexical_selection` 保留选中词的
角色、概念及注释来源引用，未采用数量和原因可审计。
重复文字合并实际检索表达时不丢各来源，不重复占用相同角色的词预算。
该预算不代替现有 tokenizer 的完整查询和输入对上限，最终输入仍接受原有
完整性校验；超限不静默截断，沿既有不可精排/暂停政策处理。

v2 的现有展示标签字段也受同一采用结果约束：`subject_class_label`、
`predicate.label`、合法目标的 `label` 及数据属性 `literal_spec.label` 只保留
已入选的原标签；原标签未入选时用该概念首个入选词，完全无入选词时回退 IRI。
否则被拒用的超长/超预算词可能经旧单标签字段重新进入模型。该约束不改写
冻结源标签，v1 查询仍保持原样；IRI 回退不是新生成别名，也不抹除未采用诊断。

`subject_mentions`、`trusted_context` 仍要求可回放且已支持的原文依据。
类/谓词/目标类型别名不能进入可信主体提及，不能用于实体身份合并。
发现与反证各生成真实查询，两者均具有角色化本体词汇；反证指令、否定和条件
语义不被肯定表达替换。现有定义背景及原文来源验证保持原协议。

## 4. 真实调用、依赖与重放

选词不能停留在快照、日志或 H1：v2 组装后的 `model_text` 必须实际传给
查询 embedding、记录/组语义召回和完整精排输入对。源视图和候选全集仍由
各自冻结原文范围决定，词汇扩展不增加事实证明权限或已检查计数。

`query_dependency_hash` 必须覆盖词汇内容身份、v2 选词政策、有效采用信息及
既有主体、谓词、原文、根和证明依赖。即使修改的词因预算未采用，完整词汇身份
也须可检测；提交与恢复验证按相同规则重建精确查询。

| 对象 | 依赖规则 |
| --- | --- |
| 查询向量、逐对精排缓存 | 精确查询/输入对、权限与模型相同才可复用 |
| 排序 epoch、门禁、准入与搜索处置 | 纳入新查询依赖；词汇改变不能复制旧分数处置 |
| prepare、后续扩搜、提交与回放 | 使用同一冻结本体及选词规则，重建依赖须一致 |
| 原文解析、纯记录视图和原文向量 | 按真实未变依赖复用，不因词汇变化全部清空 |
| 证明、费用与原运行任务 | 不因重建查询清零费用或更新已有证明身份 |

S0 不变更 H0/H1 的固定词表及启发式策略身份，也不将新 altLabel 接入 H0/H1。
新快照中 rdfs 多值展示的确定性选择可能影响既有单标签词面输入；其收益不能
算作本次语义接入结果，E0/E1/E2 对照必须固定展示字段以隔离该因素。
各检索阶段仍按冻结策略和预算执行，词汇无命中不能代表全文无事实。

## 5. 剪枝校准与失败

`CalibrationProfile` 兼容旧 v1 并扩展 v2 的精确绑定。v2 必须同时声明
`query_version=subject-slot-query-v2`、`ontology_hash`、`lexical_context_hash`
和 `lexical_selection_version=ontology-label-selection-v1`，并与实际运行一致。
这些信息进入 profile hash；缺任一字段、绑定不符或仅改 query_version 都拒绝。
旧 v1 禁止携带新词汇绑定；缺省新字段在序列化时省略，保持旧形状和 hash。

新载荷/v2 查询与现有 `trial` 或 `enforce` 校准不兼容时，在模型调用前明确拒绝。
不能静默沿用阈值或关闭剪枝。明确选择 `enhanced` 且不剪枝的配置可以执行；
旧冻结 v1 校准仍仅服务原身份。新增绑定能力不构成已有样本或阈值获得 v2 验收，
`enforce` 仍须匹配来源、模型、视图及独立审核后的校准，`trial` 仍标记研发状态。

| 情况 | 行为 |
| --- | --- |
| 无独立词表、确无 altLabel | 无包不阻塞；继续已有 label、IRI 和背景 |
| 注释读取失败 | 明确失败，不伪装为空载荷 |
| 完整注释多于查询预算 | 冻结全部注释，确定性采用，记录未采用原因 |
| 冻结内容损坏或重放依赖不一致 | 付费模型调用前拒绝，保留已有制品和费用 |
| v2 配旧剪枝校准 | 付费模型调用前拒绝，不自动切换运行模式 |
| 必需模型失败、暂停、取消、失租 | 沿既有技术失败/控制协议，词汇命中不代表识别成功 |

## 6. 验证与交付界限

工程测试按 [quickstart](../ontology-label-retrieval-quickstart.md) 覆盖
OL-AC-01～06：真实注释读取、冻结往返、枚举稳定、仅注释变化、角色/实例隔离、
预算审计、模型接口实际输入、后续检索/恢复与旧校准拒绝。
模型替身必须捕获实际 `embed`/`score_pairs` 输入；只断言内部文本构造不足以
证明消费链已接通，捕获调用也不等于真实模型质量评测。

OL-AC-07 单独固定原文、本体逻辑、模型、预算、调度及无剪枝配置，比较
E0 原查询、E1 补齐多语言 label、E2 再加入 altLabel。已有定义背景保持一致，
各组固定快照展示 label 及 H0/H1 输入，保存实际模型输入、候选召回、事实准确性、
完整路径与成本及未决/失败。
本轮不预设质量提升，不执行生产部署或数据库迁移。隔离真实 BGE 的小样本
排序诊断单独记录模型输入、分数和局限；它不包含完整事实识别及独立金标验收，
不能替代 OL-AC-07。实际已执行结果以 quickstart 的本次验证记录为准。
