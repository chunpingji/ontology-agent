# 实施计划

1. 规范/澄清已由 spec.md 与用户确认的工具协作设计覆盖；先冻结工具契约和新增验收。
2. 在 services/extraction/tool_validation 加入证据、GLiNER、指标及 SHACL 薄适配；线上代码不导入 evaluation。
3. 独立 evaluation runner 编排三次请求，固定 JSON Schema、同源 A/B 和服务端最终门。
4. 隔离工程测试后，核实本地模型/权重并运行 GLiNER，再运行至多 48 次真实 Qwen；结果写新目录。

## 依赖与宪章核对

复用 rdflib、现有字面量/证据模块及共享模型调度。新增 pySHACL 可选 extra，原因是需要真正执行 W3C SHACL，不能以手写模拟替代。精确锁定版本，运行时仅加载本地数据和 shapes；不引入网络服务或 agent 框架。权威 TTL/业务库不写入，既有暂停作业不恢复。Phase 0 与实现前检查：范围、离线、依赖方向和最小复杂度符合；交付时复核工程与模型验证记录。

## GLiNER2 / SKOS 追加实施

1. 核实官方模型与当前 API、本地依赖和权重可用性；模型及依赖使用隔离实验目录，避免升级运行服务的依赖。
2. 新增实验 SKOS overlay 与编译器，以真实 `skos:altLabel` 和人工补充词条生成有描述的标签；复用原三组工具协议及 IR 坐标。
3. 新增 GLiNER2 strict 适配器，复用 propose_mentions 分块/坐标/覆盖逻辑；离线加载、无外部推理接口。
4. 新增独立评测入口，复用旧 B 组冻结工具计划，替换词表与 NER 结果，再接原 Qwen 候选/语义/确定性最终门；固定最多 16 次新请求。
5. 保存模型身份、词表、原返回与同源对比，验证词表映射、缺项、span、失败和预算边界。

本次 SKOS overlay 仅作模型提示词汇，不新增业务公理、改变本体 range 或强制补值。用户新指令覆盖首轮不安装 GLiNER2 的实验选择；没有增加部署、发布、数据库或作业生命周期需求。

## GLiNER2.5 升级研究

用户追加研究请求后，优先完成[升级评估](../../docs/调研/cmc-gliner2-skos-validation-20260916/gliner25-upgrade-assessment.md)。结论建议下一轮采用官方多语言 boundary checkpoint，先处理 tokenizer 与原文保真批处理兼容，再进入真实 NER 和原定 C 组；16 次 Qwen 总预算不变。研究不等同升级已实施，不切换线上默认，不把模型卡长度声明当作已验证能力。

用户已继续授权实施上述 2.5 真实验证：并行迁移 strict 适配器及 runner，主流程准备固定权重和隔离依赖；工程检查、少量真实冒烟和 8 片段 NER 完成后，再使用准备好的工具执行 C 组。结果需独立核对原文并与旧 B 比较，报告技术失败、语义未决及真实 SHACL 覆盖。

## 现有摘要检索接入

1. 核对历史真实摘要对同一原文／IR／节点的身份，复用其来源与部分完成状态；使用 `prepare_metadata` 转成现有契约。
2. 新增独立评测薄适配，复用全文 `RecordIndex` 和 `plan_slot` 的原文／标题／摘要排序，旧类菜单产生谓词查询；不新增检索框架，不修改线上主链。
3. 先冻结检索策略和预算，完成摘要启用／屏蔽对照及真实原文回放检查。再从入选记录重建工具引用并运行 D 组至多 16 次真实 Qwen。
4. 新目录保存摘要身份、检索选择、返回和独立复核；分开检索消融与 D/C 组合差异，保留固定类槽位、预算覆盖和摘要误述等限制。

## Mock 实例知识实施

1. 固定现有静态设备档案与原文/本体/摘要身份，独立助手在预测前准备原文参考；参考不供 runner 读取。
2. 新增只读 `FrozenEquipmentCatalog` 工具，复用外部记录的命名空间、版本和字段映射，提供按原文名称/编号查询、精确编号链接核验和分来源字段返回。
3. 新评测适配仅使用 CMCReport usesEquipment 的现有 plan_slot；E2 增加 `4×不同精确编号 + 1×不同精确名称` 原文词项得分，同名档案不重复加分。每组前三个满足完整记录预算的正分记录分别生成 case，保留表头、注释、父上下文和祖先标题。
4. 三组共用紧凑候选契约，显式保留局部实体、文档属性、外部链接和 one_of 关系组；Qwen 核验后复用指标／SHACL 核心。原始 NER 全量落盘，模型按分数取最多 48 个去重 span，不注入重复 source_spans 或全工具诊断；完整请求消息预算 60,000 字符，超限不发出请求。
5. 先完成工程和输入预检，再冻结代码执行真实 NER及至多18次Qwen。 E0/E1按记录交错运行，E2随后运行；失败保留不调参重试。新制品及报告不覆盖D组，不修改线上来源和本体。

复用既有运行环境和依赖，无新增运行库、数据库结构、服务重启或主数据同步需求。额外协议只属于设备实验范围，不扩展为通用多源融合框架。
