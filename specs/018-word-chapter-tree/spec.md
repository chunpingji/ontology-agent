# Feature Specification: Word 章节树与分层摘要

**Feature Branch**: `018-word-chapter-tree`

**Created**: 2026-08-25

**Status**: Approved

**Input**: 基于现有 Word 标题层级和文档顺序构建显式章节树，为章节和叶章节页生成摘要元数据，并在 `/analysis` 提供无状态上传、树、原文和元数据联动分析工具。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看确定性的 Word 章节树 (Priority: P1)

作为文档分析人员，我希望系统根据 Word 已识别的标题层级和原始顺序展示显式章节树，并在叶章节下展示可追溯的页片段，以便理解长文档结构。

**Why this priority**: 章节树和来源范围是摘要、兼容入口及前端联动的共同基础。

**Independent Test**: 上传包含多级、跳级、重复标题和分页符的 Word，验证树父子关系、页节点及来源范围与原文一致。

**Acceptance Scenarios**:

1. **Given** 标题顺序为 H1→H2→H3→H2→H1，**When** 文档完成解析，**Then** 章节树按最近低层级标题建立父子关系，且先序遍历与扁平章节顺序一致。
2. **Given** 标题从 H1 跳到 H3，**When** 构建章节树，**Then** H3 直接归属最近 H1，不创建虚假 H2。
3. **Given** 文档存在明确分页标记，**When** 构建叶章节页节点，**Then** 页节点只包含该叶章节在对应页片段的来源块。
4. **Given** 文档没有可靠分页标记，**When** 构建页节点，**Then** 每个叶章节获得一个虚拟页节点，且不显示虚构的物理页码。

---

### User Story 2 - 阅读分层内容摘要 (Priority: P1)

作为文档分析人员，我希望每个章节层和叶章节页都展示简洁内容摘要，以便快速判断该层覆盖的主题，再定位原文核实。

**Why this priority**: 分层摘要是本能力的核心业务增量，但不能影响确定性解析。

**Independent Test**: 使用可控的本地模型响应处理多层文档，验证页摘要先生成、章节摘要自底向上生成，父摘要只消费直接内容和直接子摘要。

**Acceptance Scenarios**:

1. **Given** 本地摘要能力可用，**When** 处理包含多层章节的 Word，**Then** 每个非空页节点、章节节点和文档根均获得已完成摘要。
2. **Given** 本地摘要能力关闭，**When** 处理 Word，**Then** 完整树仍正常返回，摘要状态明确为未启用。
3. **Given** 某批摘要超时或返回无效结果，**When** 后续父层继续生成，**Then** 仅失败节点使用确定性摘录，其他节点和原始抽取结果不受影响。

---

### User Story 3 - 兼容既有 Word 抽取链路 (Priority: P1)

作为系统集成方，我希望旧 Word 入口和标注文档接口继续可用，同时所有新旧调用方共享同一次结构判定，避免标题、表格归属和分页结果漂移。

**Why this priority**: 现有抽取、分类、关系识别和连接器不能因新增树能力回归。

**Independent Test**: 对同一 Word 同时调用统一解析器、旧入口和标注文档接口，验证旧返回契约不变且树、标注、关系抽取共享结构来源。

**Acceptance Scenarios**:

1. **Given** 旧调用方使用 `parse_word()`，**When** 升级后解析同一文档，**Then** 函数签名、表格映射、段落结构及表格行在前的顺序保持兼容。
2. **Given** 标注文档请求已完成统一解析，**When** 执行标注和关系抽取，**Then** 不为相同步骤重复打开 Word 进行结构解析。
3. **Given** 旧标注缓存不含章节树，**When** 读取文档，**Then** 缓存版本使其安全重算且旧前端不会因新增可选字段失败。

---

### User Story 4 - 在文档分析页联动章节与原文 (Priority: P1)

作为文档分析人员，我希望在 `/analysis` 的“文档分析”页同时看到章节树、Word 原文和节点元数据，点击章节或页即可准确滚动并高亮对应原文。

**Why this priority**: 只有可追溯到原文，AI 摘要才可被安全核验。

**Independent Test**: 在页面直接上传包含重复标题的 Word，点击章节和页节点，验证本地选中状态、元数据与唯一原文范围同步变化，且系统没有创建抽取作业或事实数据。

**Acceptance Scenarios**:

1. **Given** `/analysis?tab=document`，**When** 页面加载，**Then** 页面展示 Word 拖放/选择入口，不读取或等待任何 ExtractionJob。
2. **Given** 文档中存在多个同名标题，**When** 分别点击这些节点，**Then** 每次均定位到各自稳定来源范围，不按标题文本误匹配。
3. **Given** 用户连续切换树节点，**When** 高亮范围变化，**Then** 已加载的即时分析结果不重新请求，原文编辑器内容不重建。
4. **Given** 窄屏设备，**When** 打开文档分析，**Then** 原文保持可读，章节树和元数据可通过抽屉访问。
5. **Given** 用户上传 `.doc/.docx`，**When** 分析完成，**Then** 服务端临时文件已清理，且没有新增作业、缓存、候选、三元组或关系。

### Edge Cases

- 标题前存在正文或表格时，内容归属虚拟文档根。
- 多个标题文本完全相同时，节点 ID 仍唯一且可精确定位。
- 标题级别跳跃或回退时，不生成虚假层级且不丢失空章节。
- 一个物理页同时包含多个叶章节时，每个叶章节只获得自己的页片段。
- 分页符位于段内、段前、分节处或表格首行时，来源块顺序仍稳定。
- Word 未保存渲染分页信息时，不根据字数、字体或页面尺寸猜测物理页码。
- 文档无标题时，根节点直接承载内容；为可展示内容生成根级虚拟页片段。
- LLM 关闭、缺包、不可达、超时、返回未知或重复节点 ID 时，解析与抽取仍成功。
- 页面刷新、关闭或点击清空时，当前文件、分析结果和节点选择全部丢弃。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将 Word 正文中的段落、表格和分页事件按原始顺序表示为统一块序列。
- **FR-002**: 每个内容块 MUST 具有文档内唯一、确定性的块 ID 和原始段落或表格索引。
- **FR-003**: 系统 MUST 仅依据确定性的标题 `level + 文档顺序` 构建含虚拟文档根的章节树。
- **FR-004**: 章节跳级 MUST 直接挂到最近低层级标题，不创建虚假章节。
- **FR-005**: 章节节点 MUST 区分直接内容与后代内容，并提供可定位的来源范围。
- **FR-006**: 系统 MUST 保留现有扁平章节、段落、标题和表格视图。
- **FR-007**: 只有叶章节可以挂载页节点；无章节文档由文档根挂载页节点。
- **FR-008**: 页节点 MUST 由明确分页事件划分；无事件时使用标明降级的虚拟页且物理页码为空。
- **FR-009**: 系统 MUST 支持手动分页、段前分页、分页型分节符、表格首部分页和最后渲染分页标记。
- **FR-010**: 系统 MUST 为文档根和每个章节节点附加层摘要及确定性计数、哈希和生成状态。
- **FR-011**: 系统 MUST 为每个页节点附加页片段摘要及确定性计数、哈希和生成状态。
- **FR-012**: 摘要 MUST 按页、最深章节到最浅章节、文档根的顺序生成。
- **FR-013**: 父章节摘要 MUST 只使用本章直接内容和直接子章节摘要，不重复发送整个后代原文。
- **FR-014**: 同一节点类型和深度的摘要 MUST 批量调用，不允许逐节点 N+1 调用。
- **FR-015**: 模型输出 MUST 只接受本批已知节点 ID 和摘要文本，未知、重复、超长或额外字段不得进入元数据。
- **FR-016**: 摘要能力关闭或失败时 MUST 返回完整树，并按节点提供未启用、失败或确定性摘录状态。
- **FR-017**: 摘要 MUST 仅作为派生展示元数据，不得进入分类事实、实体、三元组、关系或候选证据。
- **FR-018**: `parse_word()` MUST 保持公开函数签名和旧返回契约，但内部委托统一解析器。
- **FR-019**: 标注、分类和关系抽取 MUST 能复用已解析结构，避免相同步骤重复解析。
- **FR-020**: 标注文档接口 MUST 以向后兼容的可选字段返回章节树和分页元数据。
- **FR-021**: 标注缓存 MUST 随解析器、标注器或摘要 Prompt 版本变化失效。
- **FR-022**: Tiptap 中可定位的标题、段落和表格 MUST 携带稳定块 ID 与来源索引属性。
- **FR-023**: `/analysis` MUST 新增“文档分析”Tab，且默认 Tab 仍为“推理”。
- **FR-024**: 文档分析页 MUST 仅以 `tab=document` 表示入口；上传文件、分析结果和节点选择 MUST 只保存在当前页面内存中。
- **FR-025**: 页面 MUST 提供 `.doc/.docx` 拖放/选择并自动分析，成功后展示章节树、原文和当前节点元数据。
- **FR-026**: 点击章节 MUST 滚动到标题或首个来源块并高亮完整章节直接范围；点击页节点 MUST 高亮该页片段范围。
- **FR-027**: 原文定位 MUST 使用块 ID/来源范围，不得依赖标题文本作为唯一定位条件。
- **FR-028**: 节点切换 MUST 不触发新的上传分析请求或编辑器内容重建。
- **FR-029**: 选中深层节点时 MUST 自动展开祖先；选择状态 MUST 为本地状态，不写入 URL。
- **FR-030**: 摘要展示 MUST 明确区分 AI 生成、自动摘录、空内容和未生成。
- **FR-031**: 桌面端 MUST 提供树、原文、元数据三栏；窄屏 MUST 保持原文主视图并可访问另外两栏。
- **FR-032**: 本期 MUST NOT 增加 Docling 依赖或运行时解析路径；未来后端必须转换为相同统一 IR。
- **FR-033**: 系统 MUST 提供独立的 `POST /api/document-analysis/word` multipart 接口，并在请求级临时目录内完成 `.doc` 转换、结构解析、原文渲染和摘要。
- **FR-034**: 即时分析接口 MUST NOT 创建或读取 ExtractionJob、标注缓存、抽取候选、分类、实体、三元组、关系或知识图谱事实。
- **FR-035**: 即时分析接口 MUST 使用 `annotate_word(engine=None, structure_only=True, rich_style=True, structure=...)` 生成可联动原文。
- **FR-036**: 请求结束后服务端 MUST 清理上传源文件、转换产物和临时目录；客户端刷新/关闭后 MUST 不恢复结果。

### Key Entities

- **WordBlock**: Word 正文中的有序段落、表格或分页事件，保存稳定来源坐标和章节归属。
- **ChapterNode**: 文档根或章节节点，保存标题层级、路径、直接内容、来源范围、摘要元数据、子章节和可选页节点。
- **PageNode**: 叶章节在一个可识别页中的内容片段，保存页序号、可选物理页码、分页来源、块范围和页摘要。
- **LayerMetadata/PageMetadata**: 程序生成的计数、状态、哈希与模型派生摘要；摘要不属于事实数据。
- **PaginationMetadata**: 描述分页信号来源、物理页码可用性和降级状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有章节树夹具的父子关系、顺序、直接内容归属和稳定 ID 断言 100% 通过。
- **SC-002**: 手动、段前、分节、表格首部、最后渲染和无标记分页矩阵 100% 通过。
- **SC-003**: 模型成功时，所有非空页、章节和文档根节点均获得完成摘要，且调用次数按批次而非节点数增长。
- **SC-004**: 模型关闭、不可达、超时或非法响应时，Word 解析、即时分析、标注和抽取请求成功率保持 100%。
- **SC-005**: 既有 Word 解析、格式、分页、分类、关系和标注回归测试全部通过。
- **SC-006**: 重复标题夹具的树节点定位错误数为 0。
- **SC-007**: 连续切换节点不产生额外即时分析请求或 Tiptap `setContent` 调用。
- **SC-008**: 后端测试、前端 lint 和生产构建全部通过。

## Assumptions

- 第一阶段支持 `.docx`；遗留 `.doc` 继续由现有 LibreOffice 转换后进入统一解析器。
- Word 未保存完整自动分页结果；只有明确标记可用于物理页信息。
- 本地 LLM 是可选能力，air-gap 且功能关闭是正常状态。
- 不新增数据库表；抽取链可继续使用既有标注 JSON 缓存，但 `/analysis?tab=document` 的即时分析结果不读写该缓存。
- Docling 只作为未来 Strict OOXML 和复杂对象提取候选，本特性不安装、不导入也不调用。
